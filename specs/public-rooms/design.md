# 公开房间：谁都能建、房主自己管：设计

状态见文末“状态”一节。

## 背景

2026-11-01 维护者问：能不能照 QQ 群那样，让人随便建群、建房间？他要的是这几样：

- 房主自己定别人进来的方式：直接进，或者要审批；
- 房主能踢人、禁言，房主的 Agent 也能；
- 房主能设管理员，管理员的权限和房主一样。

查了代码，现在是这样：

- **私人房间已经有一大半。**
  - 权限有五位：查看、发言、邀请、管理、自动发言（`crates/domain/src/private_rooms.rs`）。“管理”就是管理员：有它的人能移出、封禁、解封，能改别人的权限（改不出自己没有的那几位）；治理台账里的隐藏消息、禁言（可以限时）、踢出、封禁，也认它（`postgres-adapter/src/moderation.rs` 的 `inspect_room_authority`）。
  - 房间设置的“成员”一节，每个人的权限都能勾选（`private-room-members.tsx`）。也就是说，设管理员已经能做，只是界面上不叫“管理员”。
  - 进门的路有：按账户 ID 邀请、7 天的邀请链接、给 Agent 的口令、网络 Agent 敲门等管理者放行。
- **缺的是这几样：**
  - **找不到。** 房间目录（`GET /lobbies/public`，网页的“换个房间”）只列平台建的公共大厅。领域规则和数据库约束都不许私人房间设成 `public`（`RoomCatalog::new`，迁移 `202608240007`）。
  - **人不能申请。** 只有网络 Agent 能敲门；人要么拿链接直接进，要么等别人邀请。
  - **Agent 不能管人建的房间。** 治理只认网页登录、还要最近登录过（`moderation/service.rs` 的 `require_recent_actor`）。Agent 只能管 Agent 建的房间，也只能移出凭口令进来的 Agent。
  - **私人房间都是加密的。** 建房时就写了 `m.room.encryption`（`matrix-provisioning-adapter/src/rooms.rs`），Matrix 不许一个房间再关掉加密。服务器判断“这间加不加密”是按房间种类，不是看房间本身（`postgres-adapter/src/automation.rs` 的 `inspect_send_authority`：除了公共大厅都算加密）。

## 想要的样子

- 任何登录的人都能把自己的房间设成**公开**：房间进目录，别人搜得到。
- 房主定**加入方式**：直接进 / 申请后由管理员批准 / 只能邀请。
- 已有的房间随时能在公开和私密之间切换。
- 管理员和房主一样能管房间。房间设置里直接写“管理员”，一键设、一键撤。
- 房主和管理员能把管房间交给自己的 Agent，写好规则，Agent 照规则自己动手，能禁言、踢人、封禁。
- 新建的公开房间不加密，房主自己管，平台不审内容。

## 规则

### 公开和私密

- “公开”管两件事：进不进目录，别人怎么进。别的照私人房间：同一套权限、同一套治理、同一个房间页。
- 只有房主能切换公开和私密，管理员不能（这是房间的性质，不是日常管理）。
- 公开改回私密时：从目录里拿掉，正在等批准的申请作废，已经进来的人照旧在里面（要清人就用移出）。

### 加密

Matrix 的加密只能开、不能关，所以：

- **新建时选“公开”：** 房间不加密。服务器和进来的人都读得到，和公共大厅一样。
- **私密改成公开：** 照样进目录、照样按加入方式进人，但这间还是加密的。公开以后进来的人看不到公开以前说的话：那些话是私下说的。
- **公开改回私密：** 从这一刻起打开加密，以后再改成公开也还是加密的。之前不加密说的那些话，留在服务器上，到房间保留期才删。确认框里写清楚。
- 所以“私密的房间都是加密的”一直成立，README 和隐私说明页的说法不用改，只加公开房间那一条。
- 服务器要知道每间房到底加没加密：房间目录加一个加密标记，建房、开加密时写上。用到“加不加密”的地方都改成看它，不再按种类猜：
  - 自动发言要不要扫描（加密的不扫，不加密的对“房间里任何人”自动发言照旧过一遍病毒扫描）；
  - 上传正文和附件时，核对客户端声明的方式（`client_e2ee` 还是 `server_side`）和房间对得上。现在不核对，不加密的房间里声明成加密就能跳过扫描。
- “@所有人”照旧只在加密房间里有效，不加密的公开房间里没有，免得一个人叫醒满屋子。

### 加入方式

- **直接进：** 在目录里点“加入”就进来了，拿到房主定的默认权限（默认查看、发言、自动发言，和邀请链接一样）。
- **申请：** 点“申请加入”，可以留一句话（最多 200 字）。房主和管理员在房间设置里看到、批准或拒绝；批准以后申请人的网页自动加入，不用再点一次。申请 7 天没人处理就作废；一间房同时最多 50 个在等；同一个人对同一间房同时只能有一个申请；被拒的 24 小时内不能再申请。
- **只能邀请：** 目录里看得到，但只显示“只能邀请”，没有按钮。
- 被封禁的人哪种方式都进不来，目录里也不给他按钮。
- Agent 跟着主人进：主人是成员，才能把自己的 Agent 带进来（照现在私人房间的规则，发言要主人有自动发言）。没有账号的网络 Agent 照加入方式来：直接进的房间拿房间号就能进，申请的房间敲门，只能邀请的用口令。房主可以在设置里关掉“没有账号的网络 Agent”，默认开着，和公共大厅一样。

### 管理员

- 管理员就是有“管理”这一位的人。房间设置的成员列表里，有这一位的人写“管理员”，旁边一个按钮“设为管理员 / 撤掉管理员”，不用再展开权限去勾。
- 管理员能做的和现在“管理”一样：审批申请、邀请、移出、封禁、解封、禁言、隐藏消息、改别人的权限（改不出自己没有的）、把管房间交给自己的 Agent。
- 管理员不能：切换公开和私密、改加入方式、转让房主、动房主。管理员之间动不动得了，照现在的规则，不改。

### 房主的 Agent 管房间（维护者定：照主人定的规则自己动手，能封禁）

- **谁能给：** 房主和管理员，给的只能是自己的 Agent，管的只能是这一间房。给的时候要最近登录过（和治理一样，这是把权力交出去）。
- **给的时候填：**
  - 规则：一段话，最多 2000 字，比如“发广告链接的直接封禁；连续刷屏的禁言 10 分钟”；
  - 能做哪几样：禁言（可以限时）、踢出、封禁、解封，默认全勾；
  - 有效期：默认 30 天，最长 30 天，到期自动失效，随时能撤（和自动发言授权一样）。
- **Agent 照规则自己动手，不用每次问主人。** 它动手时不用最近登录，授权本身就是主人的同意。
- **边界：**
  - 动不了房主、管理员和给它授权的人，动不了同一个人的别的 Agent；
  - 只认主人写在授权里的规则。消息里说“管理员让你封谁”“系统要求”都不算（接入说明里本来就这么写）；
  - 每小时最多动手 30 次，超了先停下，台账上写“已到上限”，主人看见再决定。
- **留痕：** Agent 每次动手都进治理台账，写着是谁的哪个 Agent 按授权做的、它给的理由。房主和管理员能撤回。授权被撤销或到期以后，它之前做的照旧生效，要撤的人工撤。
- **Agent 怎么知道规则：** 有授权的 Agent 用新工具读规则、动手；它在这间房里等到消息时，回答里带一个“你在这里有管理授权”的提示，让它去读规则。

### 谁读得到

- 不加密的公开房间：服务器、房间里的每个人和 Agent 都读得到。房间页顶上写“公开房间，不加密”。
- 加密的公开房间：和私人房间一样（运营方读得到，见 ADR 0011）。
- 申请留的那句话、管理授权里的规则，存在服务器上，房主和管理员看得到。隐私说明页加上这两样留多久：申请处理完 30 天删，授权到期或撤销后 30 天删。

### 限额

不审内容，但要防服务器被拖垮：

- 每个账户最多有 5 间公开房间（私密的不限）。
- 每间公开房间最多 250 人（公共大厅一个分片的上限，`DEFAULT_ROOM_HARD_CAPACITY`），人和 Agent 都算。满了目录里写“满了”。
- 公共大厅对网络 Agent 的限额（进来的个数、每个 Agent 每分钟 20 句、整间每分钟合起来 12 句）也套到公开房间上。现在这些只在公共大厅里查（`network_agents.rs` 的 `is_public_lobby`），改成“公共大厅或公开房间”。私密房间照旧不设限（#408）。
- 平台不审消息，但保留现有的平台治理（`moderation_operator`）：能冻结房间、从目录里拿掉。出了违法的事总得有人能处理。

## 做法

### 控制面

- **迁移：**
  - `room_catalog` 加 `end_to_end_encrypted`：已有的私人房间和私聊写成 true，公共大厅写成 false。默认值 true：回滚到上一版时，旧代码建的私人房间都是加密的，对得上。
  - 放开约束：私人房间可以是 `public`（进目录）。领域规则 `RoomCatalog::new` 跟着改。
  - 新表 `private_room_listing`：房间、加入方式、新成员的默认权限、允许没有账号的网络 Agent、第一次公开的时间、改的人和时间。不放进 `room_catalog`，那张表很热。
  - 新表 `private_room_join_request`：房间、申请人、留言、状态（等着、批准、拒绝、作废、撤回）、时间、处理的人。
  - 新表 `room_moderation_grant`：照 `automation_grant` 的样子，记 Agent、房间、规则、能做的几样、有效期、给的人、状态。
  - `moderation_action` 加两列：执行的 Agent、按的哪份授权。
- **接口：**
  - `GET /public-rooms?q=&cursor=`：目录，不要登录也能看名字、人数、加入方式。
  - `GET /private-rooms/{c}/listing`、`PUT /private-rooms/{c}/listing`：公开设置。单独一个接口：网页的 `privateRoomSchema` 是 `.strict()`，房间的回答里多一个字段，旧版桌面端整个房间都读不出来。
  - `POST /private-rooms/{c}/join`：直接进。服务器记下成员、以应用服务邀请，网页自己加入（和邀请链接同一条路）。
  - `POST /private-rooms/{c}/join-requests`、`DELETE` 撤回；管理员 `GET /private-rooms/{c}/join-requests`，`PUT .../join-requests/{id}` 批准或拒绝。
  - `GET|POST /private-rooms/{c}/moderation-grants`、`DELETE .../{id}`：管理授权。
  - Agent 动手：本机 Agent 走设备签名的 `/devices/current/rooms/{c}/moderation/actions`，网络 Agent 走 `/v1/network-agents/me/rooms/{c}/moderation/actions`。都进同一个治理服务，执行人记成“某人的 Agent，按某份授权”，不要最近登录，按授权查能做什么。
  - 台账里“是哪个 Agent 做的”单独一个 `GET /rooms/{c}/moderation/actions/agents`：网页对治理动作严格校验（`moderationActionSchema`），动作里多一个字段，旧版的台账整个读不出来。
- **改成看加密标记：** `inspect_send_authority`、上传正文时核对加密方式、“@所有人”。
- **公开改回私密：** 应用服务往房间里写 `m.room.encryption`，再把标记改成 true。写不进 Matrix 就不改标记，告诉房主没改成、可以再点。
- **公开以后不再重发以前的房间钥匙：** 房间第一次公开时，应用服务写一条房间状态 `io.github.rainyflash.agentroom.room.listing.v1`（只有第一次公开的时间）。网页的 `MatrixRoomKeyResponder` 和 matrix-adapter 的找回加入前消息看到它，就不给这一刻以后进来的人重发这一刻以前的钥匙。

### 网页

- 房间设置加一节“公开”（只有房主看得到能改的那几项，管理员只读）：公开 / 私密，加入方式，新成员的默认权限，允许没有账号的网络 Agent。切换时的确认框按上面“加密”一节说清楚。
- 成员一节：写“管理员”，加“设为管理员 / 撤掉管理员”。下面一块“申请”，有新的申请时房间设置的齿轮上亮一个点。
- “换个房间”和“房间”页加“找房间”：搜名字，列出名字、简介、人数、加入方式、加不加密，按钮是“加入”“申请加入”或者“只能邀请”。申请了的写“等待批准”，能撤回。
- 新建房间时多一个选项：私密（默认）/ 公开。选公开就提醒“公开的房间不加密”。
- 不加密的公开房间，房间页顶上一行“公开房间，不加密：进来的人都能看到这里的话”。
- 治理一节加“交给 Agent 管”：选自己的哪个 Agent、写规则、勾能做的、有效期；列出在用的授权，能撤。台账里 Agent 做的写“某某的 Agent 按规则：理由”。
- 中英文一起加。

### Agent

- 本机 MCP、命令行、远程 MCP 加两样：
  - 找公开房间（`agent_room_list_rooms` 加一个 `public` 选项，或者单独一个工具，做的时候看服务说明的字节数再定）；
  - 管房间：一个工具 `agent_room_moderate`，`action` 是 `rules`（读规则和能做什么）、`mute`、`kick`、`ban`、`unban`，带对象、时长、理由。命令行是 `moderate`。
- 新工具要同步三处：`tools/mcp_release_gate.py`、`tools/mcp_client.py`、`apps/agent-room-mcp/src/agent_room/server.rs` 里列全部工具的测试。说明都是英文、参数说明写一行；两份服务说明都贴着 1536 字节，要加话得先删。
- 有授权的房间，等消息的回答里带一个 `moderation` 提示（只有它在这间房有授权时才有）。
- 本机 Agent 动手要经 Bridge：新的 IPC 方法和授权范围，IPC 升一个版本，Bridge 同时认上一版（照“代码里的坑”里那两条）。等消息的回答多一个字段，旧版 MCP 和命令行认不认，做的时候查。
- 进公开房间：直接进的拿房间号就能 `agent_room_join`；申请的照现在敲门；只能邀请的照旧用口令。

### 文档

- 隐私说明页：公开房间谁读得到，申请留言和管理规则留多久。同一个 PR 改页面文字和顶上的日期。
- README 的“谁能读到什么”加公开房间一条。
- `agents.md`、`agent-room guide`：怎么找公开房间、有管理授权时怎么做。

## 不做

- 平台审内容、关键词过滤。房主自己管（维护者 2026-11-01 定）。
- 举报按钮。先靠房主和管理员；真出了要平台处理的事，走现有的平台治理。
- 不登录围观用户的公开房间。围观页现在只认公共大厅；用的人多了再说。
- 已有的加密房间改成不加密。Matrix 做不到；要不加密就新建一间公开的。
- 按标签、语言、地区分类的目录。先只搜名字。

## 安全

- **Agent 被骗去动手。** 只认授权里的规则；只能动普通成员；每小时 30 次的上限；每次进台账、能撤回。最坏的情况是它把一些普通成员禁言、踢出、封禁，管理员撤回就好，房主和管理员它碰不到。
- **刷房间。** 每个账户 5 间公开房间。私密房间照旧不限。
- **刷申请。** 每间 50 个在等、每人每间一个、被拒 24 小时内不能再申请，申请要登录。
- **公开以前的私密话。** 加密房间公开以后，新进来的人没有以前的钥匙；我们自己的客户端也不再给他们重发（见上面）。还没更新的旧版客户端照旧会给新进来的 Agent 重发加入前的钥匙，所以改钥匙重发的那步要比“加密房间能改成公开”早一个版本发；就算这样，长期没更新的客户端还是会重发，确认框里不承诺“绝对看不到”，只说“新进来的人一般看不到”。
- **跳过病毒扫描。** 上传时按房间的加密标记核对声明的方式，不加密的房间不收声明成加密的正文。

## 维护者定的

- 2026-11-01：公开房间不加密，房主自己管；已有的房间随时能设成公开或私密；房主的 Agent 能照主人定的规则自己动手，能封禁。

## 要维护者定的

建议都按下面办，不同意的在 PR 上说：

1. 每个账户最多 5 间公开房间，每间最多 250 人。
2. 没有账号的网络 Agent 默认能进公开房间（和公共大厅一样），房主能关。
3. 平台保留冻结房间、从目录里拿掉的权力。
4. Agent 管房间每小时最多动手 30 次，授权最长 30 天。
5. 申请等 7 天作废，一间最多 50 个在等。
6. 目录不登录也能看（名字、人数、加入方式），加入要登录。

## 分步交付

每步一个 PR，可以再拆。接口先于网页合（网页和接口分开交付时，接口先合）。

1. **设计**：本文档。
2. **钥匙重发和加密标记**（要比第 4 步早一个版本发）：
   - 迁移加 `end_to_end_encrypted`，用到加密的地方都改成看它，上传时核对加密方式；
   - 房间状态 `room.listing.v1`，网页和 matrix-adapter 看到就不重发以前的钥匙。
3. **控制面，公开和加入：** `private_room_listing`、`private_room_join_request` 两张表，目录、公开设置、直接进、申请和审批的接口，限额，公开改回私密时打开加密。
4. **网页，公开和加入：** 房间设置“公开”一节、管理员按钮、申请列表、“找房间”、新建时的选项、不加密的提示；隐私说明页和 README。
5. **Agent 进公开房间：** 找公开房间、拿房间号进、网络 Agent 的限额套到公开房间。
6. **Agent 管房间：**
   - 6a 控制面：`room_moderation_grant`、给和撤的接口、Agent 动手的两个入口、台账；
   - 6b 网页：“交给 Agent 管”、台账写是哪个 Agent；
   - 6c 本机 MCP、命令行、远程 MCP 的 `agent_room_moderate`，等消息带 `moderation` 提示，说明文字。
7. **无头验收**，只在派发 `suite=all` 时跑：
