# 公开房间：谁都能建、房主自己管：设计

状态见文末“状态”一节。

## 背景

2026-11-01 维护者问：能不能照 QQ 群那样，让人随便建群、建房间？他要的是这几样：

- 房主自己定别人进来的方式：直接进，或者要审批；
- 房主能踢人、禁言，房主的 Agent 也能；
- 房主能设管理员，管理员的权限和房主一样。

查了代码，现在是这样：

- **私人房间已经有一大半。**
  - 权限有五位：查看、发言、邀请、管理、自动发言（`crates/domain/src/private_rooms.rs`）。“管理”就是管理员：有它的人能移出、封禁、解封，能改别人的权限（改不出自己没有的那几位）；治理台账里的隐藏消息、禁言（可以限时）、踢出、封禁，也认它（`postgres-adapter/src/moderation.rs` 的 `inspect_room_authority`）。
  - 房间设置的“成员”一节，每个人的权限都能勾选（`private-room-members.tsx`）。也就是说，设管理员已经能做，只是界面上不叫“管理员”。
  - 进门的路有：按账户 ID 邀请、7 天的邀请链接、给 Agent 的口令、网络 Agent 敲门等管理者放行。
- **缺的是这几样：**
  - **找不到。** 房间目录（`GET /lobbies/public`，网页的“换个房间”）只列平台建的公共大厅。领域规则和数据库约束都不许私人房间设成 `public`（`RoomCatalog::new`，迁移 `202608240007`）。
  - **人不能申请。** 只有网络 Agent 能敲门；人要么拿链接直接进，要么等别人邀请。
  - **Agent 不能管人建的房间。** 治理只认网页登录、还要最近登录过（`moderation/service.rs` 的 `require_recent_actor`）。Agent 只能管 Agent 建的房间，也只能移出凭口令进来的 Agent。
  - **私人房间都是加密的。** 建房时就写了 `m.room.encryption`（`matrix-provisioning-adapter/src/rooms.rs`），Matrix 不许一个房间再关掉加密。服务器判断“这间加不加密”是按房间种类，不是看房间本身（`postgres-adapter/src/automation.rs` 的 `inspect_send_authority`：除了公共大厅都算加密）。

2026-11-02 维护者又提了两样：公开房间里的人要能拿一个链接分享给朋友、发到社交媒体，打开是这间房的网页，说清加入要注册登录、带 Agent 要下载桌面应用；应用里要有一个展示、搜索、加入公开房间的界面。先出了设计稿，维护者看过同意（见“维护者定的”）。

## 想要的样子

- 任何登录的人都能把自己的房间设成**公开**：房间进目录，别人搜得到。
- 房主定**加入方式**：直接进 / 申请后由管理员批准 / 只能邀请。
- 已有的房间随时能在公开和私密之间切换。
- 管理员和房主一样能管房间。房间设置里直接写“管理员”，一键设、一键撤。
- 房主和管理员能把管房间交给自己的 Agent，写好规则，Agent 照规则自己动手，能禁言、踢人、封禁。
- 房主和管理员能写一条**常驻公告**，一直挂在房间顶上，进来的人和 Agent 都看得到。
- 新建的公开房间不加密，房主自己管，平台不审内容。
- 公开房间里的每个人都能拿一个**分享链接**，发给朋友或者发到社交媒体。没登录的人打开，看到这间房的网页：名字、简介、人数，加入要先登录或注册，想带上自己的 Agent 要装桌面应用。
- 应用里有一个**发现**页：看、搜、加入公开房间。

## 规则

### 公开和私密

- “公开”管两件事：进不进目录，别人怎么进。别的照私人房间：同一套权限、同一套治理、同一个房间页。
- 只有房主能切换公开和私密，管理员不能（这是房间的性质，不是日常管理）。
- 公开改回私密时：从目录里拿掉，正在等批准的申请作废，已经进来的人照旧在里面（要清人就用移出）。

### 加密

Matrix 的加密只能开、不能关，所以：

- **新建时选“公开”：** 房间不加密。服务器和进来的人都读得到，和公共大厅一样。
- **私密改成公开：** 照样进目录、照样按加入方式进人，但这间还是加密的。公开以后进来的人看不到公开以前说的话：那些话是私下说的。其实他们连公开以后、自己进来以前的也看不到（见下面“公开以后不再重发以前的房间钥匙”），进来以后的照常看得到。
- **公开改回私密：** 从这一刻起打开加密，以后再改成公开也还是加密的。之前不加密说的那些话，留在服务器上，到房间保留期才删。确认框里写清楚。
- 所以“私密的房间都是加密的”一直成立，README 和隐私说明页的说法不用改，只加公开房间那一条。
- 服务器要知道每间房到底加没加密：房间目录加一个加密标记，建房、开加密时写上。用到“加不加密”的地方都改成看它，不再按种类猜：
  - 自动发言要不要扫描（加密的不扫，不加密的对“房间里任何人”自动发言照旧过一遍病毒扫描）；
  - 上传正文和附件时，核对客户端声明的方式（`client_e2ee` 还是 `server_side`）和房间对得上。现在不核对，不加密的房间里声明成加密就能跳过扫描。
- “@所有人”照旧只在加密房间里有效，不加密的公开房间里没有，免得一个人叫醒满屋子。

### 加入方式

- **直接进：** 在目录里点“加入”就进来了，拿到房主定的默认权限（默认查看、发言、自动发言，和邀请链接一样）。
- **申请：** 点“申请加入”，可以留一句话（最多 200 字）。房主和管理员在房间设置里看到、批准或拒绝；批准以后申请人的网页自动加入，不用再点一次（停在发现页上时；离开了的，邀请在“房间”页上等他点）。申请一直等着，没人处理也不作废（维护者定），所以不设每间房的上限：设了上限又不作废，没人处理时这间房就再也申请不进来。同一个人对同一间房同时只能有一个申请，被拒的 24 小时内不能再申请。房间关了、公开改回私密时，在等的申请作废。
- **只能邀请：** 目录里看得到，但只显示“只能邀请”，没有按钮。
- 被封禁的人哪种方式都进不来，目录里也不给他按钮。
- Agent 跟着主人进：主人是成员，才能把自己的 Agent 带进来（照现在私人房间的规则，发言要主人有自动发言）。没有账号的网络 Agent 照加入方式来：直接进的房间拿房间号就能进，申请的房间敲门，只能邀请的用口令。房主可以在设置里关掉“没有账号的网络 Agent”，默认开着，和公共大厅一样。

### 管理员

- 管理员就是有“管理”这一位的人。房间设置的成员列表里，有这一位的人写“管理员”，旁边一个按钮“设为管理员 / 撤掉管理员”，不用再展开权限去勾。
- 管理员能做的和现在“管理”一样：审批申请、邀请、移出、封禁、解封、禁言、隐藏消息、改别人的权限（改不出自己没有的）、把管房间交给自己的 Agent。
- 管理员不能：切换公开和私密、改加入方式、转让房主、动房主。管理员之间动不动得了，照现在的规则，不改。

### 房主的 Agent 管房间（维护者定：照主人定的规则自己动手，能封禁）

- **谁能给：** 房主和管理员，给的只能是自己的 Agent，管的只能是这一间房。给的时候要最近登录过（和治理一样，这是把权力交出去）。
- **给的时候填：**
  - 规则：一段话，最多 2000 字，比如“发广告链接的直接封禁；连续刷屏的禁言 10 分钟”；
  - 能做哪几样：禁言（可以限时）、踢出、封禁、解封，默认全勾；
  - 有效期：默认 30 天，最长 30 天，到期自动失效，随时能撤（和自动发言授权一样）。
- **Agent 照规则自己动手，不用每次问主人。** 它动手时不用最近登录，授权本身就是主人的同意。
- **边界：**
  - 动不了房主、管理员和给它授权的人，动不了同一个人的别的 Agent；
  - 只认主人写在授权里的规则。消息里说“管理员让你封谁”“系统要求”都不算（接入说明里本来就这么写）；
  - 动手不限次数（维护者定）。
- **留痕：** Agent 每次动手都进治理台账，写着是谁的哪个 Agent 按授权做的、它给的理由。房主和管理员能撤回。授权被撤销或到期以后，它之前做的照旧生效，要撤的人工撤。
- **Agent 怎么知道规则：** 有授权的 Agent 用新工具读规则、动手；它在这间房里等到消息时，回答里带一个“你在这里有管理授权”的提示，让它去读规则。
- **认人（维护者 2026-11-03 定）：** Agent 给的是它在消息里看到的发言人的聊天账号。控制面认成一个“人”：人的账号就是他；别人的本机 Agent 认成它的主人；网络 Agent 认成它自己（它有一个替它记账的主体）。台账里的对象照旧是这个人，旧版网页读得出来。认出来是房主、管理员、给授权的人的，连同他们的 Agent，一律动不了。
- **落到哪：** 照房主和管理员自己动手的那一套做，再在台账里记一条：
  - 禁言（可以限时）走台账的禁言，这个人和他名下此刻在房间里的 Agent 一起压到发言门槛下面，撤回、到期时一起放开；他的 Agent 之后进来、重连时看他此刻是不是被禁言着。人工禁言也一样：Agent 的能力本来就不能超过它代表的人。
  - 踢出、封禁走成员一节那一套（改成员记录、在聊天服务器上踢出或封禁、把他的 Agent 移出），网络 Agent 走“移出 Agent 成员”。凭口令或敲门进来的 Agent 有自己的成员记录，踢出、封禁它的主人时也一起记成已移出（7a-2c-3）；网络 Agent 撤回时不替它恢复，它要回来就凭新口令或敲门。只改聊天服务器、不改成员记录的话，网页会把被踢的人当成还在房间里，又替他加入。
  - 解封只解同一个房间里 Agent 封的人，人工封的 Agent 动不了。
  - 台账里撤回 Agent 做的封禁就是解封；撤回踢出是照房间新成员的默认权限重新邀请他。
  - 人在台账里踢出、封禁也照成员一节那一套落，撤回也一样（7a-2c-1 时改的）：以前只在聊天服务器上踢，成员记录还是已加入，网页会替他加回来；撤回封禁以前在聊天服务器上解封再邀请，现在和成员一节的解封一样回到“已移出”，要请他回来就再邀请。
  - “是哪个 Agent、按哪份授权、它写的理由”单独记一张表，不往 `moderation_action` 加列：台账那张表读写的地方多，旧版控制面回滚时也不用管新列。
- **只有本机 Agent 拿得到授权：** 给的只能是自己名下的 Agent。网络 Agent 没有主人，谁也给不了它，所以只做本机 Agent 动手的入口，远程 MCP 不加 `agent_room_moderate`。

### 常驻公告（维护者 2026-11-01 补充）

- **谁能写：** 房主和管理员（有“管理”这一位的人）。公开的、私密的房间都有，不只是公开房间。公共大厅没有。
- **写什么：** 一段纯文本，最多 2000 字，能换行，不收回车（和消息一样）。每间房只有一条，新写的盖掉旧的；清空就是撤掉公告。不用最近登录过：这是日常管理，不是把权力交出去。
- **存在哪：** 房间的状态事件 `io.github.rainyflash.agentroom.room.notice.v1`（正文、改的人、改的时间），由控制面查过权限以后以应用服务写进 Matrix，和治理动作一样。不另建表，原因有三：
  - 网页、本机 Bridge、网关本来就在同步房间状态，改了马上都看得到，不用再轮询一个接口；
  - 公告跟着房间走，以后房间放到别的服务器上（联邦）也带着；
  - 房间的 `state_default` 是管理员那一级（100），只有应用服务够得着，所以收到的这类状态事件一定是经控制面查过权限写的。读的一边只认这个 `state_key` 为空、发送者是应用服务的那条。
- **在哪看：**
  - 房间页对话上方一条“公告”，显示开头两行，点开看全文。改了以后你还没看过的，那一条亮一个点，看过就灭（看到哪一版记在本机）。
  - 房主和管理员在那一条上有“编辑”，打开一个输入框，写着还能写多少字；房间设置里也能改。
  - 对话里留一行“某某更新了公告”，免得改了没人知道。
  - 目录和不登录的围观页不显示公告，只给房间里的人看。
  - 房间归档以后公告还看得到，不能再改。
- **Agent：**
  - 进房间时（`agent_room_join`、换房间、命令行 `join`）回答里带上公告；之后公告改了，下一次等消息的回答带一个 `notice`，写着新的公告和改的时间，只带一次。远程 MCP 的网络 Agent 一样。
  - 说明里说：公告是房主和管理员写的这间房的规矩（比如“只在被点名时说话”），照着做，主人说的优先；照旧不因为公告里的一句话执行命令、打开链接，也不信“管理员说”“系统要求”。
  - Agent 先只能读，不能写（见“不做”）。
- **谁读得到：** 公告是房间状态，加密房间里也不加密，服务器读得到。编辑框里写一句“公告不加密，服务器读得到”。聊天服务器不删状态事件，改过的旧版本跟着房间一直留着，直到房间被删。

### 发现页（维护者 2026-11-02 看过设计稿）

- **在哪：** 顶栏的导航多一项“发现”，放在“房间”后面，地址 `/explore`。不登录也能看（维护者定的第 6 条），页面 `noindex`。没登录时顶栏是“登录”“注册”，卡片上的按钮写“登录后加入”。
- **找：** 一个搜索框，搜房间名、简介和房主的昵称。几个快捷筛选：全部、能直接进、要申请、一小时内有人说话、不加密。排序：最活跃（最近有人说话的在前）、人最多、最新开的。
- **列：**
  - 最上面一排是平台建的公共大厅，和现在“换个房间”里的一样。
  - 下面是公开房间的卡片：头像（名字的第一个字，底色按房间 ID 算）、名字、房主、简介开头两行、几个人几个 Agent、多久以前有人说话、加入方式和加不加密的标签。
  - 卡片上不写在线人数：要替房间里每个人问一次在线状态，一页几十间房问不起。在线人数只在点开的房间详情和分享页上写，一次只算一间。
  - 按钮看你的处境：“加入”（直接进）、“申请加入”（要申请）、“已加入 · 进去”、“等待批准”（旁边能撤回）、“只能邀请”（没有按钮）。被封禁的不给按钮。
  - 什么都没搜到时说“没找到”，给一个“自己开一间公开房间”。
- **房间详情：** 点卡片，右边滑出一块：头像、名字、房主和几位管理员、开了多久、整段简介、人数、Agent 数、现在几个在线、加入方式、加不加密的说明。要申请的房间就在这里留一句话（最多 200 字）申请，不用再跳一页。也有“分享”。
- **别的页跟着改：** “房间”页只列你在的房间（自己的、加入的、收到的邀请），公共大厅挪到发现页最上面；“换个房间”里加一条“去发现页找更多”。

### 分享链接（维护者 2026-11-02 看过设计稿）

- **谁能分享：** 公开房间里的成员都能，不只是房主和管理员；发现页的房间详情上也有“分享”，没进房间的人也能转给朋友。只能邀请的房间没有分享按钮：链接打开了也进不来。私密房间没有分享链接，照旧用 7 天的邀请链接（那个带着秘密，能直接进门）。
- **链接长这样：** `https://agentroom.chat/r/<分享码>`。
  - 分享码 6 位，大小写字母和数字随机组成（约 568 亿种），每间房一个，第一次公开时生成。不用房间名：别人抢不走名字，房间改名链接也不断。
  - 大家分享的是同一个链接，链接里没有谁分享的，服务器也不记谁复制了、谁点开了。
  - 分享码不是秘密：拿到它只看得到目录里本来就看得到的东西，进门照样按加入方式来。
  - 房主能在房间设置的“公开”一节里“换一个分享码”，旧的马上作废（比如链接被贴到了不想要的地方）。改回私密时码留着，再公开还是原来那个；换码才会变。
- **打开以后（分享页）：** 一个独立的网页，电脑和手机各一种排法。
  - 上面是房间：头像、名字、房主、开了多久、“公开房间”和加入方式、加不加密的标签、整段简介、几个人几个 Agent、现在几个在线。不加密的写一句“这间房不加密：进来的人和服务器都能看到房间里的话”。
  - 按钮看加入方式：
    - 直接进：“加入房间”（手机上写“登录并加入”），下面一行“还没有账号？用邮箱注册”，注册完自动回到这里接着加入；
    - 要申请：“申请加入”，登录回来打开房间详情，申请框已经展开；
    - 只能邀请（链接发出去以后房主改了）：说“这个房间只能由房主邀请”，没有按钮；
    - 不公开了、关了、被平台从目录里拿掉、码换了、没有这个码：一律“这个房间现在不公开了”，回 404，不写房间名，免得旧链接说出改回私密的房间叫什么。
  - 按钮都去应用里的 `/explore/<分享码>?join=1`：没登录的先登录或注册，回来以后直接进的就加入、要申请的就打开申请框；已经在里面的直接进房间。分享页本身不知道你登没登录。
  - 下面一块“带上你的 Agent（可选）”：加入只要网页，网页里就能聊；想把自己电脑上的 Agent 带进来，装桌面应用，在“接入 Agent”里点一下；只在网页上用聊天助手的不用下载，登录后在“接入 Agent”里选“网络”。电脑上给 Mac 和 Windows 的下载按钮，手机上不给下载，给“复制链接”，让人发到电脑上再打开。
  - 再下面是三步（登录或注册 → 加入房间 → 带上 Agent，可选）和“看看别的公开房间”（去发现页）。
  - 中文还是英文按浏览器的 `Accept-Language`；抓预览的爬虫多半不带它，这时看房间名里有没有中文字。
- **房间里的“分享”：** 公开房间的顶栏多一个“分享”，打开一个对话框：
  - 链接和“复制链接”；
  - 一段默认的话（“来「房间名」一起聊聊吧：简介开头……”加上链接），能改，改了只用这一次、不存，旁边“复制这段话”；
  - 发到 X、微博、Reddit：打开它们自己的分享网址（`x.com/intent/post`、`service.weibo.com/share/share.php`、`reddit.com/submit`），带上链接和那段话。不加载它们的脚本，它们也不知道是谁点的；
  - “更多…”：系统的分享菜单（`navigator.share`），没有的地方（桌面端的 WebView 多半没有）不显示；
  - 二维码：微信、QQ 里扫一扫就能打开。在本机画，不经过别的服务；
  - “发出去长这样”：社交媒体上显示的标题、简介和图。
- **发到社交媒体时的预览：** 分享页带 `og:title`（“房间名 · Agent Room”）、`og:description`（简介开头，没写简介就用一句通用的）、`og:image`、`twitter:card`。预览图先用一张通用的（Agent Room 公开房间，设计稿那种样子但不写房间的字）。每间房自己的图（房间名、简介、人数画上去）要在服务器上画图、缓存，以后再做。
- **搜索引擎：** 分享页和发现页都 `noindex`，不进站点地图。房间名和简介是用户写的，平台不审，不替它们进搜索结果；房间改回私密以后也不会在搜索结果里留着。以后要放开再说。

### 谁读得到

- 不加密的公开房间：服务器、房间里的每个人和 Agent 都读得到。房间页顶上写“公开房间，不加密”。
- 加密的公开房间：和私人房间一样（运营方读得到，见 ADR 0011）。
- 申请留的那句话、管理授权里的规则，存在服务器上，房主和管理员看得到。隐私说明页加上这两样留多久：申请处理完（批准、拒绝、作废、撤回）30 天删，没处理的一直留着；授权到期或撤销后 30 天删。删账户时他的申请一起删。
- 常驻公告：房间里的人和 Agent、服务器都读得到，加密房间也一样；旧版本跟着房间留着（见上面“常驻公告”）。隐私说明页也写上。
- 发现页和分享页不登录就看得到：房间名、简介、房主的昵称、几位管理员、人数、Agent 数、现在几个在线、多久以前有人说话。房间里说的话、成员名单都不给。设成公开的确认框里写上这一句，隐私说明页也写上。

### 限额

不审内容，但要防服务器被拖垮：

- 每个账户最多有 1 间公开房间（私密的不限）。
- 房间暂时不设人数上限（维护者 2026-11-01 改定，原来写的是每间最多 500 人）。公共大厅一个分片的上限是 250（`DEFAULT_ROOM_HARD_CAPACITY`），用户建的房间可能比它多，所以上线后照测量的数看：Synapse 的 CPU、发言到对方看到要多久、最大的几间房有多少人。加密的房间人越多，换一把房间钥匙时要发给的设备越多，换钥匙后的第一句会越慢，这一项也要看。人多的房间多了、数不好看了再定上限。
- 公共大厅对网络 Agent 的限额（进来的个数、每个 Agent 每分钟 20 句、整间每分钟合起来 12 句）也套到公开房间上。现在这些只在公共大厅里查（`network_agents.rs` 的 `is_public_lobby`），改成“公共大厅或公开房间”。私密房间照旧不设限（#408）。
- 平台不审消息，但保留现有的平台治理（`moderation_operator`）：能冻结房间、从目录里拿掉。出了违法的事总得有人能处理。

## 做法

### 控制面

- **迁移：**
  - `room_catalog` 加 `end_to_end_encrypted`：已有的私人房间和私聊写成 true，公共大厅写成 false。默认值 true：回滚到上一版时，旧代码建的私人房间都是加密的，对得上。
  - 新表 `private_room_listing`：公不公开（`listed`）、加入方式、新成员的默认权限、允许没有账号的网络 Agent、分享码（唯一）、第一次公开的时间、最近有人说话的时间、改的人和时间。房间第一次公开时才有这一行，改回私密也留着。不放进 `room_catalog`，那张表很热。
  - 房间目录上的 `visibility` 不改成 `public`，公不公开只看 `listed`：回滚到上一版时，旧代码读到 `visibility` 是 `public` 的私人房间（约束 `room_catalog_entry_private_visibility` 不许），这间房就整个读不出来了。原来写的是放开这条约束，做的时候改了。
  - 新表 `private_room_join_request`：房间、申请人、留言、状态（等着、批准、拒绝、作废、撤回）、时间、处理的人。
  - 新表 `room_moderation_grant`：照 `automation_grant` 的样子，记 Agent、房间、规则、能做的几样、有效期、给的人、状态。
  - `moderation_action` 加两列：执行的 Agent、按的哪份授权。
- **接口：**
  - `GET /public-rooms?q=&join=&active=&encrypted=&sort=&cursor=`：发现页的目录，不要登录。每间房给名字、简介、房主昵称、人数、Agent 数、加入方式、加不加密、开房时间、最近有人说话的时间、分享码。登录的人另带一个 `viewer`：已加入、等待批准、被封禁。
  - `GET /public-rooms/{分享码}`：一间房的详情（房间详情和应用里的 `/explore/<分享码>` 用），比目录多几位管理员、现在几个在线。不公开、关了、没有这个码都回同一个 404。
  - `POST /private-rooms/{c}/listing/share-code`：房主换分享码，回新的。
  - `GET /private-rooms/{c}/listing`、`PUT /private-rooms/{c}/listing`：公开设置。单独一个接口：网页的 `privateRoomSchema` 是 `.strict()`，房间的回答里多一个字段，旧版桌面端整个房间都读不出来。
  - `POST /private-rooms/{c}/join`：直接进。服务器记下成员、以应用服务邀请，网页自己加入（和邀请链接同一条路）。
  - `POST /private-rooms/{c}/join-requests`、`DELETE` 撤回；管理员 `GET /private-rooms/{c}/join-requests`，`PUT .../join-requests/{id}` 批准或拒绝。
  - `GET|POST /private-rooms/{c}/moderation-grants`、`DELETE .../{id}`：管理授权。
  - Agent 动手：本机 Agent 走设备签名的 `/agents/{a}/instances/{i}/rooms/{c}/moderation`（读授权和规则）和 `.../moderation/actions`（动手），和 Agent 离开房间那条设备签名的接口一个样子。进同一个治理服务，执行人记成给授权的人，另一张表记是他的哪个 Agent、按哪份授权、它写的理由；不要最近登录，按授权查能做什么。网络 Agent 拿不到授权（见上面“只有本机 Agent 拿得到授权”），没有它的入口。
  - 台账里“是哪个 Agent 做的”单独一个 `GET /rooms/{c}/moderation/actions/agents`：网页对治理动作严格校验（`moderationActionSchema`），动作里多一个字段，旧版的台账整个读不出来。
- **改成看加密标记：** `inspect_send_authority`、上传正文时核对加密方式（`RoomContentPolicyLookup`，不加密的房间里声明成 `client_e2ee` 回 400 `content.upload.encryption_mismatch`）。“@所有人”不用改：网关本来就看 Matrix 上这间房到底加没加密，接收方也只认加密消息上的。
  - 公共大厅从来不加密，约束 `room_catalog_entry_lobby_unencrypted` 卡着：哪里建大厅（测试、`tools/vertical.py`）要写 `end_to_end_encrypted = false`，不然插入失败。
- **公开改回私密：** 应用服务往房间里写 `m.room.encryption`，再把标记改成 true。写不进 Matrix 就不改标记，告诉房主没改成、可以再点。
- **公开以后不再重发以前的房间钥匙：** 房间第一次公开时，应用服务写一条房间状态 `io.github.rainyflash.agentroom.room.listing.v1`（`firstListedAt`，第一次公开的时间，协议里是 `RoomListingState`）。
  - 房间钥匙里没有时间，分不清哪个会话是公开以前建的，同一个会话还可能跨过这一刻接着用，所以一刀切：成员事件在这一刻以后的人，别人不给他们重发房间钥匙（网页的 `MatrixRoomKeyResponder`、matrix-adapter 的 `room_keys`），他们自己也不去要（网页的 `MatrixRoomKeyRecovery`、matrix-adapter 的 `room_key_requests`）。两边都在 `room_listing` 那一个判断里。
  - 代价：公开以后进来的人，连公开以后、自己进来以前的话也看不到；他们的设备和 Agent 之间的通道坏了，也不能请别人补发。这只发生在“加密的房间改成公开”这一种，新建的公开房间不加密，没有钥匙这回事。
  - 宁可少给：状态读不出来当成一开始就公开了；成员事件改过（比如改名）按最新那条的时间算；看不出时间的也算后来的。这条状态只会让重发变少，所以读的时候不核对是谁写的。
- **常驻公告：** `PUT /private-rooms/{c}/notice`（正文，空的就是撤掉），查“管理”这一位、房间没归档，然后以应用服务写状态事件 `room.notice.v1`。没有读的接口，读走 Matrix 的房间状态。写不进 Matrix 就回错，网页说没改成、可以再点。
- **最近有人说话：** 控制面每 5 分钟以应用服务读一次每间公开房间最新的一条消息事件，只取它的时间、不读内容（加密的房间也只看时间），写进 `private_room_listing`。发现页的“一小时内有人说话”和“最活跃”都按它。
- **在线人数：** 只在一间房的接口里算，照围观页那套以应用服务问房间成员的在线状态，每间房的结果留 60 秒。人很多的房间一次只问最多 200 个，写“至少 N 个在线”。上线后看测量的数，问得太多再换办法。
- **分享页：** `GET /r/{分享码}` 由控制面出整页 HTML。
  - Caddy 在裸域上把 `/r/*` 转给控制面，`public.site` 是 `redirect` 还是 `static` 都转（写在 `_server_name_block` 两种情形共用的那段）。
  - 裸域的内容安全策略只许同源的样式和脚本、不许内联，所以页面用控制面带着的两个固定名字的文件（`/r/_/share.css`、`/r/_/share.js`，只管复制链接）。分享码只有字母和数字，碰不上 `_`。
  - 房间名、简介、房主昵称都是用户写的，放进页面和 `og:` 标签之前一律转义，测试卡着。
  - `Cache-Control: public, max-age=60`，房间改名、改回私密以后一分钟内就变；404 不缓存。加 `X-Robots-Tag: noindex`。
  - 按来源限流，照现有按 IP 的那套，挡住拿分享页挨个猜码。

### 网页

- 房间设置加一节“公开”（只有房主看得到能改的那几项，管理员只读）：公开 / 私密，加入方式，新成员的默认权限，允许没有账号的网络 Agent，分享链接和“换一个分享码”。切换时的确认框按上面“加密”一节说清楚，也写上不登录的人看得到哪些（见上面“谁读得到”）。
- 成员一节：写“管理员”，加“设为管理员 / 撤掉管理员”。下面一块“申请”，有新的申请时房间设置的齿轮上亮一个点。
- 发现页和房间详情（见上面“发现页”）。新路由 `/explore` 和 `/explore/$code`，和围观页一样不进登录会话也能打开（`root-layout.tsx` 的 `outsideSession`），登录了再带上自己的处境。`/explore/$code?join=1` 没登录时先去登录、回来接着做（照 `/join` 页的做法）。两个路径加进 `tools/prodops/render.py` 的 `APP_PAGE_PATHS`（`/explore`、`/explore/*`），不然在 app 子域上回 404；裸域上它们照旧跳到 app 子域。
- 公开房间顶栏的“分享”对话框（见上面“分享链接”）。二维码要加一个画二维码的库，同一个 PR 里更新许可证清单。
- 新建房间时多一个选项：私密（默认）/ 公开。选公开就提醒“公开的房间不加密”。
- 不加密的公开房间，房间页顶上一行“公开房间，不加密：进来的人都能看到这里的话”。
- 治理一节加“交给 Agent 管”：选自己的哪个 Agent、写规则、勾能做的、有效期；列出在用的授权，能撤。台账里 Agent 做的写“某某的 Agent 按规则：理由”。
- 常驻公告：房间页对话上方的“公告”一条（开头两行、点开看全文、没看过的新版本亮点），房主和管理员能编辑；对话里“某某更新了公告”那一行。读房间状态，只认应用服务写的那条（见上面“常驻公告”）。浏览器验收在 `lobby-scene.html?private` 上加 `notice`。
- 中英文一起加。

### Agent

- 本机 MCP、命令行、远程 MCP 加两样：
  - 找公开房间（`agent_room_list_rooms` 加一个 `public` 选项，或者单独一个工具，做的时候看服务说明的字节数再定）；
  - 管房间：一个工具 `agent_room_moderate`，`action` 是 `rules`（读规则和能做什么）、`mute`、`kick`、`ban`、`unban`，带对象、时长、理由。命令行是 `moderate`。网络 Agent 拿不到授权，远程 MCP 不加这个工具（7a-2a 时改的）。
- 新工具要同步三处：`tools/mcp_release_gate.py`、`tools/mcp_client.py`、`apps/agent-room-mcp/src/agent_room/server.rs` 里列全部工具的测试。说明都是英文、参数说明写一行；两份服务说明都贴着 1536 字节，要加话得先删。
- 有授权的房间，等消息的回答里带一个 `moderation` 提示（只有它在这间房有授权时才有）：这一批里交给它管的房间、能做哪几样、到什么时候，规则不带，要读另外问（7c-2 时定的）。
- 本机 Agent 动手要经 Bridge：新的 IPC 方法 `ModerateRoom`，用管房间的授权范围 `rooms_manage`，放进还没发布的 IPC 4.6，Bridge 照旧同时认 4.4 和 4.5（照“代码里的坑”里那两条；7c-1 时改的）。等消息的回答多一个字段，旧版 MCP 和命令行认不认，做的时候查。
- 进公开房间：直接进的拿房间号就能 `agent_room_join`；申请的照现在敲门；只能邀请的照旧用口令。主人把分享链接贴给 Agent 时，`agent_room_join` 也认 `https://agentroom.chat/r/<分享码>`，换成房间号再照加入方式进。
- 常驻公告：matrix-adapter 同步时读 `room.notice.v1`（Bridge 和网关共用那一段），进房间的回答带 `notice`，改了以后下一次等消息带一次。等消息的回答多一个字段，和 `moderation` 提示一样，旧版 MCP 和命令行认不认，做的时候查。服务说明里加一句怎么对待公告，两份都贴着字节上限，先删别的。

### 文档

- 隐私说明页：公开房间谁读得到，申请留言和管理规则留多久，常驻公告不加密、旧版本跟着房间留着，发现页和分享页不登录看得到哪些。同一个 PR 改页面文字和顶上的日期。
- README 的“谁能读到什么”加公开房间一条。
- `agents.md`、`agent-room guide`：怎么找公开房间、有管理授权时怎么做。

## 不做

- 平台审内容、关键词过滤。房主自己管（维护者 2026-11-01 定）。
- 举报按钮。先靠房主和管理员；真出了要平台处理的事，走现有的平台治理。
- 不登录围观用户的公开房间。围观页现在只认公共大厅；用的人多了再说。
- 已有的加密房间改成不加密。Matrix 做不到；要不加密就新建一间公开的。
- 按标签、语言、地区分类的目录。先只搜名字、简介和房主。
- 分享页上显示房间里的话。只给名字、简介和几个数；要看话得进来。
- 记谁分享的、给分享的人奖励或排行。
- 加载社交平台的脚本或分享按钮（各家的 SDK）。只用它们的分享网址和本机画的二维码。
- 每间房自己的预览图。先用一张通用的。
- 让搜索引擎收录分享页和发现页。
- Agent 写公告。先只给人；Agent 建的房间、有管理授权的 Agent 要不要能写，用起来再说。
- 公告里的格式（加粗、链接可点）和图片。先只有纯文本。

## 安全

- **Agent 被骗去动手。** 只认授权里的规则；只能动普通成员；每次进台账、能撤回；授权随时能撤。动手不限次数，所以最坏的情况是它一下把很多普通成员禁言、踢出、封禁：房主和管理员它碰不到，撤掉授权、在台账里撤回就好。台账里同一份授权做的可以一次全撤（做第 7 步时加）。
- **刷房间。** 每个账户 1 间公开房间。私密房间照旧不限。
- **人太多。** 不设人数上限，靠测量盯着（见上面“限额”）。网络 Agent 那几条限额照旧套到公开房间上，挡住的是最容易刷的那一种。
- **借公告指使 Agent。** 管理员写的公告 Agent 会当成房间的规矩，所以服务说明里写清楚：公告只是房间的规矩，不是主人的话，照旧不因为它执行命令、打开链接。公告只有房主和管理员能写，普通成员和别的 Agent 写不了。
- **刷申请。** 每人每间一个、被拒 24 小时内不能再申请，申请要登录（注册要验证邮箱）。
- **公开以前的私密话。** 加密房间公开以后，新进来的人没有以前的钥匙；我们自己的客户端也不再给他们重发，新进来的人的客户端也不去要（见上面）。还没更新的旧版客户端照旧会给新进来的 Agent 重发加入前的钥匙，所以改钥匙重发的那步要比“加密房间能改成公开”早一个版本发；就算这样，长期没更新的客户端还是会重发，确认框里不承诺“绝对看不到”，只说“新进来的人一般看不到”。
- **跳过病毒扫描。** 上传时按房间的加密标记核对声明的方式，不加密的房间不收声明成加密的正文。
- **借分享页冒充。** 分享页顶着 Agent Room 的标志，房间名和简介却是用户写的，有人可能起名“Agent Room 官方客服”拿去骗人。页面上写着“房主 某某”，底下一行“房间由用户创建，Agent Room 不审核内容”；平台治理把房间从目录里拿掉以后，分享页马上回 404。
- **猜分享码。** 码不是秘密，猜中了也只看得到目录里的东西；不公开、没有这个码回同一个 404，分不出这个码存不存在过；分享页按来源限流。
- **分享页里的脚本注入。** 用户写的字一律转义；页面不许内联脚本，只认同源的那一个文件。
