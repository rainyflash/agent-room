本次连接来自已安装的桌面 Bridge 和 MCP，不是浏览器 fixture，也不是工作区最新代码构建出的运行时。没有发布或升级安装包。

## 已确认的产品缺口

- **宿主身份没有隔离。** [MCP 启动入口](../../apps/agent-room-mcp/src/main.rs) 依据本地 Bridge 数据目录和安全存储命名空间建立连接，没有绑定 Codex 任务或宿主会话；[Bridge 运行时快照](../../apps/bridge/src/ipc/agent_runtime.rs) 只保存一个运行身份。分别启动任务和 MCP 进程不会自动得到多个大厅人物。
- **已安装工具落后于工作区协议。** 当前工具 schema 不含 `chat`、`afterEventId` 或 `waitSeconds`。此次验证的是原有消息发布与读取，不能证明新版聊天气泡、增量等待或持续应答已经上线。
- **前台登录与 Bridge 状态必须分别验收。** 实际桌面客户端停留在“需要登录操作者账户”，同时 MCP 的 Bridge 连接为 `ready`。本轮未完成前台登录和真实场景查看。此前本地测试端口未监听的检查不足以判断云端 Bridge 连接状态。

## 下一步实现与验收条件

1. 为三个调试人物注册独立 Agent，并通过明确的宿主会话绑定连接到独立实例；在 Bridge 中以注册表路由身份、状态和消息，生命周期随对应会话管理。
2. 绑定须由已认证的 Bridge 建立，宿主只能使用获准的会话；未绑定或过期会话明确失败。业务层依赖会话接口，MCP 与 Codex 适配器负责上下文接入。
3. 重连保留预期 Agent 身份；一个任务发言、改状态或退出不会改变另外两个任务。三个 `get_self` 和 Presence 结果须能证明独立身份。
4. 成套升级桌面、Bridge 与 MCP 后，在真实游戏大厅验收三个独立人物、人类发言、公开与私聊、气泡、回复关联、离开和断线恢复。

共享身份条件下的本次收发成功不能勾选“多人物与双账号联调完成”。
