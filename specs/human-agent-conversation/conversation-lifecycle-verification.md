# 大厅对话生命周期与真实收发调试

日期：2026-09-06。本次基于 alpha.19 调试并修复代码，未发布新的安装包，也未升级生产服务。

后续进展：本文保留当时的失败结论；Agent 加密身份、参与者验证与双向私聊的后续修复和真实证据见[加密私聊验收](./private-chat-verification.md)。

## 修复范围

- 工作区按房间保留聊天草稿、提及、回复对象与发送事务。暂时关闭面板不再中断结果确认，重试继续使用原提交标识。退出工作区或切换账户会清理这些内存状态；不承诺刷新后的草稿恢复。
- 私聊只在可见聊天时间线滚到最新消息，或最新资料条目实际可见时发送已读回执。切换资料页、隐藏页面、阅读旧消息不会提前清掉新聊天的未读状态。
- Pixi 使用静态着色器同步实现，正式 CSP 禁止动态代码求值时仍保留游戏房间渲染与交互。
- 新建私聊等待 Matrix 成员同步确认后再开放操作，公开大厅复用同一个加入确认适配器。
- 私聊内容授权通过会话中既有目标 Agent 查询 Matrix 成员状态。目标身份来自可信会话记录；仍检查产品参与者、屏蔽策略和活跃身份，不邀请第三个服务账号、不读取解密密钥，也不以数据库记录替代实时成员检查。
- 加密身份未就绪时在首次上传前明确拒绝；重试已上传事务也会重新检查。未加密的失败本地回显会解除待发送占位；加密后的未知网络结果继续保留原事务等待确认。投递查询不再把本地回显误认为服务端已接收。
- 安全中心直接打开或刷新时先恢复账户和 Matrix 会话，避免在启动阶段挂起查询并停留于不可用状态。

## 真实服务证据与剩余问题

联调使用隔离 Synapse、PostgreSQL、OIDC、对象存储与两套 Bridge，经正常浏览器登录建立两个人类账户，并通过 MCP 会话注册建立两个独立 Agent。实际页面使用 HTTPS 生产构建；测试消息、账号与会话仅属于隔离环境。

最终真实服务自动验收通过：人类公开发言被 Agent MCP 读取，Agent 回复被两个人类浏览器收到并显示正确回复引用。创建的私聊房间经 Matrix 查询恰好只有目标 Agent 和人类两名成员；无关 Agent 的私聊读取被拒绝。新账号加密尚未配置时，界面在上传前拒绝发送、保留草稿并提示设备验证；安全中心直接访问与刷新恢复正确账户。验收结束后两个测试会话已关闭，隔离服务已清理，原开发服务已恢复。

**加密私聊的完整 Agent 收发尚未通过。** 在人类完成加密身份设置后，实际消息可进入双人 Matrix 房间，但目标 Agent 的 MCP 未能解密读取。当前 Bridge 缺少完整的加密身份建立与参与者设备验证接入；浏览器的“仅签发设备”策略和 Bridge 的“仅可信设备”策略都保留不变。公开聊天通过、Matrix 提交成功、单元测试通过均不能当作私聊已可用的证据。

下一步需要补齐 Agent 加密身份的建立、已有身份的恢复与设备验证流程，再验收人类到 Agent、Agent 到人类、新设备和身份变更后的私聊行为。不能通过明文回退、默认信任未知设备、邀请第三个账号或修改测试预期来绕过这一问题。

完整私聊尝试的失败与公开聊天、加密前置检查的验收分别记录；不将完整私聊失败改标为通过。一次性编排脚本、脱敏日志和截图位于操作者的外部临时验收目录，未随代码提交。
