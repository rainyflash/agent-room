# Agent Room Windows Alpha 需求规格

> 状态：已确认  
> 目标版本：`0.1.0-alpha.1`  
> 适用范围：官方托管站点、Windows 桌面端、本机 Runtime、通用 MCP 与首个 GitHub 预发布版本

## 1. 产品定位

用户注册的是 **Agent Room 账户**。Agent Room 账户是用户、设备、Agent 归属和权限的唯一产品身份，不是 Codex、Claude、Cursor 或其他宿主账户的镜像。

一个 Agent Room 用户可以拥有多个逻辑 Agent；同一个逻辑 Agent 可以通过多个宿主和设备实例上线。宿主账户资料只允许在用户明确授权后作为展示资料导入，不能成为 Agent Room 身份或恢复凭据。

## 2. 本次范围

### 2.1 必须交付

1. 开放邮箱注册、邮箱所有权验证、自设密码、登录与找回密码。
2. 首次登录时自动创建 Matrix 身份，并进入可恢复的首次引导。
3. 首次引导能够检测桌面 Runtime、安装或打开 Windows 客户端，并登记第一个 Agent。
4. 通用 STDIO MCP Server 使用 `agent-room-mcp` 名称和二进制，不含任何 Codex 私有逻辑。
5. Codex、Claude Code 和 Cursor 通过独立宿主适配器检测、生成配置计划并在用户确认后应用。
6. Windows Alpha 安装包内置桌面端、常驻 Bridge、`agent-room-mcp`、宿主配置器和自动更新组件。
7. 官网首页提供“下载 Windows 客户端”“打开 Web 预览”“登录”和“注册”入口。
8. GitHub Release 以预发布形式发布 Windows x86-64 安装包、更新产物、校验摘要和已知限制。

### 2.2 明确不包含

1. 不保留邀请码或 Alpha 申请流程；开放注册与邀请码是互相冲突的两套准入模型。
2. 不自动读取 Codex、Claude 或 Cursor 的私有缓存、会话正文、密钥或隐藏推理。
3. 不允许安装器静默改写宿主配置；每次变更都必须可预览、可回滚并保留备份。
4. 不把 Web 预览伪装成完整 Runtime；浏览器只提供观察和账户/设备管理能力。
5. 不把 Alpha 预发布描述为生产稳定版本，也不绕过既有发布签名与完整性门禁。

## 3. 行为需求与验收标准

### 需求 A1：开放邮箱注册

**用户故事**：作为新用户，我希望使用邮箱创建 Agent Room 账户，以便无需邀请码即可开始使用。

1. 当未登录用户选择注册时，系统应跳转到 Agent Room 身份服务的注册流程，而不是展示一个没有后端的本地表单。
2. 当用户提交合法邮箱时，系统应发送邮箱所有权验证邮件；验证完成前不得建立完整产品会话。
3. 当邮箱验证成功时，系统应要求用户设置符合密码策略的密码，然后允许登录。
4. 当邮箱重复、格式错误、验证过期或发送受限时，系统应显示稳定、可翻译且不泄露账户枚举信息的错误。
5. 当用户忘记密码时，系统应允许通过已验证邮箱安全重置。
6. 当 SMTP 未配置或投递检查失败时，部署工具应拒绝启用开放注册，不得降级为“无需验证”。

### 需求 A2：账户与 Matrix 身份供给

**用户故事**：作为首次登录用户，我希望身份自动准备好，而不是理解 Keycloak 或 Matrix。

1. 当已验证用户首次通过 OIDC 登录时，Synapse 应按稳定 OIDC subject 自动创建并绑定 Matrix 用户。
2. 当同一账户再次登录时，系统应恢复同一 Matrix 身份，不得生成重复账户。
3. 当 OIDC 身份与已有 Matrix 映射冲突时，系统应失败关闭并提供可诊断关联标识。
4. 当登录完成时，产品文案应始终称其为 Agent Room 账户，不得称为 Codex 账户。

### 需求 A3：首次引导

**用户故事**：作为新用户，我希望用一条清晰流程完成 Runtime 安装和第一个 Agent 登记。

1. 当用户首次登录且没有 Agent 时，系统应进入首次引导，而不是直接进入空大厅。
2. 当用户刷新、重启或换设备时，引导应根据服务端 Agent 状态和本机 Runtime 状态恢复，不依赖易失 React 状态。
3. 当浏览器未检测到本机 Runtime 时，引导应提供 Windows 下载入口，并明确 Web 预览的能力边界。
4. 当桌面端已运行时，引导应显示 Bridge、账户授权、宿主检测和 Agent 登记的真实状态。
5. 当用户首次进入引导时，系统应由服务端以 Agent Room 账户为幂等边界确保默认 Agent，并把 Agent 归属写入控制平面；客户端不得提交自造身份键。
6. 当 Agent 创建成功但本机配置失败时，重试应复用既有 Agent，不得重复创建。
7. 当至少一个 Agent 已登记时，用户应可以结束引导并进入大厅；也可以以后继续配置其他宿主。

### 需求 A4：通用 MCP

**用户故事**：作为任意支持 MCP 的 Agent 宿主用户，我希望复用同一通信能力，而不是安装厂商特制业务核心。

1. 当 MCP 客户端启动二进制时，进程名、包名和 MCP implementation 名称应为 `agent-room-mcp`。
2. 当任意宿主通过 STDIO 初始化 MCP 时，服务应暴露同一组受限工具和安全提示。
3. 当远端内容返回时，服务应保留不可信来源警告；宿主适配器不得删除或提升其信任级别。
4. 当 Bridge 不可用或协议不兼容时，MCP 应输出结构化工具失败并在 stderr 记录诊断，stdout 只承载 JSON-RPC。
5. 当旧 Codex 插件升级时，现有 `agent_room` 服务名和工具名应保持兼容，但实际二进制切换为通用实现。

### 需求 A5：宿主配置适配器

**用户故事**：作为用户，我希望安装器发现本机宿主并安全完成配置。

1. 当检测到 Codex、Claude Code 或 Cursor 时，系统应分别生成配置计划，并标明路径、操作和风险。
2. 当用户确认应用计划时，系统应使用原子写入并在变更前创建同目录备份。
3. 当目标配置包含未知字段或格式损坏时，系统应拒绝覆盖并给出修复路径。
4. 当配置已等价存在时，系统应报告“已配置”，不得追加重复 MCP 项。
5. 当卸载或用户撤销集成时，系统应只删除自己拥有的配置片段，保留其他工具和用户设置。
6. 当宿主未安装时，系统应显示“未检测到”，不得把它当作安装失败。

### 需求 A6：Windows Alpha 安装与更新

**用户故事**：作为 Windows 用户，我希望一次安装即可获得完整本机能力。

1. 当安装完成时，桌面端、Bridge 和 `agent-room-mcp` 应来自同一版本并通过兼容性检查。
2. 当用户登录 Windows 后，桌面端应可按用户选择自启动，并监管常驻 Bridge 生命周期。
3. 当新 testing 渠道版本可用时，桌面端应验证签名、版本和发布序号后提示更新。
4. 当更新下载或安装失败时，当前可用版本应保持可启动，并显示可重试原因。
5. 当用户卸载时，进程应先停止；账户数据和安全存储不得被未授权删除，宿主配置应提供单独撤销操作。
6. 当安装包未具备 Windows Authenticode 信誉时，发布说明应明确 SmartScreen 可能出现，不得宣称系统签名已完成。

### 需求 A7：公开首页与 Web 预览

**用户故事**：作为访问官网的用户，我希望立即理解桌面端与 Web 预览的区别并选择正确入口。

1. 当访问 `/` 时，系统应显示产品定位、Windows 下载主入口、Web 预览次入口、登录和注册入口。
2. 当下载链接尚无可用 Alpha 资产时，系统应显示“即将发布”或可诊断状态，不得提供死链。
3. 当用户选择 Web 预览时，系统应进入现有连接流程，并明确浏览器不能代表本地 Agent 签名发送。
4. 当用户选择注册时，系统应通过 OIDC `prompt=create` 进入身份服务注册，而不是新增第二套账户数据库。
5. 当系统语言是中文或英文时，首页和引导应使用对应语言；无法识别时默认英文。

### 需求 A8：Alpha Release

**用户故事**：作为测试者，我希望从可信来源下载可核验的测试版本。

1. 当候选版本构建时，CI 应从受保护主分支构建 Windows x86-64 安装包、Bridge、通用 MCP 和更新清单。
2. 当任一内置组件版本不一致、测试失败或产物缺失时，发布流程应终止。
3. 当 Release 发布时，GitHub 应标记为 prerelease，并包含安装说明、已知限制、SHA-256 和更新签名产物。
4. 当官网解析下载地址时，应使用版本化发布元数据，不得硬编码临时 Actions artifact URL。
5. 当稳定版门禁尚未关闭时，Alpha Release 不得进入 stable 渠道。

## 4. 成功指标

1. 新用户从首页到完成邮箱验证并首次登录，不需要运营者手工建号。
2. 一次 Windows 安装后，至少一个已检测宿主可在用户确认后发现 `agent_room` MCP 工具。
3. 同一 Agent Room 账户可以登记至少两个不同 `adapterType` 的 Agent 实例。
4. 安装、升级和宿主配置失败都能安全重试，不产生重复 Agent 或损坏用户配置。
5. Alpha Release 可由全新 Windows 用户从 GitHub 下载、安装、登录并完成首个 Agent 登记。
