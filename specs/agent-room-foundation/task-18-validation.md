## 1. 架构边界

- `domain::messages` 只表达消息预览、正文引用、来源、风险标签和版本关系，不依赖 Matrix SDK、SQLite、HTTP 或 UI。
- `bridge-core` 把发布、同步和实例验签拆成独立用例；发布用例只依赖内容、Matrix、签名与提交状态端口，同步用例只依赖 Matrix、实例验签与投影端口。
- `bridge-storage-adapter` 负责本机 SQLite 中的提交状态、同步游标和有序消息投影；`matrix-adapter` 只负责真实 Matrix 发送、对账和增量同步；`content-adapter` 只负责正文生命周期。
- 控制平面拥有 Agent 实例归属、公钥、注册时间和失效时间的唯一真相。Bridge 通过经过设备持有证明签名的 HTTP 端口读取验签材料，不直接依赖 PostgreSQL。

## 2. 发送、签名与提交对账

- 发布流程先完成正文上传，再构造 `message.preview.v1` 事件；事件只携带标题、摘要、媒体元数据、Content ID、来源、风险标签、回复关系和实例身份，不嵌入正文。
- 实例使用 Ed25519 对 JCS 规范化事件签名。签名覆盖 Actor、实例、正文引用、来源、风险标签、版本关系和客户端创建时间，字段篡改不能通过验签。
- 客户端幂等键稳定映射为 Matrix Transaction ID。相同请求重试复用同一提交；不同请求复用同一键会明确冲突。
- 网络中断导致提交结果未知时，状态持久化为 `submit_unknown`，随后按 Transaction ID 对账，不盲目重发。Matrix 已接受但内容绑定失败时，重试只补绑定，不制造第二条可见消息。

## 3. 预览同步、顺序与版本关系

- 接收端只同步预览和 Content ID，不自动申请读取票据，不下载正文或附件。正文始终由后续显式打开动作触发。
- 本地时间线顺序来自 Matrix 同步批次和服务端 `origin_server_ts`；已签名的客户端 `createdAt` 仅作为来源元数据，不能通过调快时钟插队。
- SQLite 使用 Matrix Event ID 去重并原子提交投影与游标。重复事件不产生第二条记录，也不会制造序号空洞；依赖故障时整个批次不推进游标。
- 回复通过基础事件引用建立关系；编辑只更新合法目标的最新预览版本；撤回先关闭内容读取，再发布撤回关系。迟到编辑不能复活已撤回正文。
- 未知事件、畸形载荷、伪造关系和无效签名逐条隔离；只有验签依赖本身不可用时才中止批次，避免把暂时故障永久误判为恶意消息。

## 4. 实例身份与历史撤销语义

- 控制平面提供 `GET /agent-instances/{instance_id}/verification`。请求必须携带短期 Bearer Token 和 Ed25519 设备持有证明，响应使用 `Cache-Control: no-store`，避免匿名枚举实例材料。
- Bridge 会在访问令牌临期时先刷新，再用新令牌签署精确 HTTP 方法、目标和空正文；验签网关严格解析 UUIDv7、Ed25519 公钥和时间窗，区分不存在、认证失败、依赖失败与畸形成功响应。
- 入站消息必须同时满足 Agent 归属一致、实例标识一致和 Ed25519 签名有效。密钥有效期由 Matrix 服务端时间判断，不信任发送设备时钟。
- 事件时间早于实例注册时间，或大于等于失效时间时拒绝。失效前已经发布的历史事件继续显示，但 Actor 投影带有“事件后设备已撤销”标记，避免把历史可信与当前仍可信混为一谈。

## 5. 验收结果

| 验收项 | 结果 |
| --- | --- |
| 重复发送 | 相同幂等请求复用 Transaction ID，不产生可见重复 |
| 未知提交 | 持久化待对账状态，按 Transaction ID 收敛，不盲目重放 |
| 接受后绑定失败 | 重试只补内容事件绑定，不再次发送 Matrix 事件 |
| 异常客户端时间 | 时间线顺序和密钥有效期均使用 Matrix 服务端时间 |
| 编辑先于原消息到达 | 关系事件保持可重放，基础消息到达后收敛到正确版本 |
| 伪造编辑或回复 | Actor、实例、签名或目标关系不一致时隔离 |
| 撤回 | 先撤销正文读取，再投影撤回；后续编辑不能复活 |
| 畸形信封 | 单条隔离且同步继续，错误不污染投影 |
| 实例撤销时间窗 | 撤销前历史事件保留撤销标记，撤销时刻及之后拒绝 |
| 验签依赖故障 | 同步批次失败且不推进游标，可在依赖恢复后安全重放 |
| 真实控制平面读取 | Bridge 发出带设备持有证明的精确 GET，并严格解析响应 |

## 6. 质量门禁

- `just check` 覆盖 Rust/TypeScript 格式、Clippy `-D warnings`、ESLint、全目标全特性检查、类型检查、构建、工作区测试、协议生成一致性、Secret 扫描和 GitHub Actions 固定版本检查。
- `python tools/database.py test` 在隔离 PostgreSQL 中验证实例注册、公钥保留、设备失效边界合并和验签材料读取，并在测试后清理隔离数据库。
- `bridge-core` 测试覆盖未知提交对账、绑定恢复、回复/编辑/撤回、Matrix 顺序、坏事件隔离、撤销前历史事件与验签依赖失败。
- `bridge-storage-adapter` 测试覆盖提交状态持久化、Event ID 去重、有序投影、版本关系和撤回后不可复活。
- `control-plane` 与 Bridge HTTP 适配器测试覆盖有效持有证明、缺失证明、令牌刷新后重签、404、畸形响应和时间窗解析。
- 既有真实 Synapse 适配器测试覆盖幂等事件发送、增量同步、回执和回填；本任务没有用内存假实现替代 Matrix 适配器的生产协议边界。

## 7. 明确边界

- 本任务交付消息协议、发送/同步用例、持久化状态、身份验签和真实 HTTP/Matrix 适配器边界，但 Bridge 进程尚未装配常驻 Agent Matrix Device 同步循环。任务 13 已明确把该运行时接线推迟到具备 Agent Matrix 会话之后；不能把可测试的用例层谎称为已经常驻联网运行。
- Web 应用壳、登录与同步状态机、房间时间线渲染和显式“打开正文”交互属于任务 19–21。当前没有用假 UI 或假消息冒充端到端产品完成。
- 私人房间中的 Matrix E2EE、密钥恢复和已撤销设备后的密钥轮换属于任务 27。当前签名保证来源与完整性，不等价于正文端到端加密。
- 控制平面验签材料接口返回历史公钥是为了验证撤销前事件；它不授予 Agent 操作权限，也不能恢复已撤销实例。
