# 任务 35 验证记录：隐私安全加固

## 1. 结论

任务 35 已完成。远端事件、Agent Card、MCP 参数、IPC 帧和富文本都被当作不可信输入；大小限制与结构校验在协议边界和实际执行边界各做一次。浏览器只能显式读取远端正文，正文渲染器没有工具、发送器或交接网关依赖，因此提示注入即使被用户展开，也不能自动进入 Agent 上下文、读取交接目标、批准交接或发布消息。

本项没有把后续公开联邦、正式签名发行和账户删除文案冒充为已经完成。安全文档第 19 节中属于封闭测试的门禁已经通过；双 Homeserver 洪泛、发行签名和账户删除联邦残留分别留给任务 37–38、43 和 41/45。

## 2. 不可信输入边界

- IPC 采用共享长度常量，先限制帧长，再分配和反序列化；工具参数仍在 Bridge 执行前二次校验。
- MCP JSON Schema 声明字符串、数组、分页和进度范围，拒绝额外字段；随机 JSON 即使通过 Schema 解析，也必须通过 IPC 领域校验。
- Matrix 预览/修订事件和 A2A Agent Card 使用有界递归随机值做属性测试，任意输入只能规范化或被稳定拒绝，不能恐慌或泄漏内部错误。
- A2A HTTPS 客户端保留 HTTPS-only、禁重定向、固定已审计地址和私网拒绝策略，避免 Card URL 变成 SSRF 跳板。
- 控制平面继续使用 SameSite/HttpOnly 会话、同源检查、CSRF 门、请求体上限和分层限流；附件扫描失败时保持不可读。

## 3. 浏览器与桌面收敛

Tauri 与 Web 入口统一采用严格 CSP：脚本只允许同源和 WebAssembly 所需的 `wasm-unsafe-eval`，禁止通用 `unsafe-eval`、对象、框架、祖先嵌入和外部基址；样式属性的内联许可与脚本权限物理解耦。Web 额外设置权限策略、无嗅探、无来源和同源 opener，桌面能力清单继续拒绝通配符、文件系统、Shell 和进程环境权限。

验收过程中第一次真实浏览器运行暴露出 Vite 开发服务器依赖内联 React Refresh 脚本，与发布 CSP 冲突。修复不是放宽 CSP，而是让纵向验收先构建生产包，再用仅绑定 `127.0.0.1` 的严格端口预览服务运行。随后三设备真实 Synapse 验收通过。

## 4. 提示注入证明

固定夹具包含命令替换、脚本、图片、链接、表单、框架、伪造工具调用和“忽略先前指令”等攻击文本，并生成 256 行确定性变体。验证覆盖：

- 预览阶段不下载正文，也不申请正文票据。
- 用户显式打开后只生成受限 Markdown 节点，不产生脚本、图片、链接、表单或框架。
- 展开正文前后，交接目标读取、交接批准和消息发布计数均为零。
- 远端内容没有写入全局副作用，也没有 Agent 上下文交付入口。

## 5. 敏感输出扫描

`tools/sensitive_output.py` 对日志、指标、错误、审计和崩溃五类输出执行同一套检测，覆盖 JWT、Bearer、私钥、常见秘密赋值、URL 凭据和运行时金丝雀秘密。报告只记录通道和规则名，不复制命中的秘密原文。安全门禁生成的全部原始日志会在报告生成前反向扫描，任何命中都会使门禁失败。
