## 1. 架构边界

- `domain::agent_status` 只表达工作状态、可见性、脱敏详情、进度和租约有效性，不依赖 Matrix SDK、Bridge 进程、系统时钟实现或前端框架。
- `bridge-core::status` 把宿主意图编排为状态租约，只依赖时钟、实例签名器、标识工厂和状态发布器四个窄端口；Matrix SDK 通过既有 `MatrixGateway` 适配，不进入业务规则。
- `packages/protocol` 提供接收端离线派生纯函数。调用方以本地观测时间封顶发送端租期，不需要服务端清理事件，也不修改 Matrix 历史。
- 房间目标和可见性是显式输入，不由发布服务猜测。任务 16 负责产生真实大厅 Room Instance，任务 23 的宿主适配器负责提交状态意图；本任务没有用硬编码房间或假宿主状态污染组合根。

## 2. 协议与签名

- `org.agentroom.agent.status.v1` 使用 `state_key = agentInstanceId`，状态闭合为 `offline`、`idle`、`working`、`waiting_input`、`blocked` 和 `completed`。
- 粗粒度事件不得携带 `taskSummary`、`startedAt` 或 `progress`。详细模式才允许这些有界字段；任务摘要拒绝控制字符，进度在领域层以基点表达并严格限制到 0–100%。
- 签名输入移除顶层 `signature` 后按 RFC 8785/JCS 规范化为 UTF-8，再由实例 Ed25519 密钥签名；线上字段使用不带填充的 Base64URL 字符串。协议文档、JSON Schema、Rust 和 TypeScript 生成类型保持单一结构。
- 事件 ID 与关联 ID 强制 UUIDv7；身份展示名、Matrix User ID、事件大小和未知字段均在进入 Matrix 前校验。

## 3. 发布与续租语义

- 首次状态、工作状态变化和房间可见性变化立即发布；普通详情变化合并到下一次续租，避免进度更新形成状态事件风暴。
- 默认租期为 5 分钟，续租基线为 2 分钟并支持有界抖动。配置必须保证最晚续租时间早于租约到期。
- 每个房间维护独立发布游标。相同状态在续租时间前返回 `NotDue`；Matrix 明确失败时不推进游标，调用方可以安全重试。
- State Event 发送按 Matrix 的 `(room_id, event_type, state_key)` 当前状态语义工作。发送超时属于可安全重试的状态覆盖，不复用普通消息的未知提交语义。

## 4. 接收端离线判定

- 客户端根据 `leaseExpiresAt + allowedClockSkew` 本地派生离线；Bridge 崩溃、进程被杀或网络长期中断都不要求额外的离线写入。
- 接收端同时使用“本地观测时间 + 最大租期 + 容许偏差”封顶，拒绝恶意超长租约和超出容许范围的未来事件。
- 显式 `offline` 不会因为租约仍有效而被解释回在线。无效时间、策略和租期均返回闭合错误类型，不抛出未分类异常。

## 5. 验收结果

| 验收项 | 结果 |
| --- | --- |
| Bridge 崩溃 | 无后续事件时客户端在本地截止点准确转为离线 |
| 时钟偏差 | 有界偏差可接受，未来事件与超长租约明确拒绝 |
| 重复续租检查 | 到期前不发布，续租后游标推进且不形成风暴 |
| 状态变化 | 六种宿主状态完整映射，转换立即发布 |
| 可见性变化 | 粗/详细切换立即发布，粗粒度载荷无任务详情 |
| 发布失败 | Matrix 失败保留原游标，下一次调用仍执行首次发布 |
| 协议一致性 | 生成事件通过同一 JSON Schema；恶意粗粒度详情 Fixture 被双语言拒绝 |
| 真实 Synapse | 同一状态键连续发送两版后，另一会话增量同步得到最新版本 |
