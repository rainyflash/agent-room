# 任务 38 验证记录：联邦治理与兼容协商

## 1. 结论

任务 38 的领域策略、持久审计、接收入口和真实双服务兼容验收已经完成。联邦事件不会因为“来自 Matrix”就自动可信：每个入站事件先执行版本协商、分层治理、速率预算、重放检测和状态冲突检测，只有明确允许的当前协议事件才能进入可执行投影。

## 2. 兼容策略

- 当前主版本完整读写；前一主版本只读兼容。
- 未知版本和未知事件不解析正文，只投影最小元数据并标记为只读。
- 浏览器仅在用户主动展开时展示该元数据；只读联邦事件没有发送器、工具或 Agent 上下文入口。
- 事件命名空间已从占位符迁移为项目拥有的 `io.github.rainyflash.agentroom`，旧命名空间只保留前一版本读取路径。

真实联邦夹具额外证明：同一事务 ID 重放得到同一事件 ID；未来未知事件与旧命名空间事件都能跨服务抵达，但接收端投影模式为 `metadata_only_read_only`。

## 3. 治理与入口

领域层把对端、房间和用户规则视为独立可逆策略；命中多条规则时使用最严格结果。信誉只作为有界信号，不能越过显式阻止规则。入口为每个对端、房间和用户分别维护预算，并对状态键冲突进入隔离队列，而不是用后到事件覆盖可信状态。

迁移 `202608250006_federation_governance.sql` 提供：

- 联邦对端登记与协商版本；
- 对端、房间、用户三种粒度的允许/阻止规则；
- 规则反转与追加式管理员审计；
- 最小权限运行角色，应用不能篡改历史审计。

## 4. 恶意输入验证

自动测试覆盖事件洪泛、用户与房间热点、过期预算回收、同事务重放、旧版本、未来版本、未知事件、规则叠加、规则反转、信誉边界以及同一状态键的并发冲突。拒绝路径返回稳定机器码，不泄漏内部密钥、事件正文或数据库错误。
