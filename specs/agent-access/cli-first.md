# CLI 优先接入

## 目标

用户在房间复制邀请给能够执行本机命令的 Agent；无需配置 MCP、输入会话编号或重启宿主。CLI 与 MCP 继续共用 Bridge 的身份、权限、消息及持久化。MCP 保留为兼容入口；后台接待由应用准备独立 MCP 配置，不修改用户的宿主全局配置。

## 交付范围

- CLI 提供邀请接入、持久化人物上下文、恢复、显式确认消息进度及接待登记；旧命令保持兼容。
- 邀请不包含登录令牌或 Matrix 密钥。命令使用实际安装位置、正确的 shell 转义；失败返回可执行的提示。
- 人物按邀请/任务隔离，默认新建，恢复必须明确选择；不能跨任务默默接管身份。
- 桌面邀请默认 CLI，高级入口才展示 MCP；网页支持在桌面继续，并解释远程运行方式。
- 指定房间不可用必须明确失败，不偷偷换房间后宣称接入成功。
- 界面根据真实连接与取信证据显示状态；复制指令不等于 Agent 在线。
- 后台接待从 CLI 登记准确任务，界面提供回复授权与启动；不把结束任务显示成仍在监听。
- 安装程序、开发入口、文档和插件说明采用同一流程，并增加进程级与浏览器验收。

## 验证

CLI 参数与真实进程、身份持久化/损坏/并发/重启、消息游标与重试、错误与退出码、MCP 兼容、桌面/网页邀请交互、双语与布局，以及原生打包检查。实际安装环境验证采用同一版本 CLI 与 Bridge，不以模拟模型回复代替实际接入证据。

## 本轮验收（2026-09-13）

- 前端 133 个文件、600 项测试通过；邀请、接待、登录恢复及房间状态的 16 条浏览器流程通过，包含桌面与手机布局。
- Rust 原生组件测试、CLI 真实进程测试、消息进度并发回归、完整工作区 Clippy 检查通过。
- PostgreSQL 17 隔离实例中的 9 项房间分配与入口测试通过，覆盖目标房间校验和并发容量约束；未使用生产数据库。
- 同一源码构建的桌面、Bridge 和 CLI 在真实账户下完成邀请接入、任务登记、关闭后重启及恢复；人物身份保持一致，原生界面显示实际到达，登录保持有效。
- 真实桌面验收发现并修复了本机面板缺失会话上下文、诊断响应遗漏新增字段的问题；整页测试和 Rust/前端共用契约已加入打包门禁。
- 已有真实项目人物完成 CLI 取信、确认消息及恢复验证。后台授权、绑定、启动及失败恢复由应用层和浏览器回归覆盖；本轮没有触发真实模型的后台回复。

## 发布边界

此功能完成于源代码，尚未发布新版本。本轮运行的是嵌入正式前端资源的原生验收构建，没有制作或发布新安装包。指定房间入口需按完整版本发布：先部署兼容的新控制面，再发布桌面、CLI、MCP 和网页。旧控制面不支持新增字段，不能以当前线上环境的默认大厅接入验证代替指定房间的端到端部署验收。
