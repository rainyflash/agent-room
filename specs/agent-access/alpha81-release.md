# Alpha 81 发布记录

[Alpha 81](https://github.com/rainyflash/agent-room/releases/tag/v0.1.0-alpha.81) 于 `2026-10-24T09:22:41Z` 公开。

- 升级序号 `81`，源码 `7f41fe97bd8331ff3ca93a59999c633a2acef645`（[PR 578](https://github.com/rainyflash/agent-room/pull/578) 的合并提交）。
- 网页、服务器和维护者本机的 Windows 应用都已升级。服务器上装好了每小时一次的生产错误汇总。
- 本版在受保护的 `release/v0.1.0-alpha.81` 分支上以锁定模式公开，是正式版，标为 Latest。

全程由编码 Agent（Claude Code）操作，实机验收的真实宿主和上一版一样用 Codex。#574 改了 `infra/identity/` 的登录主题和 `infra/production/keycloak-registration-reconcile.py`（在 `release_acceptance.LOGIN_PATHS` 里），实机验收走了一次新设备授权，维护者 `09:12Z` 前后批准了设备码，码一次就批上了。维护者 10-24 说“等全部合并完就立即发”，本机随时可以升级，`owner-ready.txt` 派生时就写好了。

## 用户可见的变化

- 在网页上打开私人房间的地址（`/lobby/<房间号>`）直接进房间，不再回 500、显示“没能进入房间”（#570）。
- 上一次登录没走完就回来的，网页自动重新打开一次登录页，不再停在“这次登录没有完成”（#573）。
- 点了过期的邮件链接，身份服务的错误页说清楚怎么办，并给“回到 Agent Room”的按钮（#574）。
- 生产错误汇总发成私有仓库 `agent-room-ops` 里的 issue（#572、#575），见下面“发布后”。
- 依赖的安全升级：zod 4.6.7，undici、body-parser 经 overrides 抬到修复版，tokio 1.53.3，ctutils 0.4.5，chacha20 0.10.2；crypto-bigint 0.5.5（RUSTSEC-2026-0387）要等上游换新一代 p256，在 `deny.toml` 加了带理由的例外，跟踪 #577（#578）。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 没变（还是 `4.5`，Bridge 同时接受 `4.4`）。没有迁移，compose 没有新变量，Synapse 配置没动。

## 发布后

- 错误汇总的定时器从 `10:07Z` 起每小时跑一次，新问题开在 `agent-room-ops`，叫醒云端开发 Agent 的 routine 见 [docs/operations/error-triage.md](../../docs/operations/error-triage.md)。
- 发版慢的几处在改：
  - 每天查一次依赖的安全公告，改锁文件的 PR 上也查（#580），别等发布提交切好才撞上；
  - 发布链一看到 CI 或候选有作业失败就停，不等候选建完、资产下完；
  - 草稿资产由服务器去下、本机从服务器拷回，少走 GitHub 到本机这段慢路；
  - CI 拉镜像遇到 503 之类自动重试。
- 第一个发布提交的草稿 `v0.1.0-alpha.81-superseded-ec3a7a66` 留着，和以前让位的草稿一样，删不删等维护者。
- 维护者可以在设置里清掉以前的验收电脑（Alpha 74、77、78、79、80 那几台已经不用了）。
- `release/alpha76-version` 这个没用的分支还在，要维护者在 GitHub 上删。
