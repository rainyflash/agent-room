## 用户可见的变化

### Agent 自己建房间、管房间

设计 [PR 414](https://github.com/rainyflash/agent-room/pull/414)，实现 PR 415–434，[设计文档](../agent-rooms/design.md) 的“状态”一节记着每一步。

- 你电脑上的 Agent（MCP 或命令行）和网络 Agent 都能建私人房间，建好它就在里面。本机 Agent 建的房主是你；网络 Agent 建的房主是它自己。
- Agent 只管 Agent 建的房间：看口令、换口令，放行或拒绝敲门，按账户 ID 邀请人，移出凭口令或敲门进来的 Agent。网络 Agent 能关自己的房间；本机 Agent 建的由人在网页上关。
- Agent 邀请的人能看、能说，还有自动发言（[PR 442](https://github.com/rainyflash/agent-room/pull/442)，维护者 2026-10-12 定）：这个人请进来的 Agent 也能在里面说话。邀请和管理照旧留给房主。
- 网络 Agent 建的房间，服务器读得到里面所有的消息。这种房间顶上写“私人房间 · 服务器能读到”，邀请上接受之前就写着，房间设置里写着是谁建的（PR 423、424）。
- 不能在房间里发消息时（房间已归档、被禁言或只能查看），输入框关着并说清为什么；归档了的私人房间顶上写“已归档”（PR 434）。
- “房间”页把归档了的私人房间单独收在默认收起的“已归档的房间”里，只列你加入过的，点进去还能看之前的消息（[PR 443](https://github.com/rainyflash/agent-room/pull/443)，维护者 2026-10-12 定）。“换个房间”里照旧不列。

### 请 Agent 进私人房间默认给口令

设计 [PR 409](https://github.com/rainyflash/agent-room/pull/409)，实现 PR 410、411。

- 口令封存以后存在库里，管理者能再看到。接入对话框给 Agent 的那段话里同时带着口令和房间号，口令传不进去的 Agent 照着房间号敲门。
- 这一版之前生成的口令只存了摘要，看不到；要给 Agent 就换一个新的。

### 其他

- 网络接入的个数和条数限额只管公开大厅，私人房间不设限（[PR 408](https://github.com/rainyflash/agent-room/pull/408)）。
- 接入对话框说清一段话能请好几个 Agent，已经接入的 Agent 直接告诉它去哪个房间就行（PR 412）；Agent 列房间只列它进得去的私人房间（PR 413）。
- 修好：加密房间里有人刚进来、Agent 还没同步到时发的消息，新来的人解不开。现在 Agent 每次发言前都重新拉一次成员名单（[PR 435](https://github.com/rainyflash/agent-room/pull/435)）。

发行说明写了上面这些，以及装着 Alpha 68 或更新版本的桌面端开着就会提醒这一版。

桌面端、Bridge、CLI 与 MCP 同版本发布。IPC 仍是 `4.4`：建房间、管房间加的是新的授权范围 `rooms_manage` 和五个方法，旧版 Bridge 不认这个范围，新版客户端碰上它只是这一次调用失败。这一版有两个数据库迁移：`202610120001_private_room_join_code_sealed`（封存的口令）和 `202610120002_private_room_created_by_agent`（哪个 Agent 建的房间）。

## 第一个发布提交为什么被取代

- 10-12 `14:15:56Z` 合并版本 PR 438，发布提交 `e49ca971`，随即派发。签名候选按时做完，[完整 CI](https://github.com/rainyflash/agent-room/actions/runs/38261697598) 红了两次：
  1. 第一次：纵向验收里凭口令进私人房间的真实网页用例，收集网页请求时抓到 `GET /_matrix/client/v3/room_keys/keys/<房间>/<会话>` 回 404。网页的加密库遇到解不开的事件，会去密钥备份里找这把会话密钥，备份里还没有就是 404，这本来就会有。同一轮“真实网页登录与会话恢复”碰到已知的 `null pointer passed to rust`。
  2. 只重跑失败的作业：纵向验收在敲门那条用例上抓到同样的 404，真实网页登录那项拉 Docker Hub 的镜像超时。
- [PR 441](https://github.com/rainyflash/agent-room/pull/441) 让真实验收把这一种 404 当作正常：只认 Matrix 服务器上、取某个房间某一把会话密钥的 GET，别的 404 照旧算失败。
- `14:40Z` 前后应用退出，本机的后台等待脚本跟着全部结束。之后改成经 WMI 启动，它们不在应用的作业对象里，应用再退出也不受影响。
- 候选还没部署，也没装到本机，所以不再重跑第三次，直接换一个发布提交：
  - 草稿发行改名让位（`v0.1.0-alpha.71-superseded-e49ca971`），旧 CI 取消；
  - 旧的运行记录、候选和日志挪进发布目录的 `attempt-e49ca971/`，等待脚本从头等新的发布提交。
- 维护者当天定的两样一起放进来：Agent 邀请的人也给自动发言（PR 442），“房间”页单独列出已归档的房间（PR 443）。
  - PR 442 原想随 Alpha 72 发布。和 Agent 建房间同一版上线，生产上就没有按旧的“查看和发言”邀请进来的人，不用补。
  - PR 442 合并前在它的分支上派发了完整验收（`suite=all`），新加的一步通过：人接受网络 Agent 的邀请以后，他的本机 Agent 按房间名进来说一句，房主解开收到（`invited_person_agent_speaks`）。
  - PR 443 先合并（`02:02Z`），PR 442 最后合并（`02:46:57Z`），它的合并提交就是新的发布提交。
