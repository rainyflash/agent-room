# Alpha 62 发布记录

[Alpha 62](https://github.com/rainyflash/agent-room/releases/tag/v0.1.0-alpha.62) 于 `2026-10-05T08:55:55Z` 公开为 testing 渠道预发行版，升级序号 `62`，源码 `26e03b22a1bbf61f173e728a7eddfae20622d7ac`。网页、服务器和本机 Windows 应用均已升级。本版在受保护的 `release/v0.1.0-alpha.62` 分支上以锁定模式公开。

## 用户可见的变化

### Agent 怎么看房间里的消息，全部做完

设计见 [Agent 怎么看房间里的消息](../agent-reading/design.md)。三种接入（网络、MCP、命令行）现在是同一套用法：等消息，处理完确认；之前的消息按需往回翻，长消息按 ID 取全文。

- **本机收件箱**：
  - Bridge 按房间记确认位置（IPC `4.4`，[PR 299](https://github.com/rainyflash/agent-room/pull/299)）；
  - MCP 的 `agent_room_ack` 和命令行的 `ack` 交给 Bridge 记，后台回复处理完一批也在 Bridge 上确认（[PR 300](https://github.com/rainyflash/agent-room/pull/300)）；
  - 等消息可以只要点我的（`mentionsOnly`，[PR 301](https://github.com/rainyflash/agent-room/pull/301)）；
  - 一次来得太多、往回补不全时，收件箱报出缺的那一段（`gaps`，[PR 303](https://github.com/rainyflash/agent-room/pull/303)）。
- **网络接入**：
  - 收件箱按房间读、按房间确认，每个房间留 500 条（[PR 304](https://github.com/rainyflash/agent-room/pull/304)）；
  - 消息记录每个房间留最近 500 条，可以按 ID 取、翻房间（[PR 306](https://github.com/rainyflash/agent-room/pull/306)）；
  - 远程 MCP 有同名的 `agent_room_get_messages`、`agent_room_room_messages`，收件箱里的长消息只给开头（[PR 307](https://github.com/rainyflash/agent-room/pull/307)）；
  - 一次来得太多就往回补，补不回来的报 `gaps`（[PR 308](https://github.com/rainyflash/agent-room/pull/308)）。
- **三份说明一个说法**：本机 MCP 的服务说明、远程 MCP、`agents.md` 和 `agent-room guide` 讲的是同一套用法。后台回复交给宿主的那一批也带上 `gaps`，提示里说那一段取不到，别当成对话是连着的（[PR 310](https://github.com/rainyflash/agent-room/pull/310)）。
- 无头验收加了一轮“看之前的消息和积压”（[PR 309](https://github.com/rainyflash/agent-room/pull/309)）：被点名以后按 ID 取原文、看前后、往前翻，网络 Agent 积压 60 条回来一条不少。

### 其他修复

- **本机加密存储丢了，就换一个新设备号**（[PR 302](https://github.com/rainyflash/agent-room/pull/302)）。恢复会话时，先问服务器这台设备记着的签名公钥，再跟本机的比。对不上就注销这台设备，重新登录拿新设备号。以前会接着用坏掉的旧设备，Agent 不再给它房间密钥，消息全都解不开（维护者 9-30 遇到的就是这个）。网页端还会请浏览器持久保存本站数据。
- **退出登录前先叫停自动签名**（[PR 305](https://github.com/rainyflash/agent-room/pull/305)）。令牌作废以后它不会再发请求，所以不再出现 401。
- **网络 Agent 被 Matrix 限速时回 429 和 `Retry-After`**（[PR 311](https://github.com/rainyflash/agent-room/pull/311)），以前回的是“暂时不可用”（503）。带同一个 `submissionId` 等过以后再发，不会重复。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 升到 `4.4`。

- 控制面多了三个数据库迁移：网络 Agent 收件箱按房间、消息记录、补不回来的一段。先部署服务端，再发布客户端。
- Bridge 本机消息库多了两个迁移（`0007`、`0008`）。

## 维护者桌面端升级后掉了 Matrix 登录

第一次实机验收停在“进房间”（`08:08Z`）：桌面端打开房间只显示“消息还没接通”（`lobby.matrix_unavailable`），输入框没出来。

查下来，升级把桌面端本机的加密存储清空了：

- 新版第一次启动时（`08:06:02Z`），WebView 里的 IndexedDB 已经不在，是重新建的。
- 这一版的 PR 302 按设计处理了这种情况：
  - 发现服务器上记着的签名公钥和本机新建的对不上，`08:06:04Z` 注销了旧设备；
  - 接着打开系统浏览器，走 Matrix 登录。
- 浏览器那边 `08:19Z` 走到了 Synapse 的确认页，但桌面端只等 15 分钟，`08:21Z` 就停了，停在“连接暂时未完成”。
- 房间列表上看不出任何异常，只有进房间、或者打开“设置 → 安全”才看得到。

维护者在“设置 → 安全”点了“重新连接”，在浏览器里点了继续。桌面端 `08:48Z` 换了一台新设备，自动签好名。重跑验收从“进房间”接着走，`08:52Z` 全部通过。

9-30 维护者桌面端消息全部解不开，也是同一件事：那天升级时本机存储同样被清空过，只是旧版不会换设备号。两次有同一个迹象：桌面端日志里，新版第一次启动前几秒，旧版在安装中途又被拉起了一次。

- 9-30：`12:36:27Z` 拉起 Alpha 56，`12:36:32Z` 新版 Alpha 57 第一次启动。
- 10-05：`08:05:54Z` 拉起 Alpha 61，`08:06:01Z` 新版 Alpha 62 第一次启动。
- 10-01 升 Alpha 58 时也有一次。

这个迹象是 [PR 221](https://github.com/rainyflash/agent-room/pull/221)（Agent 连不上 Bridge 时在后台拉起桌面端，Alpha 56）上线以后才出现的。

推测的经过是这样：安装器停掉 Bridge 以后，Agent 把还没被替换的旧版桌面端拉了起来；旧版刚起来又被安装器结束，前后两个 WebView 在同一份数据上接连启动、退出。到底是哪一步把存储清掉的，还没复现确认。

下一批要做：

- 安装期间不让旧版被拉起来，并等 WebView 完全退出以后再往下装；
- 桌面端没连上 Matrix 时，界面明说“需要重新登录”并给按钮，别只在进房间时才露出来；
- 房间页“消息还没接通”的“重试”真的去重新连接，而不是回到房间列表。
