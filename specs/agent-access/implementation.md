# Agent 接入与持续接待

用户已确认按 MCP 接入引导、持续接待、CLI、云端运行方式的顺序完善。各入口共用现有 Bridge 的身份、授权、消息与持久化能力，不重新实现 Matrix 客户端。

本文保留首轮实现的设计与阶段记录；后续接待产品化、Claude Code、OAuth 和当前验收结果以[补齐与验收记录](completion.md)为准。

## 交付顺序

1. MCP 接入：配置结果有明确反馈；展示真实宿主会话及消息收发证据；提供可复制的接入指令与具体故障提示。配置写入不能显示为 Agent 已接入，界面查询不能伪造宿主收取消息。
2. 持续接待：提供可取消、可恢复的消息等待；宿主运行绑定使用明确标识，串行处理消息并保留游标。仅通过受支持的宿主接口启动或继续任务，不猜测最近任务，不读取宿主私有缓存。没有唤醒能力的入口明确说明限制。
3. CLI：提供诊断、会话、收信、发信、状态和监听命令，机器输出结构化 JSON，稳定错误码与退出码；复用 Bridge 的业务规则和身份。
4. 云端运行：提供无需桌面 UI 的认证和运行方式、明确受保护的远程接入边界、部署说明及端到端验收。不得将桌面 IPC 直接暴露到公网，不共享不同所有者的会话或密钥。

## 验收边界

- 单元测试验证业务状态与授权边界；传输测试使用真实进程或协议交换。
- 浏览器验收覆盖接入、等待、失败、消息证据与窄屏显示，使用仓库 Playwright；截图与调试构建产物不提交。
- 接入成功必须来自真实工具请求；接待能力不能由在线租约推断。
- 发布能力与本地实现分别报告。沿用用户授权自行提交代码；新入口先完成验证，不改动当前生产服务和已安装运行时来代替测试。

第一阶段：桌面增加只读任务诊断与接入指令、配置成功反馈。成功取信、取到消息、确认发信分开记录，未知提交不计成功；诊断不会刷新会话寿命。Rust 会话检查 13 项、权限检查 1 项、IPC 19 项，前端相关 29 项与 3 项浏览器检查通过，类型检查与 Rust Clippy 通过。浏览器使用隔离 fixture，在 1440px 和 390px 实测配置、复制与收发证据，截图存于仓库外并已查看；这不替代真实宿主的端到端验收。

第二、三阶段：新增正向 `ReadInbox`，空房间首次突发多页消息不会跳过前页；MCP `agent_room_wait_for_messages` 与 CLI 共用 `agent-client`。CLI 提供任务、状态、收信、发信、监听和明确绑定 Codex 任务的接收器。接收器仅处理指定人类在指定房间的直接提及，要求有效自主发言授权；持久化 pending 后才投递，同任务独占运行，不确定投递需核对后重试或跳过。接收器向 MCP 子进程显式传递云端 vault 路径，不依赖宿主默认环境继承。共享收信/状态测试 4 项、CLI 单元测试 6 项、真实 CLI 进程测试 3 项及正向分页存储测试通过；MCP 的 19 项工具与传输测试通过。

第四阶段：新增单所有者 Streamable HTTP MCP，校验独立 Bearer 令牌、Host、Origin、大小与并发限制；使用 SDK 协议，不暴露管理型 IPC。新增可选加密文件 vault，Bridge、MCP 与 CLI 共用，默认 OS 钥匙串保持原行为。HTTP 套接字验收 4 项（旧版初始化、新版无状态协议、会话工具与错误边界）、Windows vault 验收 3 项（重开、损坏、密钥与账户绑定）通过；真实 CLI 新进程验证加密 IPC 凭据读取与缺失配置拒绝。已提供独立 Compose、Containerfile、登录/密钥/令牌/备份/升级说明。

最终本机回归：Bridge 26 项库测试、64 项运行时测试和 1 项消息网关测试通过（OS/真实基础设施测试沿用忽略）；相关包及桌面 Clippy、前端 33 项测试、类型检查、ESLint、Web/PWA 构建、UI 文案、许可证检查通过。三项浏览器验收再次通过，已查看 1440px 与 390px 截图，位于仓库外 `agent-access-final/`。构建仍有既有 Matrix SDK 大分块提示。

首轮结束时尚缺 Linux 运行与 OAuth 验收；后续已增加 Linux CI、单所有者 OAuth、桌面接待管理与实际回复核对，最新证据及未完成的真实模型验收见[补齐与验收记录](completion.md)。这些变化尚未部署到生产，仍需成套发布后才能用于已安装 Alpha.26。
