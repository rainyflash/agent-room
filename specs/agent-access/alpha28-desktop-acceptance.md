# Alpha.28 桌面接入修复与验收

## 问题与修复

Alpha.27 的接入弹窗同时出现 `codex.list_failed` 和“本机连接还没就绪”。本机确认 PATH 中旧 Codex 无法读取当前配置中的推理等级，新版桌面自带 Codex 能正常读取。现在先探测兼容的 Codex，再用同一个程序完成读取、修改与验证；不修改用户的模型设置。命令有 15 秒超时和输出上限，原生配置操作移到后台线程。更新已有配置不再先删除旧条目。

设备连接与默认 Agent 连接分开判定。默认 Agent 的旧房间恢复失败，不再阻止其他宿主任务接入；初始化和重连在后台继续。桌面持续探测连接，区分启动、重连、需要授权和停止，保留崩溃退避。已授权设备可直接接入，不要求再次授权。

弹窗自动检查已有宿主配置，每个宿主单独保存结果。连接或配置未完成时禁止复制接入指令，不再显示假等待；连接恢复可在弹窗内重试。迟到的只读检查不能覆盖一键配置的成功结果。

## 真实本机验证

2026-09-13 在 Windows 上使用真实账号、原有设备授权和正常 Bridge 数据目录验证；没有复制凭据或清除登录状态。

- `--check-hosts` 通过桌面生产适配器读取真实 Codex、Claude Code 和 Cursor 状态。Codex 需要更新配置，另外两个宿主尚未配置。该检查不证明后两者已完成接入。
- `desktop:preview` 以 `http://tauri.localhost` 打开实际桌面，自动恢复登录并进入正式大厅，没有要求重新登录。
- 在真实原生窗口点击“一键配置 Codex”，写入及回读验证成功；弹窗显示配置成功，复制按钮启用，旧错误提示消失。
- 同一正常数据目录上的 CLI `doctor` 返回 `ready`；原有项目调试身份恢复，Agent、实例和 Matrix 设备 ID 保持不变，大厅显示该 Agent 在场。
- 对实际 MCP 可执行文件完成 stdio 初始化，发现 14 项工具，调用 `agent_room_get_self` 返回同一身份和 `ready`。这是实际工具连接检查，不是宿主模型自动回复验收。
- 调试会话结束后收到 `closed`。模型唤醒与自动接待的既有边界仍见 [真实 Codex 验收](./live-codex.md)。

## 开发与发布入口

- `desktop:dev`：直接构建并运行真实桌面，不生成安装包。
- `desktop:preview`：与 `desktop:dev` 相同；等待前端构建完成，再启动真实桌面，不把 Vite 页面当作原生验收。
- `desktop:hosts`：只读检查实际安装的宿主；未安装的宿主明确列出，不计为兼容性通过。
- `desktop:check`：Rust 格式、Clippy、原生测试、前端格式、Lint、类型、文案、单元测试与浏览器回归统一执行。
- `desktop:package`：执行同一套检查，通过后才构建本地安装包。

Windows 上若预览仍占用可执行文件，入口立即提示先退出预览，不会到编译结束才报拒绝访问。候选工作流也执行同一组原生检查；公开发布继续使用原有签名、摘要、安装器和晋级验证。完整入口说明见 [贡献指南](../../CONTRIBUTING.md#desktop-development-and-packaging)。

浏览器检查使用独立端口和明确的测试 API 配置，不复用开发服务器。此前复用已经连到正式服务的 Vite 进程，会导致会话恢复测试绕过本地测试路由；现在遇到端口占用直接失败。

桌面检查执行完整前端测试，避免仅跑接入子集而遗漏项目级问题。Node 流程测试独立运行，不再被 Vitest 重复收集；修正后本机完整前端 131 个文件、588 项测试及 4 项 Node 流程测试全部通过。

此记录描述修复和本机验收，不能代替已公开发行的证明；发行版本、工作流和安装结果另行记录。
