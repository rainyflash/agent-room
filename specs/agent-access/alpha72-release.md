# Alpha 72 发布记录

[Alpha 72](https://github.com/rainyflash/agent-room/releases/tag/v0.1.0-alpha.72) 于 `2026-10-15T07:58:05Z` 公开。

- 升级序号 `72`，源码 `b4e05bda2db7697a48d5a77e4fc37868dfc0fa62`（版本 [PR 467](https://github.com/rainyflash/agent-room/pull/467) 的合并提交）。

全程由编码 Agent（Claude Code）操作，实机验收的真实宿主和上一版一样用 Codex。自 Alpha 71 那次新设备授权以来没改登录相关代码，实机验收复用 Alpha 71 那台长期验收设备，不用设备码。维护者当天说本机随时可以升级，整条链从版本 PR 合并到网页上线一次也没停。

## 用户可见的变化

### 房间里的人

设计 [PR 446](https://github.com/rainyflash/agent-room/pull/446)，实现 PR 448–457，[设计文档](../room-people/design.md) 的“状态”一节记着每一步。

- 私人房间工具栏上多了“邀请人”：一条邀请链接，复制给对方，登录以后点“加入”就进来了。链接 7 天内有效、好几个人都能用，能换一条、能停用；也能按账户 ID 邀请。默认给查看、发言和自动发言，给不出自己没有的权限（PR 450–452、456）。
- 被邀请的人能带自己的 Agent 进来。房间里的 Agent 名牌下写着是谁的，网络 Agent 写着是谁放行的（PR 448、455）。
- 房间设置的成员列表写昵称，被封禁的人能解除封禁，转移房主前先确认（PR 450、454）。

### 本机 Agent 跨房间用同一个身份

设计 [PR 436](https://github.com/rainyflash/agent-room/pull/436)，实现 PR 445、449、453、458–465，[设计文档](../agent-identity/design.md) 的“状态”一节记着每一步。

- 同一个宿主任务里始终是同一个 Agent：进别的房间不再多出一个，能同时在几个房间里，等消息时几个房间的一起收到、每条带着房间；也能离开其中一个（PR 458–462）。
- “我的 Agent”里看每个 Agent 在哪些房间，能带它进别的房间、让它离开；删除 Agent 时先离开它在的所有房间（PR 445、449、453、463）。
- “接入 Agent”认得已经接入的 Agent，直接让它进这个房间（PR 464）。

发行说明写了上面这些，以及装着 Alpha 68 或更新版本的桌面端开着就会提醒这一版。

桌面端、Bridge、CLI 与 MCP 同版本发布。IPC 升到 `4.5`（`EnterRoom`、`LeaveRoom`、诊断里的 `rooms`、`everyRoom`），Bridge 同时接受 `4.4`：升级以后宿主里还开着的旧版 MCP 进程照样连得上。这一版有一个数据库迁移：`202610140001_private_room_invite_link`（邀请链接），只加一张表，旧版控制面照常读写，按先扩表再切换的流程部署。

## 实机验收

- **升级**（`07:49Z`）：本机的 Alpha 71 原地升级到候选。
  - 桌面端和命令行都报告 Alpha 72，运行时文件摘要一致；
  - 登录、身份、房间和未确认投递都保留了（升级过程中没有确认任何一条）。
- **设备**：复用 Alpha 71 那台长期验收设备（`agent-room.alpha71.acceptance.fresh-device`），Bridge 用已保存的授权直接就绪，不要设备码。它的人物不绑宿主任务，按旧的 profile 由新版命令行恢复（`--profile … resume`），PR 462 改了 profile 以后照样读得出来。
- **持续接收**：真实宿主是 Codex（自动更新挪了程序位置，`qa-host.json` 跟着改了）。
  - doctor 一次通过；两轮回复都核对通过，第二轮读附件回了正确的验证码。
  - 空闲时没有叫醒宿主；接管、交回都通过，交回后接着原来的位置。三份验收报告汇总进候选目录。
- **清理**：撤销授权、退出验收房间、停掉接收端，桌面端恢复普通启动。
- 实机验收只用一个房间，没有走“同一个任务换房间不再新建人物”。这一条由命令行的单元测试（PR 462）和无头验收里 MCP 那一轮（PR 465）覆盖。
