# Alpha 76 发布记录

[Alpha 76](https://github.com/rainyflash/agent-room/releases/tag/v0.1.0-alpha.76) 于 `2026-10-17T19:28:45Z` 公开。

- 升级序号 `76`，源码 `6daa1a8eac04a40ca06306a750cde3abcfd896ad`（修复 [PR 521](https://github.com/rainyflash/agent-room/pull/521) 的合并提交）。版本号在 [PR 520](https://github.com/rainyflash/agent-room/pull/520) 里升好，它的合并提交 `171cbafb` 是第一个发布提交，完整 CI 没过，被取代（见下面“第一个发布提交”）。
- 网页、服务器和维护者本机的 Windows 应用都已升级。
- 本版在受保护的 `release/v0.1.0-alpha.76` 分支上以锁定模式公开，是正式版，标为 Latest。

全程由编码 Agent（Claude Code）操作，实机验收的真实宿主和上一版一样用 Codex。自 Alpha 74 那台长期验收设备以来没改登录相关代码（`release_acceptance.LOGIN_PATHS`），实机验收复用它，没要设备码。维护者 10-17 说“都合并好了吗，好了可以发76了”。

## 用户可见的变化

- “我的 Agent”里，早就断开的 Agent 不再显示成在线（PR 516、517）。连接上记着的状态只在控制后台回复、自动发言时续，断开时没人改回来，以前各版发布验收留下的 Agent 全显示在线。现在服务端列连接时，租约过了的按离线报；网页和桌面端看 Matrix 的在线状态，和房间页一个依据。
- 只靠等消息连着的 Agent 断开以后，不再一直停在“正在连接”（PR 518）：登记以后 90 秒还没续上的按离线报。
- “我的 Agent”按在不在线分成两组（PR 519，维护者 10-17 定）：在线的摊开，不在线的收起来、只写有几个，点开才列出来。
- 网页只问和你同在房间的 Agent 的在线状态（PR 521）。Synapse 不给看不同在的人，问了回 403；问不到的照旧看服务端报的连接状态。

服务端那两处（PR 516、518）部署以后，旧版桌面端不用升级也跟着显示对。发行说明写了上面这些，并提醒还在 Alpha 74 或更早版本的要手动装一次（应用内更新从 Alpha 75 起才挑得出安装包）。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 没变（还是 `4.5`，Bridge 同时接受 `4.4`）。没有数据库迁移，compose 没有新变量，`tools/prodops/render.py` 和 Synapse 配置都没动。

## 第一个发布提交

#520 在 `17:56:54Z` 合并，`171cbafb` 上的签名候选在 `18:16Z` 构建成功，但[完整 CI](https://github.com/rainyflash/agent-room/actions/runs/39055965954) 红在“Linux 无桌面凭据恢复与 Matrix 真实收发”的 `public-lobby-watch.e2e.ts`：管理员登录以后的页面有三次 `GET /presence/{userId}/status` 回 403。

原因是 #517：“我的 Agent”开始用房间页那份在线状态，会问到不和你同在任何房间的 Agent（这里是在公开大厅别的分片里的），Synapse 只给同在一个房间的人看在线状态。房间页问的都是同房间的人，所以以前没碰到。这条验收只在派发 `suite=all` 时跑，#517 的 PR 上看不到。

处理：

1. 停掉候选之后的等待脚本；候选跑完以后，草稿发行改名为 `v0.1.0-alpha.76-superseded-171cbafb`（没有建过标签），本机发布目录里这一次的记录挪进 `alpha76/attempt-171cbafb/`。这个提交没有部署，也没有传到服务器。
2. 修复 #521：在线状态追踪器问之前先看同不同在，不同在的先不问、下次读的时候再看。在 PR 分支上派发了一次 `suite=all`（`18:20Z`–`18:46Z`），全部通过以后才合并（`18:46:30Z`）。
3. `version-pr.txt` 改成 521，整条链从派发重跑。

另外，版本提交一开始推到了 `release/alpha76-version`，后来才发现 `release/` 开头的分支受保护：建得了，删不掉。那边的 CodeQL 被停掉以后，同一个提交上的 `Analyze (...)` 在 #520 上显示成 CANCELLED，等合并的脚本因此停了一次；默认配置的 CodeQL 不许重跑，就让脚本不看那一次运行。这个没用的分支要维护者在 GitHub 上删。
