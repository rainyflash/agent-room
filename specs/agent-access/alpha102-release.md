## 用户可见的变化

- 在子房间里点“接入 Agent → 网络”，以前要子房间的口令，可子房间没有口令，点了只报错。现在照父房间的设置先请 Agent 进父房间，再拿子房间号进这一间；要批准的子房间叫它敲门，管得了的人在对话框里放行。命令行和 MCP 给 Agent 的话里写“父房间名/子房间名”（#975）。
- 登录页偶尔要等十几秒才出来：身份服务用不着的内存被挤进了交换分区，读回来时卡住。现在它的堆定死在 512 MB、不许用交换分区（#981）。
- 只凭网络接入的 Agent 发来的请求不对时，回答说清是哪一样（没带 `Content-Type`、不是 JSON、缺了哪个字段），确认用错了 ID 时说要 `$` 开头的 `eventId`，确认没成时提醒它每次等消息都会交回同一批（#980）。
- Windows 上后台回复不再因为 Agent 回的话里带着回车就整条作废、那一批没人回（#986，见下一节）。
- 后台回复的自检（`agent-room receiver doctor`）说清它要读的是接收端写好的已校验文件，读不到时带上 Agent 回了什么（#966）。
- 安全更新：ruma 校验 Matrix 标识符时两处会让 Agent 崩掉的漏洞，升级 `url` 和 `cookie`（#971）。
- 发行说明照旧提醒还在用 Alpha 74 或更早版本的人手动下载安装一次。

用户看不到的：

- Agent 口令请求失败带上落在哪一步（#978）；聊天服务器和控制面的容器日志多留几天（#979）；远程 MCP 等消息不算进 API 延迟、备份指标真的收进来（#972）；设备证明没通过时日志写明是哪一处（#973）。
- 错误汇总的几条噪音规则（#967、#974、#976、#977、#984、#985）；报 IndexNow 之前先等网站换成这一版（#969）。
- 删掉不再用的邮件提醒开关表（#982），连同为演练留的 `/messages → 403` 噪音规则。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 和本机 MCP 的工具都没变，桌面端没加原生命令。部署配置没加新变量。

带一个迁移 `202611260001_drop_account_reminder.sql`（删前生产上 0 行）：回滚只能退到 Alpha 100，Alpha 99 及更早的控制面还读写这张表。

## 第一个发布提交为什么让位

`cc6fdc7c` 的 CI、候选都一次过。维护者 `03:37Z` 说“候选好了就升，我在电脑前”，服务端 `04:05Z` 部署好，本机升到 Alpha 102。第一个设备码 `04:06Z` 发出，没人看到就过期了；重发的 `04:24Z` 批准。之后实机验收两次停在 doctor（后台回复的契约检查）：

1. `04:25Z`，`receiver.attachment_unreadable`：宿主是 Alpha 101 第二个发布提交建的那个 Codex 任务（`01a1fec4…`），回的是“无法确认该路径是 Agent Room 为当前会话验证的附件，因此未读取该文件。请将文件作为房间消息的附件发送。”和 Alpha 101 一样：这个任务上一版在房间里读过附件，之后就不肯直接读验证码文件；#966 改过的提示也没管用。
2. 照 Alpha 101 的办法换了一个干净的 Codex 任务（`01a2161b…`），等验收人物的旧会话闲满 15 分钟，`04:43Z` 再跑：这次它读到了，可回的正文是 `agent-room-contract-…\r\n`。它用 PowerShell 读文件，照抄了输出里的 CRLF；消息正文不收回车（`validate_chat`），接收端报 `receiver.host_reply_invalid`，整条作废。验证码文件本身不带换行，回车是宿主加的。

第二条在真实的后台回复里一样：宿主照抄命令输出、带上回车，那一批就没人回了。这个毛病不是这一版引进的，可它正是验收要挡的东西，所以先修再发（同 Alpha 49 的 #149）。#986 让 `HostReply::parse` 先把 CRLF 和单独的回车换成换行，`05:11:24Z` 合并，它的合并提交成为新的发布提交。新发布提交的 doctor，宿主回的正文照样带着 `\r\n`，这次过了。

让位的做法照 Alpha 101：

- 验收 `cleanup`：doctor 没过，`revoke-grant.js` 还没写，照 `release_qa.revoke_grant_js` 手写了再跑。
- 第一轮新授权的验收设备用的是同一个凭据命名空间，`retire_device_credentials` 清掉了它的 8 条凭据，`start` 才会再发设备码（Alpha 84 碰上过）。
- 草稿改名为 `v0.1.0-alpha.102-superseded-cc6fdc7c`（没有建过标签）；新版本公开以后删掉了。
- 本机这一次的记录挪进 `alpha102/attempt-cc6fdc7c/`，服务器上的发布目录改名为 `alpha102-attempt-cc6fdc7c`。
- 升级前的两项检查改成接受生产上已经是 Alpha 102，发完改回了原来的写法。
- 新的候选 `05:54Z` 核验完，升级前基线停在“本机已经是候选版本”，预料中的。问过维护者今晚还是明天，他说现在做，`06:02Z` 用核验过的 Alpha 101 安装器装回 101，核对了版本和三个运行时文件的摘要，从基线那一步接着跑。
