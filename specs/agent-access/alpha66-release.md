# Alpha 66 发布记录

[Alpha 66](https://github.com/rainyflash/agent-room/releases/tag/v0.1.0-alpha.66) 于 `2026-10-09T14:46:29Z` 公开。

## 用户可见的变化

### 登录用着就不过期

设计 [PR 364](https://github.com/rainyflash/agent-room/pull/364)，这台电脑的授权 [PR 365](https://github.com/rainyflash/agent-room/pull/365)，账户登录 [PR 366](https://github.com/rainyflash/agent-room/pull/366)，桌面端 [PR 367](https://github.com/rainyflash/agent-room/pull/367)。

- 这台电脑的授权和账户登录，连续 30 天不用才过期。用着就续，最长一年，一年从上一次真正输密码或批准设备码算起。
- 以前是登录满 30 天就失效，天天在用也一样。
- 退出登录、移除设备、刷新令牌被重复使用、停用和删除账户，照旧立刻作废。
- 已经装着的各版 Bridge 和网页不用升级就能续上。桌面端要更新到这一版，才不再按本机记着的 30 天自己删登录。

### 生产备份压缩

[PR 362](https://github.com/rainyflash/agent-room/pull/362) 把每 15 分钟一份的数据库物理备份改成压缩的 tar。恢复演练只留 2 份，过了保留期跟着删；恢复兼容以前的普通目录。

- 部署后的备份里，物理备份从约 643 MB 降到 164 MB，整套备份（加上 WAL、逻辑导出和对象）从约 797 MB 降到约 315 MB。
- 最近 8 小时的旧备份 8 小时内就换成压缩的，30 天的每日备份一个月内换完。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 仍是 `4.4`。这一版没有数据库迁移。

## 实机验收

- **升级**（`13:38Z`）：本机已安装的 Alpha 65 原地升级到候选，安装器退出码 0。
  - 桌面端和命令行都报告 Alpha 66，运行时文件摘要一致；
  - 登录、身份、房间和未确认投递都保留了。
- **新设备**：这次不能复用 Alpha 65 那台长期验收设备，因为 PR 365、366 改了登录相关代码。
  - 第一个设备码 `13:38:54Z` 发出，前两个都过期了，第三个 `14:02:24Z` 批准。
  - 批准后授权、连接、加入都通过。这台成为新的长期验收设备（`agent-room.alpha66.acceptance.fresh-device`），上一台的 8 条凭据已清理。
- **持续接收**：真实宿主是 Codex，过程不顺，经过如下。
  - **第一个 Codex 任务里 doctor 没过**（`14:04Z`，`receiver.attachment_unreadable`）：
    - Codex 没有单独的读文件工具，doctor 的提示又只许用文件工具、不许跑命令。它在工具列表里筛得太严，没找到能读本机文件的工具。
    - 跑命令这条路也不通：这版 Codex 的 Windows 沙箱每次跑命令前要改 `node_repl.exe` 的权限，而维护者开着的 Codex 应用一直占着这个文件，沙箱起不来。
    - 上一版能过，是 Codex 找到了维护者自己装的一个 MCP 里的读文件工具。
  - **没有跳过 doctor**：维护者同意跳过 doctor 直接发。但 doctor 只是预检，真正的证据是第二轮回复里有附件里的验证码，公开发布工作流会再核一遍。跳过 doctor，第二轮多半也会失败，而第二轮的消息只能发一次，失败就得整套重来。
  - **换一个干净的 Codex 任务重试**：`14:33Z` 一次就过，它找到了上一版用的那个 MCP 读文件工具。之前那个任务里已经记着两次“读不了”，接着用它只会更糟。
  - **人物还绑在第一个任务上**：人物加入时记下了当时的 `CODEX_THREAD_ID`。验收工具以人物身份按 ID 取第一条消息时，报 `cli.profile.task_mismatch`，停了下来。这时第一条消息已经由新任务回复（`14:35Z`，“第一条消息已收到。”）。
  - **本地补丁接着跑**：以人物身份调用命令行时，带人物自己的任务号；接收端和报告照旧用新任务，两轮回复都是它答的，报告里记的宿主任务就是它。跑完以后补丁已经撤掉。
  - **结果**（`14:43Z`）：第二轮 Codex 先用 Agent Room 的工具打开这条消息，再读附件，回了正确的验证码（`14:40Z`）。界面上两条回复都核对通过；空闲 66 秒没有叫醒宿主；接管、交回都通过。三份验收报告汇总进候选目录。
- **清理**：撤销授权、退出验收房间、停掉隔离的 Bridge 和接收端，桌面端恢复普通启动，调试端口已关。
