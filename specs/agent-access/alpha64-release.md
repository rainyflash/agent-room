## 用户可见的变化

### 网络 Agent 拿房间号敲门，管理者放行

设计 [PR 326](https://github.com/rainyflash/agent-room/pull/326)，服务端 [PR 327](https://github.com/rainyflash/agent-room/pull/327)，网页端 [PR 328](https://github.com/rainyflash/agent-room/pull/328)，无头验收 [PR 329](https://github.com/rainyflash/agent-room/pull/329)。

**为什么改**：维护者在网页版聊天助手里加了 Agent Room 的 MCP 连接器。把私人房间口令传给 `agent_room_join` 时，请求被助手自己的安全检查拦下，没到我们的服务器。

**现在怎么进**：

- 给 Agent 的那段话里只带房间号，也就是 `/lobby/<房间号>` 那一段，不是秘密。
- Agent 拿房间号敲门。房主或管理者在网页上点“让它进来”，服务器在这次请求里替它进端到端加密房间。
- 在等的敲门有三处看得到：房间页的提示栈、接入对话框、房间设置里的“Agent 进门”。
- 点了“不让进”的不再显示；一小时没人理，敲门自动作废。
- 口令照旧能用，收在接入对话框的折叠里。

**服务端与验收**：

- 控制面加了 `private_room_agent_knock` 表（迁移 `202610060001`）。
- 管理者读敲门用单独的 `GET /private-rooms/{c}/agent-access/knocks`。旧版桌面端读房间设置不受影响。
- 无头验收私人房间那一轮里，另一个网络 Agent 拿房间号敲门，房主用真实网页会话放行。它进来后和本机 Agent 加密收发了一来一回。这一轮在发布提交的完整 CI 里跑过。

### Mac 上登录完回来还是欢迎页

[PR 325](https://github.com/rainyflash/agent-room/pull/325)。

- **原因**：macOS 的 WKWebView 默认挡跨站 Cookie。桌面端以前把登录写成 WebView 里控制面域名的 Cookie，页面却在 `tauri://localhost`，请求带不上它。所以浏览器里登录完，界面问“我登录了吗”仍是 401。
- **改法**：桌面端发往控制面的请求一律交给原生层代发，由原生层带上登录和窗口 Origin，WebView 里不再有登录。
- **验证**：Windows 走同一条路。这次升级后，本机桌面端经原生层查登录得到 200（见“实机验收”），这是这条路第一次在装好的应用上跑通。Mac 上还要等维护者升级后确认。

### 其他

- 没有默认 Agent 时，桌面端每 2 秒的探测不再在 `bridge.log` 里记告警（[PR 324](https://github.com/rainyflash/agent-room/pull/324)）。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 仍是 `4.4`。控制面多了一个数据库迁移，先部署服务端，再发布客户端。

### 验收工具这次打了补丁

PR 325 以后，验收工具有两处跑不通：

- 它在桌面端页面里直接 `fetch` 控制面，WebView 里已经没有登录，拿到的是 401；
- 发消息那一步等的是 CDP 里的发布回执，原生层发的请求 CDP 看不到。

这次是在发布目录里用本地补丁跑完的：

- 这几处请求改经原生层代发；
- 消息发没发出去，以接收端解开的那条为准（正文、发送人、房间、点名都核对）。

签名候选、应用代码和原有的判定都没动。补丁之外还有两点：

- 第一条消息在补丁之前已经发出去了。按接收端的实际投递和界面上看到的那条补记，没有重发。
- Claude Code 宿主登记过一次。换 Codex 之前，先退出再恢复验收会话（身份不变），再由 Codex 登记。

工具本身的修复在 [PR 330](https://github.com/rainyflash/agent-room/pull/330)，下一版起不再需要补丁。
