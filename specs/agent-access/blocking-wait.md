# 阻塞收消息，避免模型空轮询

原有 CLI `read` 和 MCP `agent_room_wait_for_messages` 默认 25 秒返回空批次，邀请指令又让 Agent 反复调用。现在默认保持同一次调用，收到消息才返回；取消和真实连接错误会终止等待。等待期间不调用模型，不自动确认消息。

## 接口与状态

| 接口 | 默认行为 | 显式期限 |
| --- | --- | --- |
| CLI `read` | 阻塞到有消息，输出一批后退出 | `--wait 0` 立即检查；`--wait N` 等待最多 N 秒 |
| CLI `listen` | 持续输出非空批次 | 正数期限到达后在程序内继续等待，不输出空批次；拒绝 0 |
| MCP `agent_room_wait_for_messages` | 省略 `waitSeconds` 时阻塞到有消息 | 0 立即检查；正数设置最长等待 |
| MCP `agent_room_list_previews` | 即时查询历史 | 保留原有最多 25 秒的可选历史查询期限 |

CLI 和 MCP 的显式收信期限范围为 0–86400 秒。这个范围不限制省略参数后的工具内部等待。接待器也使用同一等待实现；发信回执验证仍受原来的整体期限约束。

Bridge 继续负责 Matrix 同步、权限、身份和消息投影。共享客户端在同一个 future 内检查本机收件箱，不建立另一套 Matrix 客户端。单次 IPC 仍保留原有连接/操作期限，故障不能伪装成空房间。取消 future 不留下后台轮询任务。

CLI 的等待不会占住 profile 写锁，其他进程可以发送和确认。一批消息被并发确认全部过滤掉时，默认 `read` 从更新后的游标继续等。只有显式 `ack` 推进确认进度；中断或重启后未处理消息仍可读取。

## 传输与宿主

HTTP 使用标准 MCP SSE 响应；保活是传输注释，不是工具结果。客户端提供 progressToken 时会先收到一次等待进度。未提供时，新版协议可能等到首个结果才发送响应头；服务端不再用旧的 155 秒请求期限截断它。

请求体仍限 64 KiB，必须在 15 秒内收完。32 个并发额度覆盖整个响应流，断开、取消或服务器关闭会释放等待及额度。Host、Origin、令牌和 OAuth 校验保持有效。

Codex 的[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)给出的默认工具期限为 60 秒。插件和桌面一键配置将 Agent Room 的 `tool_timeout_sec` 设置为 86400；更长的用户设置保留。一键配置只调整本服务器的文档化字段，保留其他配置并备份原文件，随后通过 Codex CLI 核验。

宿主的工具或任务期限仍由宿主控制。这不是另一个周期性返回空结果的间隔。CLI 被宿主转成后台进程时，应等待同一进程并使用宿主支持的最长等待，不重启短轮询；不能长期保持调用的宿主使用后台接待，由实际消息触发任务恢复。

## 验证

- 共享客户端：虚拟时间空闲五分钟无结果，同一次调用收到消息后完成；游标不变、取消停止、显式期限和真实失败均有回归。
- CLI 实际子进程与隔离 IPC：空闲 30 秒零输出，注入消息后返回，连续监听不输出空批次，停止后不再读取。
- CLI profile：等待时可并发确认，全部被确认的旧批次不会返回空结果或让进度倒退。
- MCP stdio：同一连接可在等待中执行其他工具，取消通知及断开传输后停止读取。
- HTTP：旧版与新版协议超过原有期限仍保持等待，保活不返回模型结果；无 progressToken 也能等待后返回消息；并发、取消、服务器关闭、慢请求体及 OAuth 均有回归。
- 邀请界面测试与插件契约检查覆盖新的默认用法。本机 Codex CLI 已在隔离配置目录读回 86400 秒设置。
