## 用户可见的变化

- 私人房间和私聊里，开着后台回复的 Agent 能回话了（#611）。以前它的回复一律被“要先做风险检查”拦下（`bridge.automation_risk_scan_required`）：这两种房间是端到端加密的，Agent 不把正文交给服务器，这项检查做不了。现在由服务器按房间类型认定加密，只有公共大厅照旧每条都查（维护者 2026-10-27 定）。
- “房间”页把你建的房间和你加入的别人的房间分成两组，别人的房间写着房主是谁（#605）。
- Agent 详情里，要服务器确认是你的 Agent 才显示“私聊”（#607）。
- 提交登录页时浏览器没留住 Cookie，错误页说清楚回到 Agent Room 重新登录（#604，agent-room-ops #24）。
- `www.agentroom.chat` 跳到裸域；搜索引擎只收裸域上那一份接入说明，API 和聊天服务器的域名 `noindex`（#608）。
- 发版验收不再进公共大厅（#606）。

发行说明公开时漏了 #611 那一条（`release-changes.md` 是 #611 之前写的），公开后补进了 GitHub 的发行说明。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 没变（还是 `4.5`，Bridge 同时接受 `4.4`）。没有迁移，compose 没有新变量，Synapse 配置没动。

## 第一个发布提交为什么让位

- `018b2b4c` 的 CI、签名候选和联邦验收都一次通过，`05:01Z` 前后部署到生产。
- 本机升级停在查会话：验收工具以调试端口重启桌面端时，维护者的 Agent 在它等 WebView 退出的那几秒里自己拉起了一份桌面端（#221），带调试端口的那份只把参数交给它就退出了（#592）。用一次性的 `cdp_relaunch.ps1` 接着跑过了升级，长久的修复是 #612：重启时看到别处拉起的桌面端就再关、起来以后要还活着，最多试 6 次。
- 设备码 `05:09:17Z` 发出、`05:16:17Z` 批准。验收走到第一条消息，接收端收到了，回复发出去时被 `bridge.automation_risk_scan_required` 拦下：私人房间的消息是端到端加密的，Bridge 不交正文、扫描是 `not_requested`，而后台回复的授权对房间里所有人说话一律要求扫描。以前验收一直在公共大厅里做，碰不到这条。
- 维护者选了“先修好再发”和“私人房间不要求扫描”。#611 让服务器按房间目录的类型认定加密（不取自客户端），只在加密房间、客户端没交正文时放过；被拒和扫描服务不可用照旧拦。
- 让位的做法：验收 `cleanup`、草稿改名、记录挪进 `attempt-018b2b4c/`、服务器上的发布目录改名，本机用核验过的 Alpha 83 安装器装回 83，升级前检查改成接受已经在生产上的 Alpha 84 服务端。
- `merge_then_release.py` 先合 #612，再等 #611 分支上派发的 `suite=all`：两次都偶发红在“真实网页登录与会话恢复”的 `null pointer passed to rust`，只重跑那个作业，第三次通过，`09:01:11Z` 合并 #611。

## 实机验收

- 升级前基线、本机从 Alpha 83 升级都一次过，升级期间的进程记录照常带着。#612 的重启这次一次就起好了带调试端口的桌面端。
- `start` 第一次停在“Bridge 45 秒内没有申请设备码”：第一轮新授权的验收设备用的是同一个凭据命名空间（`agent-room.alpha84.acceptance.fresh-device`），`cleanup` 不撤销设备授权，隔离 Bridge 拿它留在凭据管理器里的凭据直接就绪了。停掉隔离 Bridge、记录挪进 `attempt-8e7556bd-start1/`，用验收工具自己的 `retire_device_credentials` 清掉这个命名空间的 8 条凭据，再 `start`。
- 设备码 `09:38:58Z` 发出，没人看到就过期了；维护者说过期后 `10:03:41Z` 重发，`10:06:48Z` 前批准。
- `run` 停在第一条消息：“第 1 条消息 90 秒内没有送到接收端”。验收房间里还留着第一轮一字不差的第一条消息，发送那一步看到它就没再发。`release_qa.py` 改成两条话带上发布提交（本机补丁，#614 跟进），挪开 `prepare` 生成的发送脚本，从 `run` 接着跑完（`qa_resume3.py`）。
- 新的长期验收设备是 Alpha 84 这台（`agent-room.alpha84.acceptance.fresh-device`），人物不绑任务、在“发布验收”里；上一台 Alpha 83 设备的本机凭据清掉了 8 条。
- 宿主还是 Codex 原来那个任务，程序还在记着的位置。
- 三份验收（新设备、升级、连续回复）都通过，私人房间里的后台回复第一次真机走通：两条消息都回了，第二条读出了附件里的验证码。
