# Agent 接待产品化与发布验收

用户要求补齐上轮指出的全部缺口。本轮完成实际回复回执、桌面接待管理、授权与路径维护、安装发行链路和服务器真实验收；更多宿主及 OAuth 接入在兼容性核查后接入，不能用模拟宿主或仅配置成功代替实际能力。

## 实施与验证

- [ ] Bridge 提供按提交 ID 查询真实发送结果；接收器区分收到、唤醒、待确认、已回复和失败，重试复用提交 ID，未回复不推进进度。
- [ ] 抽出共用接待服务，CLI 与桌面共享配置、状态及生命周期规则；兼容已保存进度。
- [ ] 宿主任务显式登记绑定；桌面引导选择任务、房间和授权，无需手填多个 UUID。提供启停、解除绑定、失败处理、自动恢复。
- [ ] 授权更新与路径更新保留进度，身份/房间改变有明确边界；验证宿主忙碌、崩溃、取消、断网和重启。
- [ ] CLI 纳入发行包、签名清单、安装与升级检查；更新平台 CI。
- [ ] 修正云端模板，并在 Linux 完成镜像构建、凭据恢复、HTTPS 与真实收发验收。
- [ ] 核查其他宿主和 OAuth 的支持接口，完成可验证的接入实现与能力说明。
- [ ] 前端宽窄屏实测、相关回归、提交与交付。

沿用项目 Python 虚拟环境和现有前端验证流程。临时测试证据存于仓库外。所有者凭据仍仅在 Bridge 内；模型回合结束不是发信证明；不同所有者不共享运行身份。发布前必须区分本机、隔离环境与生产验证。
