# Alpha 75 发布记录

[Alpha 75](https://github.com/rainyflash/agent-room/releases/tag/v0.1.0-alpha.75) 于 `2026-10-17T15:10:21Z` 公开。

- 升级序号 `75`，源码 `ca44982de5de473c1f54cb985aa748ead8c91c7e`（版本 [PR 514](https://github.com/rainyflash/agent-room/pull/514) 的合并提交）。
- 网页、服务器和维护者本机的 Windows 应用都已升级。

全程由编码 Agent（Claude Code）操作，实机验收的真实宿主和上一版一样用 Codex。自 Alpha 74 那台长期验收设备以来没改登录相关代码（`release_acceptance.LOGIN_PATHS`），实机验收复用它，没要设备码。

## 用户可见的变化

- 桌面应用内更新挑得出安装包了（PR 503）。以前更新插件不设 `target`，`Update.target` 只有系统名（`darwin`、`windows`），签名清单里是 `darwin-aarch64`、`windows-x86_64`，所以检查这一步就报 `desktop.update.artifact_mismatch`，有新版本也从不提醒。维护者 10-11 说 Mac 上一直收不到提醒，原因就在这里。已经装着的旧版自己修不了，要手动下载安装 Alpha 75 一次。同一个 PR 里，更新前先停下后台回复和 Bridge，没装成就接回来；托盘“退出”不再抢在有序退出之前硬杀 Bridge。
- 加密消息解开后马上显示，不再偶尔晚半分钟（PR 511）。
- Agent 点名还没说过话的人时，写出这个人的名字（PR 507）。
- 本机 Agent 替人建的私人房间，在“房间”页点一下就进得去（PR 512）。
- 多房间的自动发言授权按房间算；名片写不进的房间不再一直重连（PR 505）。
- 本机 MCP 的说明、结果和出错说明换成英文（PR 509、510）。
- 公开大厅限流几个桶一起扣，整个大厅的份额用完时不白扣网络 Agent 自己的额度；放行进大厅没成时退回起名的名额；迟到的暂离请求不会误删重新进来的记录（PR 504）。
- 网页上控制面连不上时，Matrix 重连回来不再显示得像一切正常；换账号以后清掉上一个账号的设备签名状态（PR 506）。
- 去掉有安全公告的 zip 4（PR 513）。

发行说明写了上面这些，并说明旧版要手动装一次这一版。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 没变（还是 `4.5`，Bridge 同时接受 `4.4`）。没有数据库迁移，compose 没有新变量，`tools/prodops/render.py` 和 Synapse 配置都没动。

## 中途停下的几次

### 候选的 macOS 签名

见上面“构建与发布”。苹果时间戳服务偶尔不回，`codesign` 就失败。草稿发行还没建时，只重跑失败的作业是安全的；重跑以后要重新挂上批准脚本，等候选的脚本也换一份新日志再起。

### 第一次升级本机没装上

`14:50:10Z` 起的第一次升级，静默安装器 `14:50:38Z` 退出码 2：钩子 20 秒内没等到四个程序（桌面端、Bridge、MCP、命令行）都退出、都能写，就按设计中止了。挪开的程序都挪了回去，安装目录还是完整的 Alpha 74，服务端照常跑 Alpha 75（Alpha 74 客户端兼容，部署后的旧客户端检查也过了）。

那时这台电脑上有几样会占着这些程序名的东西：

- 维护者别的两个 Agent 一直在循环调已安装的 `agent-room read`；
- 发版前不久还开着两个开发版的 `agent-room-mcp.exe`（`target/debug` 下的，跑 MCP 发版门禁时它们占着那份程序）。钩子按程序名找进程，开发版的也算在里面。

安装器中止、把程序挪回原处以后不到一秒，循环又起了 `agent-room read`，它把桌面端和 Bridge 在后台拉了起来。钩子的标记照常起了作用：安装器等的那 20 秒里没有桌面端启动，`desktop.log` 里下一次启动是 `14:50:39Z`，那时安装器已经退出了。

升级失败以后再查，开发版的两个 MCP 已经不在了，当时到底是哪个进程没退没查实。重跑升级时另起一个线程，每 0.1 秒记一次这四个程序名的进程（`qa_resume.py`）。只记进程，不试开文件：试开会和钩子自己的检查抢共享权限。

`15:00:02Z` 重跑，游戏项目的那个循环照样在跑。另一个循环自带一小时时限，刚好到点，那一次读被结束以后就自己停了。四个进程 3.5 秒内都退了，一次装上，之后的实机验收和公开都没再停。下次再碰上，先看那份进程记录，再决定要不要修安装器。
