## 用户可见的变化

- 房间“邀请人”对话框多了一张带二维码的邀请卡片，能复制、能保存成图片，旁边一段能改的话连链接一起复制（#937）。卡片在这台设备上画，邀请链接的秘密不交给服务器；换一条或者停用链接以后，发出去的图也跟着失效。
- 公开房间“分享”对话框里的二维码换成能拿走的分享卡片（#938）。
- 网页上接入 Agent 先请人在 Agent 那台电脑上装桌面应用，账号已经有装着它的电脑时不请，不想装的旁边一步换成网络（#936）。手机、Linux 上照旧从网络开始。
- 发行说明照旧提醒还在用 Alpha 74 或更早版本的人手动下载安装一次。

另有：每周周报的“新用户走到哪一步”加“一周后又说了话”一列（#935）；错误汇总的一条噪音规则（#933）；picomatch 公告的精确例外（#940，跟踪 #939）。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 和本机 MCP 的工具都没变。没有迁移，没改 Rust 代码，compose 没有新变量。没改告警规则，发完没跑 `telemetry-apply`。

回滚可以退到 Alpha 96：没有迁移。

## 实机验收

- 升级前基线一次过。本机从 Alpha 96 升级，安装器一次装上（约 10 秒换完），装好的桌面端、CLI 都是 `0.1.0-alpha.97`，运行时哈希和候选一致。升级期间的进程记录照常带着：维护者电脑上别的 Agent 一直在循环调命令行，没挡住安装。
- 升级验收查会话那一步停在“桌面应用 90 秒内没有通过调试端口打开页面”（`04:52Z`）。桌面端其实好好的，带着调试端口开着房间列表；是验收工具连调试端口用的 `tools/cdp_run.mjs` 起不来，报找不到 `@playwright/test`。
  - 原因是编码 Agent 自己：`04:16Z` 趁等 CI 清理一个已经合并的临时工作树，它的 `node_modules` 是连到主检出的 junction。Git for Windows 把 junction 当普通目录，`git worktree remove --force` 顺着链接把主检出 `apps/web/node_modules` 里的一部分包删了。源码没受影响（`git status` 干净），服务端和装好的应用也没事。
  - 在主检出里离线重装（`corepack pnpm@10.28.0 install --frozen-lockfile --offline --force`，26 秒），`cdp_run.mjs` 连得上了，从 `upgrade` 接着跑（`qa_resume.py`），升级验收一次通过。
- `start` 按 `LOGIN_PATHS` 没看到改动，复用 Alpha 96 那台长期验收设备，没发设备码。
- 宿主还是 Codex，程序还在 `bin/9e1da79431da526b`，验收前看过。
- `run` 一次通过（`04:57:54Z`–`05:05:11Z`）：私人房间“发布验收”里两条消息都回了，第二条读出了附件里的验证码，空闲、接管和恢复都过了。
- 没做：邀请卡片的“复制图片”“保存图片”在装好的桌面端上还是没点过。验收工具不点这两个按钮；要点就得再占用一次维护者的桌面端，而且经调试端口点，保存和剪贴板走的不一定是人真点时的那条路。留给维护者点一次，或者约个时间由编码 Agent 在他看着的时候点。

## 本机发布脚本

- `derive_alpha97.py` 从 Alpha 96 派生：Alpha 96 那次“公开的上一版”（94）和“服务端、本机装着的”（95 候选）不是同一个，这一版两样都是 96。下一版从 Alpha 97 派生，回到平常的写法（上一版 97、这一版 98）。
- 这一版加了三个一次性的脚本，派生时别带：`rerun_then_restart.py`（等 CI 整轮跑完、重跑那一个红的作业、再拉起等待进程），`qa_resume.py` 和 `start_qa_resume.ps1`（从升级验收接着跑）。
- 开版本 PR 之前，除了 `cargo deny check advisories`，本机再跑一遍 `corepack pnpm@10.28.0 audit:node`：cargo-deny 查不到 Node 的公告。这一次是发版前那次 `suite=all` 抓到的。
- 发布途中别做清理这类不急的事。删接过 `node_modules` 链接的工作树，先摘掉链接再删目录，别直接 `git worktree remove --force`。
- 验收报“调试端口没开页面”时，先单独跑一次 `node tools/cdp_run.mjs --port 14222 --url-prefix http://tauri.localhost`，看是不是工具自己起不来，再怀疑桌面端。
