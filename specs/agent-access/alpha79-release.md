## 用户可见的变化

- 设置 → 账户里能退出登录，也能换个账号登录；退出时连身份服务（Keycloak）上的登录一起结束，再登录可以换成别的账户（PR 536、537）。维护者 10-19 说网页和桌面端都没有退出、换账号的地方，退出只在“我的 Agent”顶栏，退出以后再登录还回到原来的账户。
- 桌面端也能换账号：确认以后，这台电脑先凭自己的设备签名把自己移出原来的账户（新接口 `POST /auth/devices/current/release`），原账户留在本机的登录、Agent 连接和数据一起收走，再用新账户登录、授权这台电脑（PR 538–541）。无头验收加了一轮换账号（PR 543）。
- 旧版 iPhone、iPad 浏览器（iOS 17.4 以前）补上 `Promise.withResolvers` 和 `AbortSignal.any`，加密房间的同步不再停住、消息发得出去（PR 534）。维护者 10-19 用手机浏览器登录时发现。
- 退出登录的一个集成测试换了登录秘密，不再和别的用例撞（PR 542），不进安装包。

桌面端、Bridge、CLI 与 MCP 同版本发布，IPC 没变（还是 `4.5`，Bridge 同时接受 `4.4`）。托管的 Bridge 多认标准输入的一行 `release`，旧版 Bridge 忽略它。没有数据库迁移，compose 没有新变量，`tools/prodops/render.py` 和 Synapse 配置都没动。

## 实机验收

- 本机升级装上了，但升级验收查升级后的会话时，控制面回 401（`12:34:41Z`）。查下来：桌面端以调试端口重启后第一次打开的页面是个空文档（`readyState` 是 `complete`，没有 `body`，十分钟后还是这样），网页没起来，也就没去恢复账户登录，原生层代发 `/auth/session` 时没带登录。服务器上维护者的登录一份也没撤销，桌面端那份到 11 月 17 日才过期；数据目录里没有换账号的标记，`account_release` 没动过东西。重载一次页面，就进了房间列表、登录还在。和 Alpha 78 那次“页面刚好跳转”一样，从升级验收接着跑（`alpha79/qa_resume.py`：upgrade → start → 等批准 → run），会话检查一次通过；公开发布由 `publish_chain.sh qa_resume` 接着做。第一次打开为什么是空文档还没查实，只在验收这种调试端口重启里见过。
