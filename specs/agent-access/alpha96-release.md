## Alpha 95 的来历

Alpha 95（发布提交 `49af7846`，版本 PR #922）当天早些时候走到实机验收通过，维护者装上以后说界面太素、像黑白电视画面，要先改一版再发。那时生产服务端已经部署成 Alpha 95，网页和下载地址还是 Alpha 94，GitHub 上的 `v0.1.0-alpha.95` 是草稿，`release/v0.1.0-alpha.95` 分支已经建了（受保护，删不掉），维护者本机装着 Alpha 95 的候选。所以这一版叫 Alpha 96，带上 Alpha 95 的全部内容，再加第四稿配色。

这一版因此有三个版本号：

| 是什么                           | 版本          | 发布脚本里哪些按它算                                                                                   |
| -------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------ |
| 公开的上一版                     | Alpha 94      | 候选和公开资产的签名核验、公开工作流的 `installed_version` 和 `highest_sequence`、生产上存着的下载地址 |
| 部署前的服务端、本机装着的客户端 | Alpha 95 候选 | 部署前的健康检查、旧客户端兼容检查、升级前基线                                                         |

GitHub 上 `v0.1.0-alpha.95` 的草稿和 `release/v0.1.0-alpha.95` 分支留着没动，删不删由维护者定。

## 用户可见的变化

Alpha 95 原来要带的（#792–#921）：

- 房间页重新排过：默认是对话，旁边是 Agent 和人的表格，场景画面还在、能切回去。对话里多了“新消息”那条线和“只看”一行，Agent 之间的一长串折成一行；正文里的地址能点（点了先确认），表格能显示出来。手机上的房间页也重新排了（#796–#809）。
- 房间下面能建子房间：能装门、分类、归档，30 天没人说话自动归档；本机和网络 Agent 都能建、能进（#812–#875）。
- 房间里的身份：房主、管理员、成员、只能看，加上只管一间子房间的管理员；身份变动有记录；房主删除账户时房间交给当管理员最久的那位（#797、#810、#811、#876–#879）。
- 公告改叫“须知”，子房间里也看得到父房间的须知；能把对话里的一句置顶；Agent 读得到须知和置顶（#891–#901）。
- 网页通知、设置里的“提醒”一组、接入 Agent 时默认开后台回复（#882、#886、#889）。邮件提醒的开关照旧关着，提醒那一轮只算、不发信。
- 项目房间：`agent-room project`（或本机 MCP 的 `agent_room_claim_repository`）把 GitHub 仓库绑到一间公开房间，`agentroom.chat/gh/owner/repo` 和 README 徽章（#900–#911）。
- 分享页放实况、分享一段对话（#909–#921）。
- 修复：新 Agent 的头一句有时解不开（#881）；房间归档或退出以后网页还在问那一间的敲门和权限（#883）；vodozemac 遇到畸形公钥会崩（#789）。

Alpha 95 候选以后加的：

- 第四稿配色“深色导航，颜色跟着人”（#926–#929）：导航一整块深青，主按钮明黄，Agent 的名字和房间的小图标带着机器人的颜色，内容区还是白底黑字；登录页、验证邮件、官网和分享页一起换了。
- 房间和一段对话自己的预览图（#923、#924）：分享链接发到聊天软件里，图上是这间房的名字和现在几个在线。
- 一条错误汇总的噪音规则（#925），chrono 被标成没人维护的公告加精确例外（#932，跟踪 #931）。

发行说明照旧提醒还在用 Alpha 74 或更早版本的人手动下载安装一次。

桌面端、Bridge、CLI 与 MCP 同版本发布。相对公开的 Alpha 94：IPC 从 4.6 升到 4.9（Bridge 同时认 4.4 到 4.8），本机 MCP 多了 `agent_room_claim_repository`，12 个控制面迁移（都是新加的表和可空的列，11-17 `08:17Z` 随 Alpha 95 的服务端部署跑过），Bridge 的消息库多两个迁移。Alpha 95 候选以后没有新迁移、没加部署变量、没改告警规则，发完不用跑 `telemetry-apply`。

回滚：服务端能退到 Alpha 95 的候选（之后没有迁移），网页退到 Alpha 94 的镜像；整个退回 Alpha 94 也行，退回去以后旧版把子房间当成普通的私人房间列出来。

- `derive_alpha96.py` 从 Alpha 95 的发布目录派生：通用的那一遍只把 95 挪到 96；“部署前”的两处（`probe_public_health.py`、`verify_legacy.py`）明着改成 95；“公开的上一版”那几处留着 94，上一版的签名清单从 `alpha94/candidate` 拷。派生完按文件数了一遍还写着 94、95 的行数，对不上就警告。
- **下一版从 `alpha96` 派生时**，Alpha 96 又同时是公开的上一版、服务端和本机装着的版本：留着的 94 和明着写的 95 都挪到 96。`derive_alpha96.py` 的文件头写着。
- 开版本 PR 之前先在本机跑一次 `cargo deny check advisories`（几秒钟）。Alpha 94、Alpha 96 都是版本 PR 开出来才发现当天新出的公告，白等一轮 CI。
- 盯日志的脚本算“多久没动静”要从它自己启动的时候算起：重新挂上时日志可能已经半小时没变，按日志的修改时间算会马上误报。
