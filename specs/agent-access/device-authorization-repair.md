# 新电脑设备授权修复

## 问题与证据

2026-09-14 的生产日志显示，浏览器批准设备授权后，`POST /auth/devices/register` 四次返回 401，应用层原因均为 `device.register / InvalidAuthorization`。客户端重启后申请了新的设备码，界面再次要求授权。

服务端原来使用 ID Token 的 `auth_time` 判断设备授权是否新鲜。这个字段代表上次用户登录时间，而且允许省略；复用已登录浏览器批准新设备时，它不能代表本次授权时间。依据：[OpenID Connect ID Token 声明](https://openid.net/specs/openid-connect-core-1_0.html#IDToken)。

原有发行验收验证了已有设备凭据的升级与恢复，未覆盖浏览器旧会话批准新设备的情形。

## 修复

- 设备断言验证端口单独返回受签名保护的 `iat`，与主体的 `auth_time` 分离。设备注册按 `iat` 校验现有时间窗口和时钟偏差，保留浏览器登录时间原义。
- 继续校验签名、issuer、设备客户端 audience、过期时间和 nonce；一次性授权摘要消费与设备公钥持有证明保持不变。未扩大授权时间窗口，也未修改身份提供方策略。
- 桌面在等待授权期间发生失败时保留错误并停止自动创建新授权；重试由用户明确触发。窗口恢复不会覆盖这一失败原因。
- 接入弹窗和本机 Agent 面板显示授权未完成及错误详情，不再把登记失败显示成新一轮授权要求。

## 验证

新增回归测试先在旧实现上重现 `InvalidAuthorization`，修改后通过。覆盖旧浏览器登录、缺失可选 `auth_time`、过旧或未来 `iat`、边界时钟偏差、错误受众、过期签名断言、HTTP 适配器保留两类时间，以及桌面不自动申请新设备码。

服务端修复兼容已发布的 Alpha 30，无需更换客户端即可修正登记拒绝。桌面停止重复授权及新提示将在包含此提交的客户端构建中生效；不能把源代码测试视为用户另一台电脑已经恢复。
