# 退出登录和换账号：设计

状态见文末“状态”一节。

## 背景

2026-10-19 维护者在手机浏览器上发不出消息（另修，#534），顺带说：“不管是网页端还是桌面应用，都缺少退出当前账号登录/切换其他账号的功能。”

查下来有三处问题。

### 退出登录找不到

- 只有“我的 Agent”页顶栏右边有一个“退出登录”（`account-workspace-view.tsx`）。顶栏窄于 1260px 时它只剩一个图标（`app-navigation.css`），桌面端窗口、平板和手机上都是这样。
- 设置 → 账户第一行写着“登录的账户”和名字，旁边没有按钮。房间列表、房间页、设置的其他几节都没有退出。

### 退出了也换不了账号

- 退出只作废 Agent Room 自己的登录：控制面的那份（`POST /auth/logout` 撤销 `web_session`）和这台设备的 Matrix 会话。身份服务（Keycloak）上的登录还在；登录页勾了“记住我”的，关掉浏览器也还在。
- 每次登录都带 `max_age=300`（`recent_authentication_window`）。所以退出以后再点登录：
  - 5 分钟内输过密码的，身份服务直接放行，回到原来的账号；
  - 超过 5 分钟的，身份服务要你再输一遍这个账号的密码。填别的账号，Keycloak 报“你已经以另一个用户登录”（`differentUserAuthenticated`），要先在它那边退出。
- 也就是说现在没有办法换账号。在公用电脑上退出以后，5 分钟内别人点登录就进了你的账号。

### 桌面端多一层

- 桌面端退出只删本机的桌面登录，这台电脑的授权（Bridge 拿到的设备凭据）照旧属于原来的账户，本机的 Agent 照常在后台跑。
- 桌面端点登录时，系统浏览器里网页登录着，控制面就直接拿那份网页登录换桌面登录（`authorize_desktop_session`），又回到原来的账户。
- 就算登录成了别的账户，这台电脑的连接、本机的 Agent 和后台回复还是原来那个账户的。一台电脑只能属于一个账户：授权、`owner.json`、本机 Agent 的人物和命令行 profile 都按这个账户记在 Bridge 的数据目录里。

## 怎么改

### 1. 设置 → 账户里放退出和换账号

- “登录的账户”那一行右边放“退出登录”，下面一行“换个账号登录”，说明“退出这个账户，再用别的账户登录”。
- 网页、桌面端都在这里。“我的 Agent”顶栏的那个按钮照旧留着。
- 手机上的房间页没有顶栏：左上角回到房间列表，顶栏的“设置”进去。
- 桌面端的“换个账号登录”要第 4 步才能用，那之前桌面端不显示这一行。

### 2. 退出时连身份服务的登录一起退

- 控制面撤销这份登录以后，用删除账户的那个服务账号客户端（`agent-room-account-admin`，realm-management 的 `manage-users`）调 Keycloak 的 `POST /admin/realms/{realm}/users/{id}/logout`，结束这个账户在身份服务上的全部登录。
- 为什么结束全部，不只结束这个浏览器的：
  - 控制面没记身份服务的会话号，要记得加列、改登录和桌面登录的几条路；
  - 桌面端是在系统浏览器里登录的，那个浏览器眼下的身份服务登录不一定是当初那一份，只结束当初那份照样换不了账号。
- 代价：这个人在别的浏览器里下次碰到身份服务（新登录、要最近登录过的操作）要再输一次密码。已经登录着的 Agent Room 网页、桌面端、这台电脑的授权都不受影响，它们是控制面自己的登录，不跟着身份服务走。
- 只退本部署签发方的账户，和删除账户一样。网络 Agent 没有身份服务的登录。
- 身份服务连不上、超时都不挡退出：本地照样退出、回 204，控制面记一条告警。这时换账号可能还会碰到身份服务的提示，过一会再试。
- 接口不变，已经装着的网页和桌面端不用改。

### 3. 网页换账号

- “换个账号登录”：先退出（第 2 步把身份服务的登录一起退了），退出成功就开始登录，身份服务给的是空的登录页，填哪个账户都行。
- 不加新的登录意图。退出没成（比如断网）就停在原处，说为什么。

### 4. 桌面端换账号

换账号就是把这台电脑从原来的账户里移出来，再交给新账户。

- 点“换个账号登录”先确认：“这台电脑会从 X 的账户里移除：X 在这台电脑上的 Agent 断开、后台回复停掉；X 在别的电脑上的不受影响。”
- 确认以后：
  1. 桌面端经标准输入给 Bridge 发 `release`。Bridge 拿自己的设备凭据请控制面移除这台电脑（新加 `POST /auth/devices/current/release`）。拿着这台电脑凭据的就是这台电脑本身，所以不要最近登录过；控制面照撤销电脑那样撤掉它和它的 Agent 连接。
  2. Bridge 清掉本机凭据和数据目录里属于原账户的东西（`owner.json`、`host-agents`、`cli-profiles`、`mcp-joins`、`messages`、`matrix-store`、`attachments`、`handoffs`、`retired`），留下日志和部署配置，然后退出。
  3. 桌面端退出登录（第 2 步把身份服务的登录一起退了），再用 `reauthenticate` 意图登录：不拿系统浏览器里的网页登录换，身份服务给的是空的登录页。
  4. 新账户登录以后照旧（`specs/desktop-sign-in/design.md`）：桌面端重启 Bridge，Bridge 等电脑授权，原生层拿新的桌面登录要一份交给它，这台电脑就归新账户了。
- 移除这一步没成（控制面连不上）就整个停下，不退出登录、不清本机，界面说为什么、能重试。服务器上已经移除、本机还没清完的，下次 Bridge 启动发现凭据作废（`bridge.not_authorized`）照旧停下，人点“重新授权这台电脑”时清掉再授权。
- 宿主里还开着的 MCP、命令行进程拿着原账户的人物：Bridge 不认这些人物了，它们报找不到人物，在宿主里重新接入就是新账户的 Agent。
- 旧版 Bridge 不认 `release` 这一行（新加的行不认识就忽略），所以桌面端和 Bridge 一起升级；桌面端发出 `release` 以后等不到 Bridge 回话就当失败。

### 5. 验收

- 第 2 步：控制面的单元测试（撤销后调身份服务、身份服务失败不挡退出、别的签发方不调）；真实依赖测试里退出以后，这个用户在 Keycloak 上没有会话。
- 第 3 步：浏览器夹具看设置里的两行；真实网页验收里用第二个种子账户：A 退出、点“换个账号登录”、在身份服务的登录页登录 B，回来是 B。
- 第 4 步：Bridge 的单元测试（`release` 清目录、清凭据、退出），控制面的接口测试；无头验收在派发 `suite=all` 时把一台电脑从 A 换给 B，Synapse 里 A 的 Agent 都离开了房间，B 的 Agent 能进房间说话。
