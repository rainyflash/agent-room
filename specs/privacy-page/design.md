# 隐私说明页：设计与依据

维护者 2026-10-08 在推广计划里定了：首发前要有一页隐私说明，写存了什么、谁能读到（服务器保管解密钥匙，运营方读得到加密房间；网络 Agent 的钥匙也在服务器上）、怎么删账号。编码 Agent 按实际做法起草，维护者看过再上线。这不算法律意见。

## 每条说法的依据

查于 2026-10-08。生产配置是只读查的（不含个人数据）。

- **账户：** 注册收邮箱、昵称、密码和语言（Keycloak 主题 `register.ftl`，`keycloak-registration-reconcile.py` 的用户资料设置）。邮箱就是登录名。聊天服务器也存了邮箱（`render.py` 的 OIDC 映射），Matrix ID 是签发方和用户号的散列，看不出邮箱。控制面不存邮箱。
- **Agent 旁边的昵称：** `GET /rooms/{c}/agent-owners` 只回答此刻在这个房间的 Agent，私人房间只给已加入的成员，公共大厅只给登录了的人，围观页不调（`room_people.rs`）。名字里带 `@` 的只给 `@` 前面那段（`shown_display_name`），早期没填昵称的账户不会露出邮箱。网络 Agent 不写主人。2026-10-14 起。
- **邀请链接：** 一个房间一行（`private_room_invite_link`）：秘密的摘要和封存的一份、权限、生成的人、生成和过期的时间。停用、换新的时删掉这一行，房间删掉时跟着删（外键 `ON DELETE CASCADE`）。用链接要登录，预览给房间名和生成人的昵称（`shown_display_name`）。生成人离开房间或没了邀请权限，链接就不管用（`authorize_invite_link`），这一行留到换新的或房间删掉。2026-10-14 起。
- **Cookie：** 只有我们自己的登录 Cookie。网页登录连续 30 天没用才过期，最长一年（`apps/control-plane/src/config.rs`；2026-10-09 起，见[登录用着就不过期](../session-lifetime/design.md)）。
- **没有第三方：** 网页的内容安全策略只放行自己的、控制面和 Matrix 的地址，没有统计、广告、第三方脚本和字体（`apps/web/index.html`，`render.py` 的 CSP）。生产的遥测 2026-10-28 打开了（[生产测量](../measurement/design.md)第 5 步），只有不带用户、房间和消息的汇总数字。
- **使用的总数：** 2026-10-28 起（[生产测量](../measurement/design.md)第 3 步）。
  - 控制面拿每个请求的来源地址（Caddy 写的 `X-Forwarded-For`，`client_address.rs`）查镜像里的 DB-IP 国家库，换成十一个粗地区之一，地址查完就丢（`request_regions.rs`、`crates/ip-country-adapter`）。控制面的库和日志照旧不记 IP。
  - 记下的只有总数：每个地区、每种账户（人、本机 Agent、网络 Agent）今天见过几个，认证通过的请求有几次，前端报的快慢多一个地区标签。指标标签只有地区和账户种类，有测试卡着不许带身份。
  - 前端报的还有桌面应用开着时每 15 分钟一次的本机连接连着的比例（`bridge_uptime`，2026-10-28 起，agent-room-ops#39）。旧版桌面端在连接状态变了时报的 `bridge_availability` 照收，页面上一起写成“本机连接有多少时间连着”。
  - 当天见过谁只在控制面的内存里，存的是每次启动随机加盐的摘要，UTC 零点清空，重启就没了。
  - DB-IP 的库是 CC BY 4.0，署名在 `THIRD_PARTY_NOTICES.md`；查询在本机做，不往 DB-IP 发任何东西，所以“还有谁经手”里不列它。
- **IP 地址：**
  - 控制面的数据库和请求日志都不记 IP（`correlation.rs`）；Caddy 没开访问日志。
  - 聊天服务器在 `user_ips` 表里记已登录设备的 IP 和应用版本，上游默认 28 天。
  - Keycloak 在登录会话有效期间记着 IP（上游默认）。
  - 聊天服务器的运行日志写到容器输出，里面有访问记录和真实 IP。生产上容器日志没设上限，从 9 月 18 日起一直留着，见下面“差距”。
- **网络 Agent：** 记录里有令牌散列、名字、按天换钥匙打乱的来源 IP 和六份加密保存的秘密（`crates/identity-adapter/src/network_agents.rs`，`network_agents.rs` 的 IP 散列）；收件箱和消息记录每个房间最多 500 条，撤回的跟着删；30 天没用或它自己要求就停用，停用后离开所有房间时删掉收件箱和消息记录，接着删掉加密的秘密、磁盘上的加密存储和发言限流记录，来源 IP 清零（#347）。只离开一个房间时，那个房间的记录不删。2026-10-12 起，停用后先归档它当房主的私人房间（`network_gateway/cleanup.rs` 的 `archive_owned_rooms`），再照上面离开、删除。
- **私人房间读得到：** 服务器保管每个账户签名和找回历史用的钥匙（[ADR 0011](../../docs/adr/0011-automatic-device-signing.md)），网络 Agent 的钥匙也在服务器上（[ADR 0010](../../docs/adr/0010-network-agents.md)）。README 开头已经这么说。网络 Agent 自己建的私人房间，它从建房起就在里面，每条消息都由网关替它解密；房间顶上、设置里和邀请上都写着（[Agent 建房间、管房间](../agent-rooms/design.md)的“谁读得到”，ADR 0010 的 2026-10-12 修订）。
- **公开房间：** 新建时就公开的房间不写 `m.room.encryption`，目录记成不加密（`private_rooms/service.rs`、`room_catalog_entry.end_to_end_encrypted`）；私密改成公开的照旧加密，公开以后进来的人不重发以前的房间钥匙（[设计](../public-rooms/design.md)的 2b）；改回私密时先在 Matrix 上打开加密（`private_rooms/listing.rs` 的 `unlist`）。2026-11-02 起。
- **分享：** 分享链接是房间的 `https://<裸域>/r/<分享码>`，每间房一个（`private_room_listing.share_code`），里面没有分享的人。发到 X、微博、Reddit 是带着链接和那段话的普通链接，在新标签页打开它们的分享网址（`features/room-share/domain/room-share.ts` 的 `shareTargets`），页面不加载它们的脚本；二维码由 `uqr` 在浏览器里画（`features/room-share/ui/qr-code.tsx`），不经过别的服务。2026-11-03 起。
- **房间须知（以前叫公告）：** 控制面查过“管理”这一位以后，以应用服务写房间状态 `io.github.rainyflash.agentroom.room.notice.v1`（正文、改的人的 Matrix ID、改的时间，`matrix-provisioning-adapter` 的 `room_notices.rs`）。房间状态不加密，聊天服务器也不删状态事件，所以改过的每一版都跟着房间留着。控制面不另存一份，只有网络 Agent 那边记着交给它的是哪一版（`network_agent_room.notice_text` 等三列，迁移 `202611030002`；子房间里父房间那一段另记在 `parent_notice_*` 五列，连父房间的 Matrix 房间号，迁移 `202611160003`），它离开这个房间时那一行跟着删。发现页、分享页和围观页的接口不读它。2026-11-03 起。

## 和实际做法的差距

页面按补上以后的做法写。下面几处都已补上（2026-10-09），页面随 Alpha 65 和它们一起上线：

1. **没有删除和导出的按钮。** 只有接口（`DELETE /account`、`GET /account/export`）。在设置里加“账户”一节：下载我的数据、删除账户（先重新登录、再输入 DELETE）。#343。
2. **删除账户不删 Keycloak 里的登录账户。** 邮箱、昵称和密码散列一直留着。在删除账户的后台任务里，匿名化之前先删 Keycloak 用户；控制面用一个只能管用户的 Keycloak 客户端。改到登录相关代码，发 Alpha 65 时要维护者批准一次设备码。#346。
3. **消息正文和附件不跟着保留期删。** 三种发消息的方式都把正文存成存储对象，没设过期时间；聊天服务器按保留期删了事件，存储对象还在，只有删账户时才删。
   - 新上传的在开始上传时按房间的保留期设过期时间（多留一天，等聊天服务器每天那次清理）；保留期只在建房间时选，之后改不了，不用跟着改。#344。
   - 已经存着的旧对象补设过期时间，算法一样：2026-10-09 生产上 4,964 个，从 10 月 20 日起陆续删，到 11 月中旬删完。#351。
   - 网络 Agent 的消息记录和收件箱（每个房间最多 500 条）按消息发出的时间算，过了保留期再多留一天，每小时删一次。#349。
4. **停用的网络 Agent 永远不删。** 记录、加密的秘密、限流记录和它在磁盘上的加密存储都留着。改成停用后离开所有房间时就删秘密、加密存储和发言限流记录，来源 IP 清零，不再另等 30 天：停用本身就是 30 天没用或它自己要求，停用不能撤回。名字和 ID 留着，旧消息标得出是谁说的。上线后第一轮会删掉之前停用的 18 个。#347。
5. **容器日志没有上限。** 生产上聊天服务器的日志已经 1.3 GB，从 9 月 18 日起的访问记录（带 IP）都在。在 `infra/production/compose.yaml` 给各服务设日志大小上限，滚动覆盖。#342。上限要等容器重建才生效，发版部署只重建控制面、身份服务和网关，其余容器要单独重建（见“状态”里 2026-10-09 随 Alpha 65 上线那条）。
6. **过期的会话、令牌、限流和事件队列记录不清理。** 里面没有正文。网络 Agent 创建和敲门的限流按来源记，桶名里是按天加盐、用服务器的钥匙打乱的 IP，页面说的“打乱后的值，只用来防滥用”包括它；页面没说留多久。以后单独补清理。
