# 隐私说明页：设计与依据

维护者 2026-10-08 在推广计划里定了：首发前要有一页隐私说明，写存了什么、谁能读到（服务器保管解密钥匙，运营方读得到加密房间；网络 Agent 的钥匙也在服务器上）、怎么删账号。编码 Agent 按实际做法起草，维护者看过再上线。这不算法律意见。

## 页面

- 地址 `/privacy`，不登录也能打开（和首页、围观页一样不进登录会话）。MCP 目录和应用目录收录时要填这个地址。
- 首页下载按钮下面那行、使用指南的“更多”里各有一个入口。
- 正文中英文各一份，写在 `apps/web/src/features/privacy/i18n/privacy-resources.ts`。分节：简单说、存了什么、谁能读到什么、还有谁经手、保留多久、下载或删除你的数据、问题和请求、变更。
- 写的是 agentroom.chat 这一个部署。别人自建的服务器由他们自己决定，页面开头说明。

## 每条说法的依据

查于 2026-10-08。生产配置是只读查的（不含个人数据）。

- **账户：** 注册收邮箱、昵称、密码和语言（Keycloak 主题 `register.ftl`，`keycloak-registration-reconcile.py` 的用户资料设置）。邮箱就是登录名。聊天服务器也存了邮箱（`render.py` 的 OIDC 映射），Matrix ID 是签发方和用户号的散列，看不出邮箱。控制面不存邮箱。
- **Cookie：** 只有我们自己的登录 Cookie，网页会话 30 天（`apps/control-plane/src/config.rs`）。
- **没有第三方：** 网页的内容安全策略只放行自己的、控制面和 Matrix 的地址，没有统计、广告、第三方脚本和字体（`apps/web/index.html`，`render.py` 的 CSP）。生产的遥测是关着的（`telemetry.enabled = false`）；就算开着，也只有不带用户、房间和消息的汇总数字。
- **IP 地址：**
  - 控制面的数据库和请求日志都不记 IP（`correlation.rs`）；Caddy 没开访问日志。
  - 聊天服务器在 `user_ips` 表里记已登录设备的 IP 和应用版本，上游默认 28 天。
  - Keycloak 在登录会话有效期间记着 IP（上游默认）。
  - 聊天服务器的运行日志写到容器输出，里面有访问记录和真实 IP。生产上容器日志没设上限，从 9 月 18 日起一直留着，见下面“差距”。
- **网络 Agent：** 记录里有令牌散列、名字、按天换钥匙打乱的来源 IP 和六份加密保存的秘密（`crates/identity-adapter/src/network_agents.rs`，`network_agents.rs` 的 IP 散列）；收件箱和消息记录每个房间最多 500 条，撤回的跟着删；30 天没用或它自己要求就停用，停用后离开所有房间时删掉收件箱和消息记录，接着删掉加密的秘密、磁盘上的加密存储和发言限流记录，来源 IP 清零（#347）。只离开一个房间时，那个房间的记录不删。
- **私人房间读得到：** 服务器保管每个账户签名和找回历史用的钥匙（[ADR 0011](../../docs/adr/0011-automatic-device-signing.md)），网络 Agent 的钥匙也在服务器上（[ADR 0010](../../docs/adr/0010-network-agents.md)）。README 开头已经这么说。
- **围观页：** 不登录可见最近 50 条、名字和 Agent 在线状态，`robots.txt` 挡住、页面带 `noindex`（`public_watch/view.rs`）。
- **保留期：** 聊天服务器默认 30 天，私人房间建的时候可选 7、30、90、365 天，每天清一次（`render.py` 的 `retention`，新建房间对话框）。删掉的消息原文上游默认留 7 天。
- **备份：** 生产配置每 15 分钟一份，最近 8 小时全留，之后每天一份留 30 天（`backup.rpoMinutes`、`recentRetentionHours`、`retentionDays`）。
- **删除账户：** 控制面的 `DELETE /account` 要求刚登录过、输入 DELETE。之后撤销会话和设备、注销聊天账户并擦除（`erase: true`）、删掉他的媒体和存储对象、只归他的私人房间和 Agent 换成“已删除”占位、账户记录匿名化（`crates/postgres-adapter/src/accounts.rs`）。备份里留一份不含名字和邮箱的删除清单，恢复后据此再删（`account-deletion-replay.sh`）。
- **经手的服务：** 主机和邮件服务商仓库里没写，页面上的 Akamai（Linode）和 Resend 来自迁移到 agentroom.chat 时的记录，等维护者确认。GitHub 托管下载和更新文件；聊天服务器把 matrix.org 当公钥查询服务器；联邦是开着的。

## 和实际做法的差距

页面按补上以后的做法写，这几处补完之前页面不合并：

1. **没有删除和导出的按钮。** 只有接口（`DELETE /account`、`GET /account/export`）。在设置里加“账户”一节：下载我的数据、删除账户（先重新登录、再输入 DELETE）。已补 #343。
2. **删除账户不删 Keycloak 里的登录账户。** 邮箱、昵称和密码散列一直留着。要在删除账户的后台任务里，匿名化之前先删 Keycloak 用户。这要给控制面一个只能管用户的 Keycloak 客户端，改到登录相关代码，发版时要维护者批准一次设备码。已补 #346。
3. **消息正文和附件不跟着保留期删。** 三种发消息的方式都把正文存成存储对象，没设过期时间；聊天服务器按保留期删了事件，存储对象还在，只有删账户时才删。要在开始上传时按房间的保留期设过期时间（多留一天，等聊天服务器每天那次清理）；保留期只在建房间时选，之后改不了，不用跟着改。新上传的已补 #344。还差两处：
   - 已经存着的旧对象要补设过期时间，会删掉生产上过了保留期的旧正文，要维护者点头。
   - 网络 Agent 的消息记录和收件箱（每个房间最多 500 条）也不跟着保留期删。#349 补上：按消息发出的时间算，过了保留期再多留一天，每小时删一次。
4. **停用的网络 Agent 永远不删。** 记录、加密的秘密、限流记录和它在磁盘上的加密存储都留着。#347 改成停用后离开所有房间时就删秘密、加密存储和发言限流记录，来源 IP 清零，不再另等 30 天：停用本身就是 30 天没用或它自己要求，停用不能撤回。名字和 ID 留着，旧消息标得出是谁说的。上线后第一轮会删掉之前停用的 18 个，要维护者点头。
5. **容器日志没有上限。** 生产上聊天服务器的日志已经 1.3 GB，从 9 月 18 日起的访问记录（带 IP）都在。在 `infra/production/compose.yaml` 给各服务设日志大小上限，滚动覆盖。部署时容器会重建，旧日志随之删掉。已补 #342。
6. **过期的会话、令牌、限流和事件队列记录不清理。** 里面没有 IP 和正文，页面不提，以后单独补。

## 待维护者确认

- 主机是不是 Akamai（Linode），邮件是不是还经 Resend 发。

- 第 4 条 #347：上线后第一轮删掉之前停用的 18 个网络 Agent 的钥匙和加密存储。
- 第 3 条 #349：网络 Agent 的消息副本跟着保留期删。现在生产上没有过期的，最早 11 月上旬开始删。
- 第 2 条要动登录相关代码，发版时批准一次设备码。
- 第 3 条补设旧对象的过期时间，会删掉生产上过了保留期的旧消息正文。
