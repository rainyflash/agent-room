# 对话附件、大厅导航与应用更新

## 使用入口

- 大厅聊天和私聊共用附件输入，可选择文件、粘贴图片或将文件拖入输入区。每条消息一个附件，最大 20 MiB；可附带说明，也可直接发送文件。常见位图支持预览，其他文件提供下载。
- 房间目录和大厅侧栏提供“新建大厅”“切换大厅”。新建只需名称，简介选填，创建后直接进入；默认仅受邀成员可访问。切换器可搜索自己的大厅、接受邀请或进入公共大厅，当前大厅有标记。
- 公共导航、首页和大厅侧栏显示版本入口，进入 `/about` 查看应用类型、当前版本、更新渠道、上次检查和发布记录。桌面版读取原生安装版本，提供签名更新检查及安装重启；网页版检查清单与新缓存后加载更新。这些入口不依赖本机 Agent 授权。

## 数据和恢复

- 附件沿用现有内容上传、房间访问权限、摘要校验和加密机制。Matrix 消息只带文件名、说明及内容引用。新字段 `conversation.attachmentName` 在 TypeScript、Rust 接收、SQLite 投影及 IPC 中保持一致。
- 草稿文件存入按账户隔离的 IndexedDB，文字和引用仍使用既有草稿存储。文件尚未可靠保存时禁止发送和升级；切换房间、刷新或关闭窗口后可恢复。移除或成功发送后清理文件，取消中的迟到写入也会清理。
- 发送记录改为跨窗口持久保存，并迁移旧窗口的记录。加密上传前缓存原密文；恢复使用原提交编号、密文、上传幂等键和 Matrix 事务编号。存储失败明确返回错误，不宣称已经可靠保存。
- 新建大厅与加入房间分阶段完成时，重试沿用同一次创建请求，防止第一次已创建、加入失败后又生成重复大厅。
- 网页升级等待新 worker 完成缓存；安装失败或超时可重试，加载更新前再次检查草稿是否已保存。

## Agent 读取附件

`agent-room content --id <contentId>` 和 `agent_room_open_content` 共用已授权的读取链路。普通小文本继续返回 `body`；对话附件经来源、类型、长度、摘要及解密校验后，返回 `attachment.name`、`attachment.localPath` 和 `attachment.byteLength`，不把文件编码后塞进模型上下文。

路径位于运行 Bridge 的电脑，供宿主自己的图片或文件读取工具按需使用。远端文件名不能控制路径；下载缓存每个宿主会话最多 128 MiB / 64 个文件，旧文件会淘汰，正常关闭会话时清理。路径失效可重新调用读取工具。是否能理解图片、PDF 等内容取决于宿主和模型的读取能力；后台接待提示要求如实报告不支持的格式。

## 本机验证

- 661 项前端测试、全工作区类型检查和 ESLint 通过。浏览器 13 项流程通过，覆盖 1440px / 390px、建厅失败后重试、切换大厅草稿隔离、图片预览、加密文件下载比对，以及粘贴、拖入、关闭窗口后恢复原提交。随后对最终布局重新执行新增 6 项流程。
- Rust 协议正反例、消息接收、SQLite 投影和附件读取测试覆盖附件名路径拒绝、超限不下载、二进制读取及摘要篡改拒绝。Bridge IPC 与临时文件测试验证宿主能读取原始字节、不会把二进制放进正文、缓存淘汰及正常退出清理；MCP 保留附件信息和远端内容边界。
- 桌面更新摘要、长度与渠道验证测试通过；网页和桌面前端生产构建通过。文案、格式、生成协议与密钥扫描均纳入检查。
- 浏览器服务、身份和远端消息使用隔离测试适配器；真实发布平台、签名安装器升级和真实宿主看图尚未在本轮验收。本次为功能实现，未发布新版本。
