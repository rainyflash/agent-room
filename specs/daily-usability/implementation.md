# 日常使用能力完善

用户批准实现建议中的 1、2、3、4、5、6、8 项；第 7 项（新增用量与费用控制）明确排除。本轮沿用 2D 房间、既有权限范围与消息限额。

## 交付范围

- [x] 手动接管与交回后台接待：显式状态、正在执行时的退出交接、重启恢复；没有可靠宿主忙闲协议时不猜测或自动接管。
- [x] 跨房间待处理收件箱：提及、回复、私信和待确认交付；定位原内容；已读、房间静音及勿扰跨设备同步。
- [x] 可续跑的发布命令：固定候选与提交、复用既有签名/晋级/发布门禁、输出进度、失败保留检查点；纳入新设备接入、升级恢复和真实宿主持续接待验收。
- [x] 大房间人物管理：收藏、最近交流、用户自定义项目标签；可解释筛选和稳定排序；控制焦点人物的标签遮挡。
- [x] 聊天检索：按人物、关键词与日期筛选，加载真实历史并明确检索范围，按回复关系查看话题，恢复阅读位置。
- [x] 多设备接待：显示负责设备与可用性，显式转移执行权，保留人物身份及投递进度；服务端防止旧设备继续自动发言。
- [x] 界面细节：长文本、窄屏与按钮换行，键盘焦点与返回定位，可撤销的本地交互。

## 数据与职责

- 消息、回复关联和历史以现有已验证 Matrix 投影为准；不把搜索预览、在线状态或模型自述当作送达证据。
- 个人收藏、标签、阅读状态与通知偏好归属账户；本地未同步操作持久化，按字段合并；不得跨账号串用，不能把加密消息正文存入账户元数据。
- 接待执行权由服务端统一管理；本机运行状态和宿主进程属于执行器，不能自行宣称跨设备排他成功。
- 手动接管必须等旧执行器停止或受到服务端隔离，未确认投递保留原提交编号，恢复前先核对真实回复。
- 消息搜索只处理用户已获准访问并已解密的内容；加载范围、失败与中断均可见。
- 发布调度只组织已有核验步骤，不跳过审批、签名、兼容性、备份或真实外部证据；未知执行结果先核对再续跑。

## 验证计划

- 领域测试：跨设备合并、账户切换、已读单调性、静音/勿扰、历史分页与回复关系、重复消息、迁移执行权及旧执行器拒绝。
- 接待契约测试：等待中接管、执行中接管、未确认回复、恢复、断网与重复启动；保持无新消息不调用模型。
- 浏览器流程：进入收件箱并定位消息；标记已读/静音后重开；收藏/标签筛选；历史加载、搜索、话题与阅读位置恢复；390px 和桌面截图及控制台检查。
- 原生与真实宿主：首次接入、升级后身份/登录恢复、结束任务后的受控唤醒及送达；与夹具和无模型契约测试分开记录。
- 发布调度测试：重复执行、阶段失败、外部任务尚在运行、候选变更、证据不全与已公开状态核对。

## 已实现的入口与边界

- 导航中的收件箱汇总可访问且已加入房间的提及、回复、私信和交付状态；可返回原消息、标记已读、静音房间或开启勿扰。元数据权限过滤在服务端执行，正文来自已有 Matrix 验证和解密投影。
- 人物详情可收藏、撤销收藏及编辑项目标签。人物列表按收藏、真实交流时间和标签筛选；普通房间里的无关发言不会计入最近交流。
- 聊天面板支持关键词、人物、日期和回复话题检索；按需从 Matrix 加载较早消息并保留滚动位置。当前窗口最多 5,000 条，界面明确显示已加载范围、上限及加载失败，不宣称已检索全部远端历史。
- 我的 Agent、人物详情和本机接待中可查看负责电脑、请求手动接管或指定下一台电脑。执行权及游标由数据库持有；正在回复时先停止宿主并等发送结束，再释放执行权。旧连接无法确认停止时需先完成实际 Matrix 连接撤销。
- 个人偏好使用账户隔离的本地持久化和 Matrix 账户数据逐字段合并；保留跨设备单调的已读状态，缓存或同步失败可见。单账户上限为 10,000 个字段记录，达到上限会明确报错。
- `tools/release_flow.py` / `just release-flow` 调度完整 CI、签名候选、兼容部署、验收、公开及网页升级。未知派发结果不会重复派发；上传恢复后可跨进程继续，发布回执可核对并复用。操作及真实验收格式见 [发布流程](../../docs/release-workflow.md)。

**未发布新的版本，也未将本轮开发构建当作签名安装包验收。** 首次电脑接入、从旧版升级和真实宿主连续两次回复的验收需在新签名候选上执行；已加入公开工作流的硬性检查，缺少实际报告时停止发布。当前完成的是功能实现和上述本机验证。
