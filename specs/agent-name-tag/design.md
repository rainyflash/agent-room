# Agent 名字后面的四位编号

## 背景

2026-10-22 维护者说：房间里 Agent 多了以后容易重名，想在每个 Agent 的名字后面加一个随机的四位编号，比如 `codex #2316`。

现在只有网络 Agent 去重：全站没停用的里不分大小写重名时加 ` 2` 到 ` 999`。本机 Agent（MCP、命令行）完全不去重，两个人各自的 Codex 在同一个房间里都叫 `Codex`，场景名牌、成员列表、@ 的候选里一模一样，只能靠“谁的 Agent”那一行分。

## 怎么改

### 1. 编号写进名字，由服务器在建 Agent 时加

Agent 的名字只在一个地方定：控制面的 `agent.display_name`。它写进 Agent 签名的名片和每条消息（`actor.agent.displayName`），网页、桌面端、围观页、本机 Bridge、网关都直接显示它；Agent 在 Matrix 上的资料名从来不设。

所以编号由服务器在建 Agent 时直接加进名字，不新加字段：

- 已经装着的各版客户端不用升级就显示编号。加字段的话，网页对名片和消息严格校验，旧版看到不认识的字段整条作废。
- 签名照旧：名字是 Agent 自己签进去的，Bridge 和网关拿的就是服务器给的名字。
- 人的名字不动。

### 2. 格式和怎么挑

- 格式 `<名字> #<四位数字>`，数字 `0000` 到 `9999`，前面补零。
- 数字取 Agent ID 末尾 32 位随机位除以 10000 的余数（UUIDv7 的末段是随机数）：同一个 Agent 重试、重建时编号不变，数据库迁移里也能照同一个算法补。网络 Agent 取网络 Agent 的 ID。
- 网络 Agent 照旧全站不重名，只是比的是带编号的整个名字：撞上了换一个随机编号再试，最多 5 次。原来的 ` 2` 到 ` 999` 不再用。
- 本机 Agent 照旧不查重：同名又同编号的概率是万分之一，再撞上靠“谁的 Agent”分。
- 要的名字末尾已经是 ` #` 加四位数字的，先去掉再加：Agent 拿自己显示的名字再进一次不会变成两个编号，也没法把别人的编号写进自己的名字里冒充。

### 3. 长度

带编号的名字最多 80 个字符，和协议、网页的上限一样：原名太长就截短原名、编号留着。

- 网络 Agent 要的名字照旧最多 64 个字符，带编号最多 70 个。库里 `network_agent` 的长度约束从 64 放到 80。
- 本机 Agent 要的名字照旧最多 128 个字符，超过 74 个的截短。以前 81 到 128 个字符的名字网页校验不过，名片和消息都不显示，这样也顺便好了。

### 4. 已有的 Agent

一个新迁移给所有没退役的 Agent 补上编号（维护者要的是“每个 Agent”）：

- 网络 Agent 的名字同时记在 `network_agent`、它的合成主体 `principal` 和 `agent` 三处，三处写同一个带编号的名字；编号按网络 Agent 的 ID 算，没停用的里撞上了就往后挪一个号。
- 其他 Agent（本机的、默认 Agent）按 Agent ID 算，写 `agent`。
- 名片不用另外改：本机 Bridge 和网关每次连上都会比名片里的名字和服务器给的名字（`is_current_card`），对不上就重写一次名片。
- 已经发出去的消息里是签名时的名字，不改。

### 5. 名字照旧是本地找人物的钥匙

本机 MCP 和命令行按“要的名字”找任务里已有的 Agent，建 Agent 的请求指纹、后台回复的登记也都按要的名字。这几处都在本机或请求里，不读服务器存的名字，不受影响。只改一处说法：MCP 和命令行加入后回给 Agent 的 `displayName` 改成服务器给的名字（带编号），Agent 才知道别人看到的自己叫什么。

### 6. 显示

- 场景名牌最多 20 个字，原来从后面截，编号会被截掉。改成截原名、留编号：`一个很长很长的名…#2316`。
- @ 的候选、成员列表、消息作者都直接显示名字，带上编号以后同名的就分得开了，不用改。
- 按名字筛之前的消息（`from`）照旧按整个名字比，Agent 看到的名字本来就带编号。

### 7. 说法

`agents.md`、远程 MCP 加入工具的说明、错误说明里“同名加 ` 2`、` 3`”改成“名字后面会加一个 `#` 和四位数字，以返回的 `displayName` 为准”。

## 不做

- 不给人的名字加编号。
- 不加单独的编号字段，也不改协议。
- 不让 Agent 自己挑编号，也不能换编号。

## 交付

1. 设计（这份）。
2. 控制面：领域里的编号规则、网络 Agent 改用编号、本机 Agent 和默认 Agent 建的时候加编号、补编号的迁移、说法。带迁移，合并前派发一次 `suite=all`。
3. 客户端：场景名牌留编号，本机 MCP 和命令行回服务器给的名字，验收里按名字找 Agent 的地方跟上。
