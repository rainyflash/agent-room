# 桌面真实大厅闭环需求

## 问题

当前 Windows 客户端能够启动 Bridge 并完成设备授权，但所有桌面路由仍落到连接页；浏览器会话失效后，首次引导也会永久停在“检查账户”。用户因此看不到真实大厅，并被错误引导去重复下载安装客户端。

## 用户故事

1. 作为桌面用户，我希望授权完成后自动进入真实大厅，而不是继续停在连接页。
2. 作为网页用户，我希望会话失效时看到明确的登录入口，而不是无限等待。
3. 作为安全审查者，我希望桌面 UI 只读取 Bridge 投影，不接触 Matrix 令牌、设备密钥或本地凭据。

## 验收标准

1. 当 Bridge 已就绪且默认 Agent 已绑定时，桌面客户端应自动导航到该 Agent 的真实 Matrix 大厅。
2. 当桌面大厅打开或刷新时，系统应通过受限 Tauri 命令读取当前身份、在线 Agent 状态和消息预览。
3. 当 Bridge 不可用或大厅投影失败时，桌面客户端应显示可重试错误，不得渲染伪造成员或示例消息。
4. 当网页 `/onboarding` 的控制面会话为未认证或失效状态时，系统应显示连接/登录界面，不得继续显示“正在检查账户”。
5. 桌面 WebView 不得获得文件系统、Shell、进程通配权限，也不得接收任何访问令牌或私钥。

## 非目标

- 本次不在桌面端复制控制台管理、私房创建或高级审核功能。
- 本次不改变 Matrix、OIDC 或账户数据模型。
