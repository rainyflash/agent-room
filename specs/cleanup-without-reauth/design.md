# 归档房间、撤销设备不用重新登录，设计

状态见文末“状态”一节。

## 背景

2026-11-07 维护者说要能更方便地归档房间、撤销设备，而且不用重新登录才能做。

现在这两样都要“最近登录过”（5 分钟内真正输过密码或批准过登录，`AuthenticationRequirement::RecentAuthentication`），在界面上很别扭：

- **归档房间**只在房间设置的“成员”一节最底下。登录过了 5 分钟按钮就变灰，只有一句悬停提示，连“重新登录”的按钮都没有；点了直接归档，也没有确认。
- **撤销电脑和 Agent 连接**在设置的“安全”里，每一行一个按钮，另有“7 天以上没用的一键撤销”。过了 5 分钟服务器就拒（`authentication.reauthentication_required`），要先去身份服务重新登录一趟。想挑几台一起撤，只能一台台点。

## 维护者定的（2026-11-07）

1. 归档房间、撤销电脑、撤销 Agent 连接都不再要求最近登录过，改成页面里的确认框。
2. “房间”页上直接归档：你当房主的房间卡片上有“归档”，不用进房间、开设置。
3. 设置的“安全”里能勾选任意几台电脑或几个 Agent 连接，一起撤销。

没选的：一次勾好几间房间一起归档。

## 代价

“最近登录过”防的是拿到你登录的人（偷走的 Cookie、借用的电脑、桌面端里存着的登录）不用再输密码就做破坏性的事。去掉以后，这样的人能直接：

- 归档你当房主的房间：房间变成只读、不能恢复，里面的人和 Agent 都不能再说话；
- 撤销你的电脑和 Agent 连接：被撤的电脑要重新授权，Agent 要重新接入。

他照样拿不到你没有的东西：只能撤你自己的设备和连接、只能归档你当房主的房间，请求要从我们自己的页面发（Origin 检查照旧），审计照旧记。撤销本来就是“丢了设备时用的”那一类动作，被人乱撤是添麻烦、不是泄露。维护者接受。确认框防的是手滑，不防偷登录。

照旧要最近登录过的：删除账户、删除 Agent、把人移出房间（改成员）、转让房主、治理动作、平台冻结、把管房间交给 Agent 的授权。

## 怎么改

### 控制面（第 2 步）

三个接口的认证要求从 `RecentAuthentication` 改成 `ActiveSession`：

| 接口                              | 做什么                          |
| --------------------------------- | ------------------------------- |
| `DELETE /auth/devices/{deviceId}` | 撤销一台电脑                    |
| `DELETE /agent-instances/{id}`    | 撤销一个 Agent 连接             |
| `DELETE /private-rooms/{catalog}` | 房主归档私人房间（含公开房间）  |

别的都不动：同源检查、只能动自己的、只有房主能归档、审计、撤销以后让 Agent 离开房间、注销 Matrix 设备的后台重试。回答的格式不变。

旧版网页和桌面端照旧按 `recentlyAuthenticated` 把归档按钮变灰、撤销前先请人重新登录，更新以后才省掉这一步；服务器这边对它们没有影响。

### 网页：归档（第 3 步）

- 房间设置“成员”一节的“归档房间”不再变灰。点了先在原处展开确认：归档以后房间里所有人（包括 Agent）都只能看之前的消息、不能再说话，归档不能恢复。确认了才归档，归档完退出房间。
- “房间”页“你建的”那一组（你当房主的）每张卡片下面多一条，放“归档”按钮。卡片本身是个链接，按钮放在链接外面，两样共用一个框。点了在卡片上原地确认，说法和上面一样；归档完卡片挪进“已归档的房间”。“你加入的别人的房间”和已归档的没有这个按钮。
- 回滚到还要最近登录的控制面时，服务器回 `authentication.reauthentication_required`，界面照常说没成功、详情里带错误码；重新登录以后再点就行。只在回滚时碰得到，不另做“重新登录”的按钮。

### 网页：多选撤销（第 4 步）

- “已登录的电脑”一栏多一个“选几台撤销”，“Agent 连接”一栏多一个“选几个撤销”。打开的对话框列出这一栏还在用的每一项，默认都不勾；勾上以后点“撤销 N 个”，一项项撤，进度写在按钮上；没撤成的留在列表里、还勾着，可以再点一次。
- 原来的“7 天以上没用的一键撤销”保留，还是默认全勾。两种共用一个对话框。
- 网页认不出哪一台是正在用的这台电脑（见 CLAUDE.md），所以列表里有它；对话框里写一句：撤了正在用的这台，它的桌面端会断开、要重新授权。
- 单个撤销、多选撤销都不再先拦着请人重新登录。服务器回 `authentication.reauthentication_required` 时照旧给“重新登录”。

要动的文件都不在 `tools/release_acceptance.py` 的 `LOGIN_PATHS` 里，带它们的那一版不用为它们走新设备授权。`apps/control-plane/src/features/devices.rs` 的改动在控制面，不是 `crates/postgres-adapter/src/devices.rs`。

## 验收

- 第 2 步：控制面三个接口的路由测试只要求 `ActiveSession`；转让房主还要求 `RecentAuthentication`。
- 第 3 步：组件测试覆盖不是最近登录也能归档、要先确认、取消不归档、“房间”页只给自己当房主的卡片按钮；浏览器验收在 `lobby-scene.html?private` 和“房间”页的夹具上走一遍确认和取消。
- 第 4 步：组件测试覆盖多选、默认不勾、部分失败留着勾、没有最近登录也能撤；浏览器验收用 `my-agents.html?settings=security`（或 `security-center.html`）。
