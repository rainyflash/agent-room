# 新用户走到哪一步：设计

2026-11-08 维护者问还能怎么改善产品和用户体验。只读查了一遍生产（只数人数，没看是谁，也没看消息内容），最大的问题是新来的人很多停在半路、也不再回来，可不知道停在哪一步。维护者当天定了先做两件事：量清楚新用户卡在哪（这份设计），和邮箱验证卡住的那 11%（#764）。

这份文档说测什么、怎么测、怎么看。按步交付，进度记在最后的“状态”一节。

## 背景

2026-11-08 查的数（注册的 141 人，维护者自己的账户也在里面）：

| 走到哪一步 | 人数 |
| --- | ---: |
| 注册 | 141 |
| 验证了邮箱 | 126 |
| 进过应用 | 119 |
| 授权过电脑（装了桌面端） | 45 |
| 房间里来过 Agent | 约 56 |
| 自己说过话 | 59 |
| 最近 7 天说过话 | 31（其中 27 个是这周刚注册的） |

- 首发那周和下一周（10-19 到 11-01）进过应用的 59 人，到 11-08 这一周只有 3 个还在说话。
- 120 个私人房间里 112 个只有一个人；公开房间 11-04 上线后还没人建过。
- 30 天里 Agent 说了 8615 条，人说了 536 条。

从“进过应用”到“房间里来过 Agent”掉了一半多，可现在说不清是哪一种：

- 没打开“接入 Agent”对话框；
- 打开了没复制给 Agent 的话；
- 复制了，Agent 没进来（命令行和 MCP 要先装桌面端，网络接入要聊天助手能调用工具）；
- Agent 进来了，人没再说话。

这几样只有前三样需要新的数，后面的从已经存着的数据里就数得出来。

## 要回答的问题

1. 每一周注册的人，各走到了哪一步：验证邮箱、进应用、装桌面端、Agent 进房间、Agent 说话、自己说话、一周以后还来。
2. 进了应用、还没请来 Agent 的人，停在接入对话框的哪一步，三种接入方式各有多少人走通。
3. 改了某一步以后，下一周那一步的比例有没有变好。

## 不做的

- 不按人记：不新存“谁走到了哪一步”，也不给每个人记事件流水。数在出报告的那一刻从现有数据里数，只出人数。
- 不加第三方统计或跟踪脚本，网页的内容安全策略不放宽（和[测量设计](../measurement/design.md)一样）。
- 不量没登录的访客：官网、围观页、注册页本身照旧不报。注册页上的事由身份服务的库回答（注册、验证）。
- 报告里不出邮箱、名字、账户和房间的 ID、消息内容。
- 不做实时看板。每周看一次够用，人数还少，按天看全是噪音。

## 怎么做

### 1. 周报里加“新用户走到哪一步”（只用现有数据）

容量周报（`production.py capacity-report`，每周一开在 `agent-room-ops`）加一节。周报已经在服务器上跑，数据库都读得到。

按注册的那一周分组，列最近 6 周，每组一行：

| 列 | 怎么数 |
| --- | --- |
| 注册 | 身份服务的库：这一周建的账户（不算服务账号） |
| 验证了邮箱 | 同上，`email_verified` |
| 进过应用 | 控制面的库里有这个人（第一次登录应用时建） |
| 装了桌面端 | 授权过电脑（`device`，不算网络 Agent 的） |
| Agent 进了房间 | 他在的私人房间里进过任何 Agent（本机的或网络的），不算公共大厅 |
| Agent 说过话 | 这些房间里 Agent 发过消息 |
| 自己说过话 | 他自己在任何房间发过消息 |
| 一周以后还来 | 注册 7 天以后还用过：发过消息，或者网页登录续过期，或者电脑用过 |

- 网页登录用着就续期（一小时最多写一次），续的时候写的是新的到期时间，往回推 30 天就是最后一次用的时间（满一年那种封顶的不算）。电脑用 `device.last_seen_at`。
- “一周以后还来”只给注册满 7 天的那几组算，没满的写“—”。
- 每一列写人数和占“注册”的百分比，人数少于 5 的组不写百分比，免得一两个人把比例拉得很难看。
- 维护者自己的账户和发版验收用的长期设备都算在里面。人数还少，单独剔掉要认人，不剔。表下写一句。

数据从三个库读：身份服务（账户、验证）、控制面（人、电脑、房间、Agent）、Synapse（谁在哪个房间、谁发过消息，只看发件人和时间，不读内容）。报告在服务器上把这几样对起来，输出只有人数。

### 2. 网页和桌面端报接入对话框里的几步（只记次数）

只有前端知道的几步，由网页和桌面端报给控制面，控制面加计数：

| 步骤 | 什么时候报 |
| --- | --- |
| `invite_opened` | 打开“接入 Agent”对话框 |
| `invite_copied` | 点了复制给 Agent 的话或命令，带接入方式（`cli`、`mcp`、`network`） |
| `desktop_download` | 网页上点了“下载应用”（顶栏的、对话框里的） |
| `invite_arrived` | 对话框开着时认出 Agent 到了 |

- 新加 `POST /telemetry/onboarding`，请求只有 `step`、`method`（只有复制带）和 `surface`（`web` 或 `desktop`），要登录，和 `/telemetry/frontend` 一样只认自己的网页和桌面端的 Origin。
- 控制面只加一个计数 `agent_room_onboarding_steps_total{step,method,surface}`，不带账户、地区和别的标签。没开监控时收下就丢。
- 同一个浏览器里，每个账户每一步只报一次（复制按方式各一次）。记“报过了”的标记只在本机的 `localStorage`，不发出去。这样数到的大致是人数；换浏览器、清了数据会多算，周报里写明。
- 刚上线的那一周，老用户第一次打开对话框也会被数到，比例要从第二周起看。
- 周报那一节下面列这一周的四个数，复制按方式拆开。

### 3. 隐私说明页

第 1 步就改：说明页现在写着“除了上面按地区汇总的总数，不收集别的使用统计”。改成照实说：每周从已经存着的账户和房间数据里，按注册的那一周数一次有多少人走到了哪一步（验证邮箱、请来 Agent、说过话），只出人数、不读消息内容。第 2 步再加上接入对话框的几步只记次数、不带账户。顶上的日期和 [specs/privacy-page/design.md](../privacy-page/design.md) 一起改。

## 看了数以后怎么办

不在这份设计里定。先看两周（第 2 步上线后从第二周起），按停得最多的那一步再写设计，比如：

- 打开对话框的人少：新注册的人进来时直接给出对话框，或者房间里没 Agent 时把入口摆到正中间；
- 复制了 Agent 没进来：多半卡在装桌面端或聊天助手调不了工具，按方式看是哪一种；
- Agent 进来了人不说话、也不再来：那是留人的事，和“人不在时提醒他”一起想。

## 交付步骤

1. 这份设计。
2. 周报里加“新用户走到哪一步”（第 1 节），隐私说明页同一个 PR 改。只改工具和网页文字，随下一版发布；在那之前可以在服务器上手动跑一次不带 `--post` 的看看。
3. 网页和桌面端报接入对话框里的几步、控制面计数、周报列出来（第 2 节），隐私说明页同一个 PR 再改一句。
4. 第 3 步上线两周后看数，结论和下一步改什么记在“状态”一节。
