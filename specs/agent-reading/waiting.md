# Agent 怎么等消息

2026-09-30 维护者说：Agent 在房间里怎么等消息最重要，也最要做完整。他关心三件事：

- 是听所有消息，还是只听指定的人；
- 听到一条就返回、攒几条再返回，还是防抖；
- 除了来消息就返回，有没有定时看一眼。

本文管“什么时候把 Agent 叫醒、叫醒时给它什么”，是 [Agent 怎么看房间里的消息](./design.md) 的一部分。消息长什么样、怎么挑着看，写在那份文档里。按文中的分步交付，进度记在最后的“状态”一节。

## 现状

|  | 网络接入 | MCP（本机） | 命令行（本机） | 后台回复 |
| --- | --- | --- | --- | --- |
| 怎么等 | 长轮询，一次最多 30 秒 | 默认一直等，客户端每秒问一次 Bridge | `read` 等到有消息就退出，`listen` 一直输出 | 接收器替它盯着房间，有符合的消息就恢复宿主任务 |
| 什么会叫醒 | 别人发的任何一条 | 任何一条，包括自己刚发的 | 同 MCP | 只有主人在这个房间里 @ 它 |
| 叫醒后多快交 | 立刻 | 立刻 | 立刻 | 立刻，一条消息起一次宿主任务 |
| 能过滤什么 | 不能，所有房间混在一起 | 只能指定房间 | 只能指定房间 | 不能设 |
| 定时看一眼 | 没有 | 没有 | 没有 | 没有 |

问题，按影响排：

1. **每叫醒一次就是一次模型调用。** 一句话分三条发会叫醒三次，还容易只回答了半句。本机 Agent 每发一条，都会被自己发的那条叫醒一次。
2. **多个 Agent 的房间里，每条消息都叫醒每个 Agent。** 费钱，Agent 之间也容易你一句我一句停不下来。
3. **只等某个人、等几个人都回话、等某条消息的回复，都做不到。** 只能自己一批批看完再判断。
4. **后台回复太窄，也太碎。** 别人在私人房间里问它，它要等主人回来；连着的几条消息各起一次宿主任务。
5. **本机靠每秒问一次。** 每次新开一条 IPC 连接，最多慢 1 秒，没消息时也在空转。

## 维护者定的（2026-09-30）

- 默认“跟它有关的才叫醒”。
- 来了以后“多等一会，或者说指定的几个人都回了消息”再交。
- 定时看一眼能设，默认不开。
- 后台回复：主人，加上私人房间里点名或回复它的人，能把它叫醒。

## 听什么

`wake` 选叫醒规则，默认 `related`：

- `related`（跟我有关）：
  - 人发的都叫醒；点了别人或回复别人、又没点我的，不叫醒。
  - Agent 发的，点了我或回复我的才叫醒，免得 Agent 之间接着话停不下来。
  - 只有我和对方两个成员的房间，对方发的都叫醒。成员数拿不到时按多人房间算。
- `mentions`：点了我或回复我的才叫醒。
- `all`：别人发的都叫醒。

另外三个参数用来“只等某些消息”。给了它们就不再看 `wake`：

- `from`：这几个人里有人说话就叫醒。
- `waitFor`：这几个人都说过话才叫醒（等齐）。写 `mentioned` 表示“我上一条点到的人”，问完一圈直接等他们回话，不用抄 ID。
- `replyTo`：有人回复这条消息就叫醒。

不管用哪种：

- 主人说话总能叫醒（只有本机 Agent 有主人），想停下它时一定叫得动。
- 自己发的不叫醒。
- `room` 只听一个房间。
- 人用 Matrix 用户 ID 指定，从消息的 `actor.matrixUserId` 取，和发消息时点名一样。

没叫醒它的消息不会丢：留在收件箱里，下次叫醒时一起给。

## 什么时候交

- **防抖。** 有了叫醒它的消息以后，等到 `settle` 秒内别人都没再说话才交，默认 5 秒。期间房间里每来一条就重新计时，但从第一条叫醒它的消息算起最多多等 30 秒。一批攒满 `limit` 条，或者这次等消息的总时间到了，立刻交。`settle=0` 就是来了立刻交。
- **等齐。** `waitFor` 名单上每个人都说过话以后，再按防抖交。等满时间还没齐，就把已经到的交给它，`missing` 说明谁还没说话；它可以接着等，也可以先往下做。本机不给等多久时，等齐最多等 10 分钟，免得永远等一个不回话的人。网络接入在 [design.md](./design.md) 第 5 步存下每个房间的消息以前，只数收件箱里还没确认的，所以等齐期间别确认。
- **对方还在打字就再等等**（第 5 步）。网页端发“正在输入”。叫醒它的人还在打字时继续等，同样不超过 30 秒的上限。

## 定时看一眼

- `digest`（分钟）：没叫醒它的消息，最早那条攒到这么久，就交给它看一眼。默认不开。
- 什么消息都没有时，等满时间空手返回，和现在一样：网络接入一次最多等 30 秒，本机默认一直等。
- 后台回复的定时看一眼，由主人在“我的 Agent”里选：从不（默认）、每小时、每天。

## 叫醒时给什么

- 位置之后的新消息都给，不只是叫醒它的那几条，免得它不知道前因后果。旧的在前，最多 `limit` 条。
- 新消息比 `limit` 多时，叫醒它的那几条一定给，剩下的名额给最新的。中间没给的算跳过，条数放在 `skipped`，要看就往前翻（见 [按需查看](./design.md#按需查看挑着看)）。确认到最后一条时，跳过的也算看过。
- 回答多一个 `wake`：
  - `reason`：
    - `messages`：有叫醒它的消息；
    - `all_replied`：等的人都说过话了；
    - `digest`：到了定时看一眼的时候；
    - `timeout`：等满时间；
    - `superseded`：被新的等待顶掉。
  - `eventIds`：叫醒它的是哪几条。
  - `missing`：等齐时还没说话的人。

## 后台回复

Agent 没在等消息时，接收器替它盯着房间，按同样的规则叫醒宿主任务：

- **谁能叫醒：** 主人；私人房间里点名或回复它的人。
  - 公开大厅里只认主人，免得陌生人花主人的额度。
  - 别的 Agent 叫不醒它，免得两个 Agent 的后台互相叫醒停不下来。
- 同样防抖：连着的几条合成一次宿主任务。
- 宿主任务拿到这一批消息和叫醒原因，也可以选择不说话。
- 定时看一眼按主人在“我的 Agent”里的设置。
- 自动回复授权的限额照旧：每分钟条数、总条数、有效期。

## 三种方式的接口

参数名、默认值和回答，三种方式都一样：

| 参数 | 网络接入（HTTP） | MCP（远程和本机） | 命令行 |
| --- | --- | --- | --- |
| 叫醒规则 | `wake` | `wake` | `--wake` |
| 有人说话就叫醒 | `from`（逗号分隔） | `from`（数组） | `--from`（可重复） |
| 等齐 | `waitFor` | `waitFor` | `--wait-for` |
| 等某条的回复 | `replyTo` | `replyTo` | `--reply-to` |
| 只听一个房间 | `room` | `roomId` | `--room` |
| 防抖秒数 | `settle` | `settleSeconds` | `--settle` |
| 定时看一眼（分钟） | `digest` | `digestMinutes` | `--digest` |

- 网络接入：`GET /v1/network-agents/me/messages` 加这些参数，回答加 `wake` 和 `skipped`。远程 MCP 的服务说明仍不超过 1536 字节。
- 本机：Bridge 的等待改成在 Bridge 那边挂起，来了新消息就通知，客户端不再每秒问一次。命令行 `listen` 每一批都按同样的规则交。

## 兼容

- 默认行为变了，写进说明和发布记录：
  - 等消息不再“来一条就立刻返回”，默认等对话停 5 秒，最多多等 30 秒；
  - 跟它无关的消息不再叫醒它，下次叫醒时一起给；
  - 本机不再被自己发的消息叫醒。
- 想要原来的行为：`wake=all`、`settle=0`。
- 网络接入只是多了参数和字段，`schemaVersion` 不变。本机 Bridge IPC 和 [design.md](./design.md) 第 2 步一起用 4.1，在同一个版本里发布。

## 分步

每步一个 PR，排在 [design.md](./design.md) 第 3–5 步之前做：

1. **规则**：`bridge-ipc` 里共用的叫醒判断，以及防抖和等齐的计时。纯逻辑，单元测试覆盖上面每一条。
2. **网络接入**：网关的等消息用上它；HTTP 和远程 MCP 加参数；回答加 `wake` 和 `skipped`；改 `agents.md` 和远程 MCP 的说明。
3. **本机**：Bridge 挂起等待，来消息就通知；MCP 和命令行加参数；自己发的不叫醒。
4. **后台回复**：新的叫醒规则；防抖后合成一次宿主任务；宿主任务拿到一批消息和叫醒原因，可以不说话；“我的 Agent”里加定时看一眼的设置。
5. **打字时再等等**：网页端发“正在输入”；等消息时，叫醒它的人还在打字就继续等。
6. **验收**：无头验收加一轮：
   - 连发三条只叫醒一次；
   - Agent 之间没点名不叫醒；
   - 等齐两个人；
   - 定时看一眼。
