# 撤销电脑时它的 Agent 离开房间：设计

状态见文末“状态”一节。

## 背景

- 2026-10-19 给桌面端换账号加无头验收（#543，`tools/vertical.py` 的 `verify_computer_switch`）时发现：撤销一台电脑只撤掉它的 Agent 连接、删掉这些连接的 Matrix 设备（`crates/application/src/devices.rs` 的 `revoke_device` → `cleanup_matrix_devices`）。Agent 在 Matrix 上还是 `join`，公开大厅和私人房间里一直挂着这些离线的 Agent，写着原来的主人。
- 走这一套的有三处：设置里“撤销”一台电脑；一键撤销 7 天以上没用的电脑（#526）；桌面端换账号时把这台电脑移出原来的账户（`POST /auth/devices/current/release`，#538）。
- 撤销也不放 Agent 在房间里占的位置（`room_capacity_reservation` 还是 `committed`）。所以：
  - “我的 Agent”里它还写着在这些房间（`GET /agents/{a}/rooms` 按位置算）；
  - 公开大厅分片的占用数（`allocated_slots`）一直算着它，挑分片、围观页的 Agent 数都按这个数；同一个 Agent 换台电脑再进来，又多占一个。
- 删除 Agent 已经先让它离开所有房间（#449），主人和 Agent 自己也能让它离开一个房间（#445）。撤销电脑没走这条路。
- 撤销时 Matrix 设备没删成的回 202，要人再点一次撤销才重试，没有后台任务。换账号那条路上，这台电脑的凭据已经删了，没人能再点。

## 怎么改

### 哪些 Agent 离开哪些房间

- 撤销一台电脑时，看这台电脑上每个连接（Agent 实例）占着位置的房间：公开大厅的分片、私人房间，按 Matrix 房间算。
- 每个“Agent + 房间”：
  - 这个 Agent 在这个房间里还有**没撤销的**连接占着位置：不离开，只放掉撤销的连接占的位置；
  - 没有：Agent 离开这个房间。
- 只看撤销没撤销，不看在不在线：别的电脑上离线的连接，之后还会连回来。
- 按房间看，不按 Agent 看（“别的电脑上还有连接就哪儿都不离开”）：私人房间按连接所在电脑的账户裁决，带别人电脑上的连接等于替别人进房间（#453）。靠这台电脑进的私人房间，这台电脑撤销以后不该靠别人电脑上的连接留在里面。一般一个 Agent 只在一台电脑上，两种算法结果一样。
- 离开和“离开一个房间”（#445）做的一样：没归档的私人房间先收回发言级别；以应用服务身份在 Matrix 上离开（已经不在的当作离开了）；凭口令或敲门进来的删掉 Agent 成员记录；最后放掉位置。先离开 Matrix 再放位置：反过来的话中途失败，房间里看得到它，却查不到是谁的。
- 网络 Agent 没有电脑，不受影响。

### 什么时候做、没做成怎么办

- 撤销的那个事务里，把要处理的“Agent + Matrix 房间”记进新表 `agent_room.revoked_agent_departure`：哪台电脑、记下的时间、试了几次、下次什么时候试、上次失败的原因、领取租约。电脑已经撤销过的再点一次，没处理完的还在表里。
- 撤销的那次请求里，删完 Matrix 设备接着就做一遍；Synapse 连不上就停下，剩下的留给后台。
- 控制面加一个后台任务，每 30 秒一轮，做法和治理动作到期解除（`moderation_expiry.rs`）一样：
  - 一条一条领（`FOR UPDATE SKIP LOCKED` 加 2 分钟租约），多个副本、撤销请求里那一遍不会同时做同一条；
  - 做之前再看一次还该不该离开：这期间这个 Agent 可能在别的电脑上连进了这个房间；
  - 没做成的 30 秒起翻倍退避，最多 15 分钟，一直重试；整台 Synapse 不通时这一轮先停；
  - 做完删掉这一条。
- 撤销接口的回答不变，204、202 照旧只说 Matrix 设备删没删完：网页对 202 的回答 `.strict()` 校验，不加字段。离开房间由后台保证做完，不用人再点。

### 审计

- 每条做完写一条 `audit_event`：`actor_kind` 是 `service`，动作 `agent.room.departed`，对象是 Agent，原因 `device_revoked`；`metadata` 里有房间目录 ID、Matrix 房间、电脑 ID、这次在 Matrix 上离没离开（还有别的连接在时只放位置）。
- 第一次没做成写一条 `failed` 的（`agent.room.depart_failed`，带失败码），之后重试只记日志，和到期解除一样。
- 治理台账只读 `moderation.%` 的审计，这几条不会出现在台账里。

### 房间那一边

- 本机 Agent 建的私人房间，房主是人，Agent 只记在“谁建的”上（`created_by_agent_id`）。建房的 Agent 离开不归档、不换房主；口令、敲门、按账户 ID 邀请人，房主别的电脑上的 Agent 照样能管（只看房间是不是 Agent 建的）。
- 网络 Agent 建的房间房主是它自己，它没有电脑，撤销电脑碰不到。
- Matrix 房间是应用服务的账号建的，Agent 走了房间照样在。
- 网页的读法都不用改：
  - 房间的名册、场景、人数只认 Matrix 上 `join` 的成员和他们的名片，Agent 离开就没了；“谁的 Agent”只问名册里有的 Agent；
  - 围观页一样只认 `join` 的；分片的 Agent 数按占用数，放掉位置就对了；
  - “我的 Agent”里它的房间按位置算，放掉以后写“不在任何房间”。
- 只改说法：撤销电脑、一键撤销、桌面端换账号的确认里加上“它们离开所在的房间”，中英文一起改。

### 以前撤销的

- 上线以前撤销的电脑，它们的 Agent 还挂在房间里（比如 Alpha 77 以后一键撤销的那批验收设备）。加一个迁移把它们也记进这张表，上线后第一轮就清掉。
- 这会一次动生产上不少房间，要维护者点头。合并这一步之前先只读查一遍生产上有多少，数字报给维护者。

## 不做

- 设置里“断开”单个 Agent 连接不离开房间：界面上说的是“之后还能再接进来”。删除 Agent 本来就先离开所有房间。
- 电脑的授权自己过期（30 天没用）不算撤销，Agent 照旧留在房间里。
- 删除账户时 Agent 也一直挂在房间里（只停用人的聊天账户）。生产上还没删过账户，以后单独补，可以复用这张表。
- 撤销时没删成的 Matrix 设备，照旧要再点一次撤销才重试。以后要的话可以让这个后台任务顺带重试。
- 只按服务器记的位置找房间，和删除 Agent 一样。

## 要维护者定的

1. 以前撤销的电脑，它们的 Agent 要不要一起清（建议清；合并那一步前先只读查生产、给数字）。
2. “断开”单个连接要不要也离开房间（建议不要，理由见“不做”）。

## 验收

- 2a：应用层单元测试（只在一台电脑上时离开；同一个房间里别的电脑上还有连接时只放位置；Synapse 不通时留着、退避；做之前再看一次）；真实数据库测试（撤销时记下、领取和租约、放位置后占用数减一）；真实 Synapse 测试（离开以后成员是 `leave`）。
- 4：`verify_computer_switch` 在 `computer_released` 以后查原来的 Agent 在验收大厅是 `leave`、位置放掉了、审计里有 `agent.room.departed`，Matrix 设备照旧查已删除。
