# 桌面端自动更新：设计

2026-10-10 维护者说：Mac 上还是很老的版本，从来没弹出过让他更新的提醒。要把应用的自动更新做好。

本文写清现在为什么提醒不到人、改成什么样、怎么分步交付。实现以本文为准，做完一步回来更新“状态”一节。

## 为什么

### 现在怎么查更新

- Alpha 49（#122）起，网页层在页面加载完、拿到桌面端快照以后查一次（`use-desktop-runtime.ts`）。渠道按版本号定：带 `-` 的走 testing，其余走 stable。
- 查到新版本：窗口里的提示栈放一条“有新版本”，按钮把人带到“设置 → 这台电脑”，在那里再点“安装”。
- 查不到、出错都不说。设置页里看不到上次什么时候查的、查成没有。
- 安装：`installUpdate` 先 `prepareForUpdate()`（有没发出去的草稿就停下说明），再下载、核对长度和摘要、安装、重启（`release_updates.rs`）。

### 为什么提醒不到人

- **只在页面加载时查一次。** 关窗只是藏进托盘（`CloseRequested` 里 `hide`），应用和网页一直开着；开机自启以后可以一连开好几天。之后发的版本就再也查不到了。Mac 上点红色关闭按钮本来就不退出应用，更是这样。
- **查到了也只在窗口里说。** 窗口藏着时没人看得到；提示点过“稍后”或者错过了，也不会再出现。
- **Mac 上点程序坞图标打不开藏起来的窗口。** 桌面端没处理 macOS 的 `RunEvent::Reopen`，窗口藏着时点程序坞图标没反应，只能从菜单栏的托盘图标打开。窗口里的提示更难被看到。
- **出了错没人知道。** 清单过期、网络不通、签名不对，都悄悄吞掉。
- 2026-10-10 生产上还有 2 个 Agent 照旧版的方式续租（Synapse 访问日志里同步的超时是旧版的 30 秒，也不报在线状态），可能就是这台 Mac 上的。

## 目标

- 应用开着就定时查，不靠重启，也不靠人去点。
- 查到新版本，窗口藏着也知道：发一次系统通知；托盘菜单里一直有“更新到 X”。
- 一步到位：提示上直接“更新并重启”，不用再去设置页。
- 查不成时看得到原因：设置里写上次检查的时间和结果，出错把错误码收进“详情”；桌面端日志也记一笔。
- 不替人装：更新要重启桌面端和 Bridge，连着的 Agent 会断开一下，没发的草稿要先处理，所以由人点。

## 做法

### 原生层定时查

- `ReleaseUpdateRuntime` 起一个后台任务，自动检查都从这里发。结果存在内存里的“更新状态”：上次检查的时间，结果是已是最新、有新版本（版本号、序号、是不是回退），或者出错（错误码）。
- 渠道按这一版自己的版本号定，规则和现在网页层的一样。设置里手动选的渠道只用于手动检查。
- 什么时候查：
  - 启动后 30 秒查第一次，先让 Bridge 连上；
  - 之后每 4 小时一次。任务每 5 分钟醒一次，按墙上时间看离上次检查满没满 4 小时，所以电脑睡了一夜，醒来几分钟内就会查；
  - 窗口重新打开时（托盘“打开”、点程序坞图标、再启动一次应用），离上次检查超过 1 小时就马上查；
  - 正在下载安装时不查。
- 出错不加快重试：下一次照常 4 小时后，或者窗口打开时。手动检查不受限。
- 状态变了发事件 `desktop://update-status`；`desktop_runtime_snapshot` 也带上它（`updateStatus`），网页晚一步加载也拿得到。状态里记着这次走的渠道（`channel`），设置里只在选的渠道和它一样时写“上次检查”。
- 手动检查（设置里的按钮）走同一条路、更新同一份状态，只是渠道用设置里选的。
- 每次自动检查写一行日志：查到新版本记 info（带版本号），出错记 warn（带错误码），已是最新记 debug。

### 查到新版本以后

- **系统通知**：每个版本只发一次。发过的版本记在数据目录的 `update-notified` 里，重启以后同一个版本不再发。手动检查查到的、或者窗口正开在前台时只记下、不发：人已经看得到窗口里的提示。
  - 中文：标题“Agent Room 有新版本”，正文“0.1.0-alpha.68 可以安装了。打开 Agent Room，点“更新并重启”。”
  - English: “Agent Room update available” / “0.1.0-alpha.68 is ready to install. Open Agent Room and choose “Update and restart”.”
- **托盘菜单**多一项“更新到 0.1.0-alpha.68…”。点了打开窗口，再由网页走安装。原生层不直接装，免得绕过草稿的检查。
- **窗口里的提示**：标题“新版本 0.1.0-alpha.68 可以安装了”，按钮“更新并重启”（下载时按钮上显示进度），另一个是“稍后”。
  - “稍后”记住这个版本和时间（桌面端网页的本地存储），24 小时后再提醒；出了更新的版本马上提醒。从托盘菜单开始更新时，之前点的“稍后”作废，进度和结果都在这条提示里说。
  - 设置里的按钮也叫“更新并重启”，和通知里说的一样。
  - 在“设置 → 这台电脑”那一页不显示，那里有完整的更新一节。
- 安装还是原来那条路，不改。

### 程序坞图标

- 处理 `RunEvent::Reopen`：窗口藏着时点程序坞图标，把窗口拿出来，和托盘“打开”一样。

### 设置里看得到结果

- “这台电脑 → 应用更新”多一行：“上次检查：今天 14:05，已是最新版本”，或者“上次检查：今天 14:05，没查成”，没查成时“详情”里是错误码。自动检查和手动检查都算。
- 通道清单签名后 7 天过期（见 CLAUDE.md“发布”）。两次发版隔了一周以上时，检查会失败。给它单独一个错误码 `desktop.update.manifest_expired`，说法是“暂时查不到新版本，下次发版以后就好”，不当成故障。别的签名问题照旧是 `desktop.update.manifest_rejected`。

### Mac 上装不上的情况

- 应用没在“应用程序”文件夹里、被系统挪到只读路径上运行时（路径里有 `/AppTranslocation/`，2026-10-07 遇到过），更新换不了自己。
- 安装前先看路径，直接说“先把 Agent Room 拖进“应用程序”文件夹，再从那里打开”，错误码 `desktop.update.app_translocated`。查到新版本时就带上这句，免得点了才知道。

### 兼容

- 桌面端的网页跟着桌面端一起打包，原生层和网页层总是同一版，快照多一个字段不用照顾旧版。
- 已经装着的旧版（Alpha 67 及以前）照旧只在页面加载时查一次。要靠它们重启一次、或者手动“检查更新”，才能装上这一版；之后就是定时检查。发行说明里提醒一句。

## 不做

- 不自动安装，也不在退出时悄悄装。
- 不提前在后台下载：安装包 40–55 MB，点了以后有进度，几秒到几十秒。
- 不改通道清单 7 天过期的做法。
- 浏览器里的网页端照旧：页面有新版本时提示重新载入。

## 风险

- **系统通知被关掉。** 托盘菜单和窗口里的提示照样在。
- **查得太勤。** 每台电脑每 4 小时查两个小文件（签名清单和更新元数据），都在 GitHub 的发行资产上，碰不到限额。
- **托盘菜单要跟着语言和更新状态一起重建。** 改语言时用当时的更新状态重建，别把更新那一项丢了。

## 分步交付

1. **设计**（本文）。
2. **实现**：原生层和网页层在同一个 PR 里做，快照和事件两边要一起改。
   - 原生层：定时检查、更新状态、事件和快照字段、系统通知、托盘菜单项、`Reopen`、日志、两个新错误码；
   - 网页层：用原生给的状态，不再自己查；提示一步更新；设置里显示上次检查；
   - 浏览器验收：夹具 `my-agents.html` 能看到有新版本、没查成、清单过期、Mac 只读路径几种。
3. **发版后确认**：下一版发出以后，在维护者的 Mac 和 Windows 上看：开着不动，4 小时内收到通知；点“更新并重启”能装上。
