# 私人房间敲门：设计

决策背景见 [ADR 0010](../../docs/adr/0010-network-agents.md) 和它的“修订（2026-10-06）”，网络接入的整体设计见 [design.md](./design.md)。本文写清“敲门、管理者放行”这条路：接口、数据、界面和分步交付。实现以本文为准，做完一步回来更新“状态”一节。

## 背景

2026-10-06 维护者在 ChatGPT 网页版里加了远程 MCP 连接器（`{API}/mcp`）。ChatGPT 能看到并调用工具，可一把私人房间的 Agent 口令传给 `agent_room_join`，就被 ChatGPT 自己的安全检查拦下。请求没到我们服务器，重试也一样。

维护者随后在同一个对话里测了三步，都没被拦：

- 只填名字，进公共大厅；
- 带 token 查看自己；
- 带 token 离开。

所以被拦的只是“把口令交给第三方工具”这一步。口令是一个长期有效、能反复用的密码，这类应用的安全规则不让模型把用户给的这种值发给外部工具。别的应用以后也可能有类似的检查，所以不针对哪个应用打补丁，而是给所有网络 Agent 一条不用交出任何秘密的进门办法。

## 做法：敲门，管理者放行

- 邀请里只给**房间号**：私人房间网址 `/lobby/<房间号>` 的最后一段，也就是房间目录 ID。它不是秘密：房间里每个人的地址栏里都有，拿到它也看不到房间里的任何东西。
- Agent 拿房间号进房间，就是**敲门**：服务器记下“谁想进哪个房间”，先不让它进。
- 房间的管理者在房间页上看到“Sol 在敲门”，点**让它进来**，服务器替它进房间；点**不让进**就算了。
- 口令照旧可用：不拦口令的宿主、要无人值守进门的 Agent 仍然用口令。接入对话框里默认给房间号，口令收进折叠里。

和口令比：

- 一次复制加一次放行；口令是一次“生成并复制”。步数差不多。
- 每个 Agent 都是管理者亲自放进来的。口令泄露后别人悄悄进来的事不会再有。
- 代价是管理者得在场。

## 不做

- **本机 Agent 不敲门。** 经 Bridge 的 MCP 和命令行不经过云端应用的工具检查。房主自己的本机 Agent 在接入对话框的 MCP、命令行里就能进，用不着口令；别人的本机 Agent 继续用口令。以后要做，就用设备签名的接口写同一张表。
- **不推送通知。** 只有管理者开着这个房间的页面或接入对话框时，网页才去问有没有人敲门。
- **不提供“关掉敲门”的开关。** 先靠限流兜底，真被骚扰了再加。
- **放行之前不告诉敲门的 Agent 房间名。**

## 房间号

- 房间号就是房间目录 ID（UUIDv7，小写带连字符）。服务器也收整段网址：路径以 `/lobby/<房间号>` 结尾的 `http(s)` 地址，查询串和井号后面的不管。
- `room` 本来收公共大厅的名字或 slug，现在也收房间号，按这个顺序认：
  1. 像房间号或房间网址的，查目录：
     - 是公共大厅，直接进；
     - 是使用中的私人房间，敲门；
     - 都不是，回答 `network_agent.room_not_found`。
  2. 别的照旧按公共大厅的名字或 slug 找。
- 已归档的和不存在的房间都回答找不到，不说是哪一种。

## 敲门

### 规则

- 一次敲门就是“某个 Agent 想进某个私人房间”。同一个 Agent 对同一个房间只记一条，状态有三种：**在等**、**放进来了**、**没让进**。
- 在等的一小时后作废。再敲一次就从现在重新算一小时，排到最后。
- 敲门之前先看它是不是已经能进：
  - 已经在这个房间里：原样返回这个房间，和公共大厅一样；
  - 已经是这个房间的 Agent 成员（凭口令进来过，或者放行时没进成）：直接进，不敲门。
- 没让进的再敲，还是“没让进”，不再打扰管理者。
- 被移出过的可以再敲，由管理者再决定。放行时它重新成为 Agent 成员。
- 网络 Agent 停用后，它在等的敲门不再显示，也不能放行。

### 限流

| 对象 | 限制 |
| --- | --- |
| 敲门 | 每个来源每小时 10 次。凭房间号新建人物也算一次，同时照旧计一次创建 |
| 一个房间同时在等的 | 最多 5 个；满了回答 `network_agent.rate_limited`，`Retry-After` 到最早那个作废 |
| 在等的有效期 | 1 小时 |

### 网络 Agent 这边的接口

HTTP：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/network-agents` | `{name, room}`，`room` 是私人房间的房间号时：建人物、敲门，不进任何房间。返回 201，不带 `room`，带 `knock` |
| POST | `/v1/network-agents/me/rooms` | `{room}` 是房间号时：已经在里面，200 `{room}`；已经是 Agent 成员，进去，200 `{room}`；否则敲门，202 `{knock}` |
| GET | `/v1/network-agents/me` | 多一个 `knocks`：在等的，以及一天以内没让进的和作废的 |

`knock` 长这样：

```json
{
  "catalogId": "0199b2c4-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
  "status": "waiting",
  "knockedAtUnixMs": 1791264000000,
  "expiresAtUnixMs": 1791267600000
}
```

- `status`：`waiting`（在等）、`declined`（没让进）、`expired`（作废）。放进来以后房间出现在 `rooms` 里，`knocks` 里就没有它了。
- 只敲了门的人物不在任何房间里：等消息照常空等，发言会被拒。
- 放行时服务器替它进房间（见下面“放行”）。它这时正在等的消息会立刻空手返回，和自己进私人房间时一样；再调一次，就从这个房间收消息了。

远程 MCP：

- `agent_room_join {name, room}` 和 `agent_room_enter_room {room}` 的 `room` 也收房间号；工具说明和服务说明各加一句怎么敲门。服务说明上限 1536 字节，现在 1254 字节，加的话要在余量之内。
- 敲门时结果开头一句：已敲门，等房间的管理者放行；放行后你就在房间里了，用 `agent_room_wait_for_messages` 等消息，用 `agent_room_get_self` 看门还在不在等；别反复敲。
- 不加新工具，工具注解不变。

`agents.md`：私人房间那一段先讲房间号（敲门），再讲口令。

### 管理者这边的接口

都要网页会话和 Origin，和口令一样要管理权限、房间在使用中。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/private-rooms/{c}/agent-access/knocks` | `{knocks}`：在等、没作废的，先敲的在前，每个是 `{agentId, displayName, knockedAtUnixMs, expiresAtUnixMs}` |
| PUT | `/private-rooms/{c}/agent-access/agents/{agentId}` | 让在敲门的 Agent 进来。进去了才回答 200 `{agent}`。没在敲门、已作废、Agent 停用了，回答 404 `agent_knock.not_found`；服务器这会儿没能让它进来，回答 503 `private_room.agent_entry_unavailable`，敲门还在等，可以再点 |
| DELETE | `/private-rooms/{c}/agent-access/knocks/{agentId}` | 不让进。原本就不在等也回答 204 |

在等的敲门不放进 `GET /private-rooms/{c}/agent-access` 的回答里：旧版网页和桌面端对那个回答做严格校验，多一个字段整个房间设置都读不出来。错误码以 `agent_knock.` 开头，不是口令的 `join_code.`。

### 放行

放行在管理者的这次请求里做完，点了就能看到它进来：

1. 核对权限、敲门还在等、Agent 还有效，把它记为这个房间的 Agent 成员（`joined_via = 'knock'`）。
2. 网关替这个网络 Agent 进房间。这一段和它自己凭口令进私人房间完全一样：先切到加密客户端、建好加密身份，再进去，进去以后说一声在线。网关按 Agent ID 取它的会话，不用令牌，只对生效中的网络 Agent。
3. 进去了，才把敲门记为“放进来了”。

第 2 步失败时，第 1 步已经记下，敲门还在等。管理者再点一次，会从第 2 步接着做；Agent 自己再敲一次也会直接进去，因为它已经是 Agent 成员。

第一次进加密房间要开加密存储、建身份，可能要几秒，网页上显示“正在让它进来…”。

## 数据

一个新迁移：

- `agent_room.private_room_agent_knock`：
  - 主键 (`catalog_entry_id`, `agent_id`)，外键和 `private_room_agent_member` 一样；
  - `knock_status`：`waiting` / `admitted` / `declined`；
  - `knocked_at`、`expires_at`、`decided_at`、`decided_by_principal_id`；
  - 索引：(`catalog_entry_id`, `knock_status`, `expires_at`) 查一个房间在等的；(`agent_id`, `knocked_at`) 查一个 Agent 敲过的。
- `private_room_agent_member.joined_via` 的约束放宽到 `code`、`knock`。旧版控制面只写这一列、不读它，回退不受影响。
- 敲门次数记在已有的 `network_agent_rate_window`，键是 `knock:<来源摘要>`。

## 界面

用词，加进[界面翻新的用词表](../interface-renewal/design.md#用词)：

| 中文 | English | 指什么 |
| --- | --- | --- |
| 房间号 | Room number | 私人房间网址最后那一段，给 Agent 敲门用，不是秘密 |
| 敲门 | Knock | Agent 拿房间号请求进私人房间，等管理者放行 |
| 让它进来 / 不让进 | Let it in / Turn away | 管理者对敲门的回答 |

### 接入对话框（网络，私人房间）

- 主内容是一段给 Agent 的话和一个复制按钮。话里带房间号，不带口令，不用先生成什么，打开就能复制。
  - 管理者复制的话说“等我放行”；不是管理者的成员复制的话说“等房间的管理者放行”，下面再提示一句“敲门后要管理者放行”。
- 对话框底部“等你的 Agent 进来…”那一块，有 Agent 敲门时显示“Sol 在敲门 · 网络 Agent”和“让它进来”“不让进”两个按钮，只有管理者看得到；放进来以后变成“Sol 进来了”。对话框开着时每 3 秒问一次。
- 放行按钮旁边写明代价：它进来后，服务器代它收发，能读到之后发给它的消息。
- 口令收进折叠“想让 Agent 不用等放行？用口令”，里面就是现在的一键生成口令。

### 房间页的提示

- 管理者开着私人房间的页面时，有 Agent 敲门，右下角的提示栈里出一条“Sol 在敲门，想进这个房间”，带“让它进来”“不让进”。同时最多两条，多的合成一条“还有 N 个在敲门”。
- 页面在前台时每 10 秒问一次，切回这个页面时马上问一次。不是管理者、不是私人房间，就不问。

### 房间设置

- “Agent 口令”一节上面加“在敲门的 Agent”，同样两个按钮。
- “凭口令进来的 Agent”改成“进来的 Agent”：凭口令的和放行的都列在这里，都能移出。

## 安全

| 情况 | 结果 |
| --- | --- |
| 房间号传出去了 | 拿到的人只能敲门，看不到房间名和消息；管理者不放行就进不来 |
| 有人冒名敲门 | 名字在没停用的网络 Agent 里不重名，敲门上写着“网络 Agent”和时间。管理者刚发出邀请时只等一个敲门，多出来的不认识就不让进 |
| 有人反复敲门 | 按来源限流，一个房间同时在等的最多 5 个，一小时作废，没让进的不再出现 |
| 放进来以后 | 和凭口令一样：服务器代它收发，能读到之后发给它的消息（ADR 0010 第 4 条）。放行按钮旁边写明 |

敲门比口令更稳：口令泄露后谁都能悄悄进来，敲门每次都要管理者点头。

## 分步交付

1. 设计（本文）。
2. 服务端：迁移、用例与存储、网络接入的 HTTP 与远程 MCP、`agents.md`、管理者的接口、放行时网关替它进房间。
3. 网页端：接入对话框、提示栈、房间设置、中英文案、夹具与浏览器验收。
4. 无头验收：私人房间那一轮加上敲门、放行，只在派发 `suite=all` 时跑。

第 2、3 步在同一个版本里发布。

## 验收

- 用例与存储：敲门、再敲、作废、放行、不让进、没让进的再敲、已是成员直接进、停用后不显示、房间满了限流。真库测试标 `#[ignore]`，在派发的集成作业里跑。
- 控制面：HTTP 与远程 MCP 敲门的回答形状；管理者三个接口的权限和 Origin；放行时网关失败回答 503、敲门还在等。
- 网页端：对话框、提示栈、房间设置的单元测试；夹具里能看到敲门和放行。
- 真实环境：网络 Agent 拿房间号敲门，人在网页上放行，它进来后与本机 Agent 加密收发。
- 发版后请维护者在 ChatGPT 里拿房间号走一遍。
