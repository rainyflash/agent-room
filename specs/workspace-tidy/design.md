# 后台回复、已登录的电脑和房间未读：设计

状态见文末“状态”一节。

## 背景

2026-10-17 维护者看着桌面端说了三件事：

1. “我的 Agent”页“这台电脑”里“由哪台电脑回复”下面一大片卡片，“我都不知道是干嘛的”。
2. 设置里“已登录的电脑和 Agent”写着 20 台电脑、54 个 Agent，“我怎么可能登录了那么多电脑，这到底怎么算的”。
3. “房间”页每个房间应该写有多少未读、有没有人 @ 他。

查下来是这样。

### “由哪台电脑回复”

- 一张卡片是一条后台回复记录（`agent_room.reception_execution`），每个 Agent 在每个房间一条，记着现在由哪台电脑的哪个连接负责回复、停没停。
- 那一大片全是以前每版实机验收的“发布验收”Agent 在验收房间里开过的后台回复，都已停止。
- 服务端列这张表（`GET /receptions`，`crates/postgres-adapter/src/reception.rs`）只筛掉删了的 Agent，不看设备、连接撤没撤销；停止的记录也从来不删。
- 页面上同一份列表渲染了两遍：一份在“这台电脑”卡片里（`ThisComputerSection` → `ReceptionPanel` → `ReceptionOwnershipPanel embedded`），一份在页面正文里（`account-workspace-page.tsx` 的 `reception`）。正文那份没有宽度限制，铺满整个窗口。房间页是对的：本机连接服务在就只放卡片里那份。

### “已登录的电脑和 Agent”

- 真正的电脑只有两台：维护者 Windows 和 Mac 上的桌面端。其余十几台都是发版实机验收在维护者这台 Windows 上建的独立设备（“Alpha NN fresh-device acceptance”）：改过登录相关代码的版本，验收要从头授权一台新设备（`tools/release_qa.py` 的 `use_fresh_device`）。每台带着一个验收 Agent 的连接，所以 Agent 那一栏有 54 个。
- 列表什么都不筛（`list_for_principal`）：撤销了的、30 天没用授权已经过期的，都在里面，过期的照样写“已登录”（“已登录”只看 `trust_state = 'verified'`，过期记在令牌组上，接口不给）。
- “最近活动”一直是空的：`device.last_seen_at` 有这一列，接口也给，可从来没人写，所以每台都只写“注册于”。
- 验收工具用完从不撤销这些设备，也撤销不了：撤销电脑要最近登录过（`AuthenticationRequirement::RecentAuthentication`），验收工具没有维护者的最近登录。

### 房间未读和 @

- 房间（不算和 Agent 的私聊）不发已读回执，也没用过 Matrix 的未读计数。服务器的计数在这里本来也不准：消息是自定义事件类型，没有 `m.mentions`，私人房间是加密的。
- 收件箱已经有一份按房间记的“读到哪儿”（个人工作区文档里的 `read` 游标，同步到各设备），也已经会判断“这条点名了我”（`attentionKind`：点名我或 @所有人）。房间里的对话面板在你看到最新一条时往前推这个游标。
- 收件箱的房间清单（`GET /inbox`）带着每个房间的 Matrix 房间号，公开大厅的分片也在里面。
- 网页只同步每个房间最近的一段（首次同步每个房间 20 条），没打开过的房间更早的消息不在本机。

## 想要的样子

### 我的 Agent：后台回复

- “这台电脑”卡片里的后台回复列表只出现一次。网页端（没有本机连接服务）照旧只在正文里放一份。
- 正在回复、联系不上的照常列出来；已停止的收进“已停止 · N”，默认收起。
- 设备撤销了、或者连接撤销了的记录不再列出来。

### 已登录的电脑

- 每台电脑写“上次使用”：Bridge 换令牌时记一下（换令牌本来就要写令牌组那一行，顺手写设备那一行）。迁移按令牌组的到期时间往回推 30 天，补上已经有的设备。
- 分组，按这个顺序：
  1. 这台电脑；
  2. 最近 7 天用过的；
  3. 7 天以上没用的 · N，默认收起。30 天以上没用的写“已过期，要重新授权才能用”（授权连续 30 天不用就过期，和“上次使用”是同一个时间）。
  4. 已撤销的 · N，默认收起。
- “7 天以上没用的”一组有“全部撤销”：先弹一个对话框，列出这一组的每台电脑，默认都勾上，可以取消勾选，确认后一台台撤销（每台的 Agent 连接跟着撤销）。没有最近登录时先请你重新登录，和单台撤销一样。
- Agent 一栏：在线的照常列出来；不在线的收进“不在线 · N”；已断开的收进“已断开 · N”，都默认收起。

接口的回答不加字段、不加取值：网页对设备和连接的回答严格校验（`.strict()`、`trustState` 是固定的几个值），旧版桌面端多看到一样就整个读不出来。“上次使用”写进原来就有的 `lastSeenAtUnixMs`，“过期”由网页按它算。

维护者 2026-10-17 定了：现在攒下的验收设备由他在这里一键撤销，Alpha 74 那台长期验收设备和两个桌面端留着（对话框里取消勾选）。以后发版验收再建新设备，也在这里清。

### 房间页

- 私人房间的卡片写未读条数：读到的位置之后、别人发的消息（人和 Agent 都算），超过 99 写“99+”。本机只同步到读到的位置之后的一部分时，写“N+”（N 是本机有的条数）。
- 有人点名你、或 @所有人时，卡片上标 @。
- 公开大厅只标 @，不写条数（维护者 2026-10-17 定：大厅人多，条数很快就是 99+）。
- 读到的位置、“点名了我”都用收件箱那一套，不另起一套；在房间里看到最新一条以后回到房间页，这个房间就不再标。
- 还没有读到的位置的房间（从没打开过），只在有人点名你时标 @，不写条数，免得每个房间都写满一屏。

## 分步

1. 设计（本文）。
2. 后台回复：卡片里那份只出现一次，已停止的收起；服务端不列已撤销设备、已撤销连接上的记录。
3. 已登录的电脑和 Agent：
   - 3a 服务端：换令牌时写 `device.last_seen_at`，迁移补上已有设备。
   - 3b 网页：分组、一键撤销的对话框、Agent 一栏收起。
4. 房间页未读和 @。

每一步一个 PR，界面都中英文一起改、带浏览器验收。第 3a 和 3b 可以分开发布：3a 先上，旧版网页也能显示“最近活动”。

## 不做的

- 不自动替人撤销设备：撤销要最近登录过，也不该由服务器猜哪台不要了。
- 验收工具不改成复用同一把设备钥匙：新设备授权测的就是一台从没见过的电脑。
- 不删已停止的后台回复记录：它记着回复到了哪儿，换回这台电脑接手时要用。只是不显示撤销了的。
- 不改成 Matrix 的已读回执和未读计数：理由见“背景”。
