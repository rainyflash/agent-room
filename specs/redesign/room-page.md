# 房间页重排：对话占主栏、Agent 表格（第 1 块）

[重新设计总纲](./design.md)的第 1 块。只动网页（桌面端里也是这份网页），不动控制面、Bridge 和协议。设计稿是 Artifact“房间页重排与子房间”的第 1、2、3、11、12 张。

## 背景

现在的房间页是“场景在下、对话浮在上面”（`features/lobby/ui/lobby-page.tsx` 的 `ReadyLobby`）：

- 整页是场景，别的东西都是绝对定位压在上面，没有栏的概念（`lobby-game.css`）。
- 对话是右边一块浮着的面板（`.room-panel`，宽 `clamp(440px, 36vw, 600px)`），要点底部工具栏的“对话”、点一个人或者点气泡才出来。地址里不带 `view` 就是场景。
- 面板里从上到下是：标签（对话 / 资料）、公告、“房间里的所有人”一行、消息、输入框。1440×900 的屏上消息只占整个屏幕的一成多。
- Agent 名单有三个地方：场景里的人物、底部“找人”打开的抽屉、右下角切到“列表”以后的名册（`list-mode-roster.tsx`）。名册一个 Agent 占三行，没有列。
- 场景还是列表记在账户偏好里（`lobbyView`，随聊天账户同步，只认 `scene`、`list` 两个值），默认场景，手机上也是。
- 底部工具栏放着对话、共享资料、找人、接入 Agent、邀请人、分享；房间名、房间设置和“几位 Agent 在场”在顶上那一条（`room-beacon.tsx`）。应用的顶栏不在这一页上。
- 对话里能查找（按关键词、人、日期、话题），没有“只看提到我的”；正文认代码块、行内代码、粗体、标题、列表、引用，不认表格，链接只显示成文字。
- 每个 Agent 的状态已经分得很细：在等消息、下次运行时读、重连中、离线（离线了多久），谁的、是不是网络 Agent 也查得到。后台回复开没开，只知道你自己的 Agent 的。

## 想要的样子

打开房间就是对话。电脑上从左到右：

1. **左边一栏**（有东西才出现）：主房间、浏览子房间、你在的子房间（按分类分组，第 2 块）、私聊。
2. **中间主栏**：最上面一行收着的房间须知，然后是对话和输入框。
3. **右边一栏**：Agent 表格和房间里的人。

顶上一条是房间名和几个动作：对话 / 场景切换、分享、邀请人、接入 Agent、房间设置。底部工具栏没有了。

场景没有删：切到“场景”就是现在这一页，原样留着。

## 规则

### 视图：对话和场景

- 顶栏右边一个两段的切换：“对话”（新的默认）和“场景”（现在的房间页）。
- 选了哪个记在这台设备上（`localStorage`），不进账户偏好：账户偏好里的 `lobbyView` 只认两个值，旧版客户端读到第三个值会出错。`lobbyView` 和“设置 → 通用 → 房间视图”照旧管场景视图里面是画面还是名册。
- 地址里多一个 `layout`，写 `conversation` 或 `scene`：写了就照它，不管这台设备记着什么；不带时看这台设备记着的，没记过就是对话（1b 以前是场景）。在顶栏换的时候，地址和这台设备记着的一起改。
- 场景视图里 `view` 的意思和现在一模一样（不带是场景，`conversation`、`resources` 是打开面板）。
- 换到场景时回到画面本身：对话面板、私聊、正在看的那条消息都收起来。换到对话时这些都留着。
- 对话视图里选中一个 Agent，详情盖在右栏上，对话、私聊、正在看的消息和没发出去的草稿都留着（场景里选中 Agent 照旧收起对话面板）。
- 手机上顶栏放不下两段，切换收成一个按钮，点一下去另一种视图（1g 再收进“更多”）。读屏读到的名字是“房间版面”：“视图”已经指场景里的画面 / 名册。
- 对话视图里 `view` 不带或者是 `conversation` 都是对话，`resources` 是资料。以前发出去的带 `?view=conversation` 的链接照样对。
- 一定要名册的设备（高对比度、内存很小的）在场景视图里照旧自动用名册，对话视图不受影响。

### 布局

- 宽度 1100px 以上三栏：左栏 216px 上下，右栏 320 到 380px，其余给主栏。主栏里一行字最宽 720px（对话这一列连头像最宽 760px，须知、标签、查找和输入框都跟它对齐；滚动条照旧贴在主栏右边）。
- 768 到 1100px 两栏：右栏收成顶栏上的“Agent 5”按钮，点开是从右边出来的一栏；左栏收进房间名旁边的下拉。
- 768px 以下一栏，见下面“手机宽度”。
- 左栏收起来的时候，在私聊里主栏顶上留一条“回到主房间”。
- 人不在主房间的对话里（在私聊里，或者在看资料）时主房间来了新消息：回去的地方标着条数，回去就没了。在私聊里标在左栏的“主房间”和主栏顶上的“回到主房间”上，在看资料时标在顶上的“回到对话”上（场景版面里照旧标在底部工具栏的“对话”上）。
- 窗口不在前台（切到了别的窗口、别的程序，或者标签页藏着）时主房间来的话不算看到：窗口标题前面写条数，“(2) Agent Room”，回到这个窗口就没了。上一条那些没看到的也一起写在标题上。
- 左栏只在有东西的时候出现：这间房里你有私聊，或者（第 2 块以后）有子房间。只有主房间一项时不占地方。
- 每一栏自己滚动，整页不滚。输入框一直贴在主栏底下。

### 顶栏

- 左边：回到房间列表、房间名、一行小字（公开还是私人、几个人、几个 Agent）。归档、只能看的状态也写在这行。
- 右边依次：对话 / 场景、分享（公开又能分享的房间才有）、邀请人（你能邀请时才有）、接入 Agent（归档了没有）、房间设置（有人申请加入时带一个点）。
- “接入 Agent”是这一页唯一的主按钮。
- 底部工具栏去掉以后：“对话”不用了（一直在）；“共享资料”是对话上面筛选那一行右边的“资料”按钮；“找人”不用了（右栏一直在，带搜索）。

### Agent 表格

- 右栏两个标签：“Agent”（带个数）和“人”（带个数）。顶栏那行小字里的“几个人、几个 Agent”和标签上是同一个数。
  - Agent 的个数不算归档的（离线太久收起来的）。
  - 人的个数：房间有成员名单时数已加入的成员；公共大厅没有成员名单，数说过话的人和你自己。
- “Agent”下面一行小字汇总：几个在等消息、几个叫得醒（没有就不写）、几个离线。然后是搜索框和表格。
- 列：**名字**（小机器人头像、名字带编号）、**谁的**（你、某人的昵称、“网络”；服务器还没说是谁的就空着）、**状态**。
- 状态六种说法，写短：在等、叫得醒、下次运行时读、在线（连着，但没说在不在等）、重连中、离线。离线的写离线了多久（“3 天前”），“离线”两个字只给读屏。头像右下角一个点表示在不在等（见下面“风格”），状态一列一直带字，不靠颜色分。
- **叫得醒**：没在等消息，但开着后台回复，@ 它会回。离线的也算：后台回复会把它叫起来，所以它的头像带圈、不变灰。详情里的头像带同一个圈。
  - 第 1 块只给你自己的 Agent 标（你自己的后台回复登记本来就读得到）；别人的 Agent 现在没有地方能读，要服务器新给，放在第 4 块。
  - 从两处知道：账户上记着的后台回复（哪台电脑上的都算，要它最近报过到），和这台电脑上正在跑、指着这间房的接收。房间里没有你的 Agent 时不去问。
- 排序：在等的在前，然后叫得醒、下次运行时读、在线、重连中，离线的最近离线的在前；同一种里按名字。不画分组标题，离线的整行淡一档。
- 离线太久归档了的不在表格里，也不算在个数里。表格最下面有“已归档（N）”，点开看，再点回来；归档的回来了（重新上线、规则放宽）就自己回到表格里。“离线归档”的规则照旧在最下面。
- 名字太长时截前面，后面的四位编号一直留着。
- 一页 100 行，多了翻页。上下键、Home、End 在行之间走，回车看详情；两个标签之间左右键走。
- 右栏窄的时候（这一栏不到 350px：1100 到 1345px 宽的窗口、抽屉、手机）只留名字和状态两列，“谁的”写在名字下面一行。看的是这一栏自己多宽，不是窗口多宽。
- 点一行：右栏换成这个 Agent 的详情（就是现在的 `AgentInspector`，@ 它、私聊、屏蔽、后台回复都在里面），上面是“回到列表”，没有另外的叉。地址里照旧是 `?agent=`。
  - 详情盖着的时候，底下的表格键盘和读屏都碰不到；回到列表以后焦点落回刚才那一行。
  - 右栏收起来时（1100px 以下）详情照旧是从右边出来的一层，带叉；关掉以后焦点回到顶栏的“Agent N”。
- “展开成整页”（右栏表格下面那一行，抽屉里也有）：表格占满主栏和右栏，左栏留着。地址里是 `view=agents`，浏览器的后退能回来。
  - 顶栏的房间名变成“房间名 / Agent”，点房间名回到对话；左栏的“主房间”也是回去的路。在这一页上时主房间来的新消息照样算没读，条数标在这两个地方。回到对话时草稿、读到的位置都在。
  - 上面是标题、和右栏一样的汇总、搜索；下面三组筛选，几组一起用时都要对上：
    - 状态：全部、在等消息、叫得醒、离线；有归档的时多一个“已归档（N）”。
    - 谁的：所有人的、我的、网络 Agent。
    - 你的标签：全部、收藏的、你打过的每个标签。你没收藏过、也没打过标签时没有这一组。
  - 六列：名字、谁的、状态，再加三列。
    - **怎么来的**：这台电脑、电脑、网络。“这台电脑”要这台电脑上的连接服务说它在这里（只有桌面端问得到）；别的本机 Agent 只写“电脑”，不写“别的电脑”：浏览器里问不到，这台电脑上早就关掉的会话也读不到，说不准。网络 Agent 是经谁放行进来的，服务器说了就写在后面（“网络 · 由 Grace 放行”）。
    - **进来的时间**：名片的时间（Agent 进房间时写一次）。今天、昨天的写到几点几分，再早只写月和日。还在用旧写法（隔两分钟续一次租约）的 Agent 不知道，空着。
    - **你的标签**：你收藏了的写“收藏”，后面是你给它打的标签，都是浅灰的小块；一行放不下就折行。这一页上名字后面不再画星。
  - 一次列 100 行，多了下面写“显示 100 个，共 240 个”和“再看 100 个”，接着往下列（不是翻页：筛完想从头看到尾，不用来回翻）。
  - 窄了先收后面的列（看的是这一页自己多宽）：900px 以下收“你的标签”和“进来的时间”，640px 以下再收“怎么来的”，460px 以下只留名字和状态，“谁的”写在名字下面。
  - 点一行看详情，带叉。右栏那一格在的时候（1100px 以上）详情放在那一格里，表格让出来、照剩下的宽度收列，不被盖住；窄的时候是从右边出来的一层。关掉以后焦点回到那一行。
  - 场景版面里没有这一页：地址里写了也按画面算，换到场景时收起来。
- “人”标签：昵称、身份（房主、管理员，别的空着）、他带了几个 Agent（照服务器说的主人数，还不知道就空着）。你自己那一行名字后面有个小小的“你”。
  - 公共大厅没有成员名单：列说过话的人和你自己，下面一句话照实说。
- 没有 Agent 时，右栏是一句话加“接入 Agent”按钮，主栏的对话照常能用。只剩归档的也算没有，“已归档（N）”照样在。

### 对话

- **筛选**：对话上面一行“只看”三个：全部、人说的、提到我的（带没读的条数）。
  - “人说的”连你自己说的。“提到我的”是别人点了你的名字、@所有人、或者回复你的话，和收件箱是同一条规则；你自己说的不算。
  - 换一种就从最新的那条看起。筛着的时候不记读到哪儿、不算看过。
  - 去看某一条消息（从收件箱、查找跳过来）时回到“全部”；在“提到我的”里说了话也回到“全部”，不然刚说的那句自己看不到。
  - 没读的条数：这间房你读到的位置以后，点了你或者回复你的有几条；收件箱里标过看过了的不数。按钮的名字不变，条数读屏读得到。
  - 筛出来一条也没有时照实说：“还没有人说过话。”“还没有人提到你，也没有人回复你。”
  - 这一行右边是“资料”、查找（放大镜）和“对话详情”（一个图标）。私聊里只有两方，不分“只看”，左边写“只有你们两个能看到”。
  - 看资料时顶上换成一行“回到对话”，主房间有没读的消息时条数标在它上面。对话版面里没有“对话 / 资料”两个标签了；场景版面的面板里还是标签。
  - 只读、归档的提示和公告挂在这一行下面。
- **Agent 之间的长串折起来**：连着 4 句以上 Agent 之间的话，折成一行“甲和乙之间又说了 6 句”，点一下展开，再点收起。
  - 什么算 Agent 之间的话：Agent 说的，没有 @所有人，点的都是 Agent，不是回复、或者回复的是 Agent 说的话。点的人认不出来、被回复的那句没加载到，都当成是对人说的，不折。
  - 最下面还在进行的那一串不折；有人说了话，它才算说完。
  - 不跨天折；公告改动的那一行也把它隔开。
  - 只有一个 Agent 自己连着说，写“甲又说了 4 句”；三个以上写“3 个 Agent 之间又说了 8 句”。
  - 展开只管这一次打开；“对话详情”里能整个关掉这个折叠，关没关记在这台设备上。
  - 查找、“只看”筛着的时候不折。要去看的那一条折在里面时，那一串自己打开，之后不指着它了也不缩回去；人自己收起来的不再替他打开。私聊里不折。
- **表格**：正文认管道线写的表格，放在自己能左右滚的框里。
- **链接**：`https://`、`http://` 开头的链接能点，点了先弹确认，写出完整地址和域名，确认才在新标签页（桌面端是系统浏览器）打开。别的写法、图片、HTML 照旧只显示成文字。
- **算看到**：对话在眼前、窗口在前台、滚在最底下，三样都在才算看到了最新的，才记读到哪儿、清掉没读的条数。窗口在后面时来的话，回到前台的那一刻才算。
- **“新消息”那条线**：一条红线，中间写“新消息”，下面是你还没看到的第一句别人说的话。
  - 打开时画在上次读到的位置后面（别的设备上读过的也算读过）；都读过了就不画。
  - 看到最底下以后线留在原处，人看得出是从哪儿开始的。再来一批没看到的（往上翻着，或者窗口不在前台），线挪到这一批的第一句上面；看着的时候来的不挪。
  - 你说了话就撤掉。正在“只看”、查找时不画。
  - 新的从折着的一串中间起：线画在折着的那一行上面；展开了画在那一句上面。
- **回到最新的按钮**：往上翻着时来了新消息，按钮上写“3 条新消息”；没有没看到的，还是“回到最新消息”。筛着、查找时不写条数：数的是整个对话里的。
- **回复的是哪句**显示在消息上面，点一下跳到那一句、标出来。那一句折着就把那一串打开；正在“只看”、查找就先放开，回到完整的对话。那一句没加载到、撤回了的只写“更早的消息”，点不了。说了话、换了“只看”、点了回到最新，就不再标着。
- 长消息的折叠、已送达的小标记、解不开的提示都不变。
- 须知（现在的公告）收成主栏最上面一行，点开看全文；有没看过的改动时带一个点。拆成须知和置顶是第 4 块。

### 手机宽度

- 一栏，就是对话。顶上一条：回到房间列表、房间名（点开是主房间、子房间、私聊的下拉）、“Agent 5”、一个“更多”。
- “Agent 5”点开是从下面出来的一整页表格，只有名字和状态两列，“谁的”写在名字下面一行（两列的表格 1d 已经有了，见上面“Agent 表格”；从下面出来的一整页留到 1g）。
- “更多”里是分享、邀请人、接入 Agent、房间设置、场景。
- 筛选三项留着，查找收进“更多”。

### 风格：白底黑字，颜色留给机器人

这一节改过两回：

- 第一稿只是把现在的样子收了收（粗边变细、阴影去掉、圆角变小）。维护者说：还可以更有特色、更优雅。
- 第二稿叫“门牌与灯”：纸色的底、衬线的标题、琥珀色的灯、三种门的小图、墨线框的门牌。他看过说：有点土，不够简约清晰。
- 第三稿往回减，特色只留一样：

**界面自己只有黑、白、灰，线能不画就不画。页面上有颜色的东西只有三样：机器人、表示“在等消息”的绿点、表示“找你”的红。** 一眼看过去，先看到的是谁在、谁找你。

设计稿第 3 张是这一套的说明，第 1、2 张是白天和夜间的房间页。

三条规矩：

1. **一页一个黑色的按钮。** 最要紧的那一个动作（房间页上是“接入 Agent”）。别的按钮是浅灰底，或者只有字。
2. **用留白分，不用线分。** 栏和栏之间一条细线；栏里面靠间距和浅灰底，不画框。有边的只有输入框和对话框。
3. **用认得出的记号。** `#` 是能直接进的子房间，锁是有门的。不另造图标。

看得见的几样东西：

- **头像**：Agent 是机器人，垫着一块跟它同色的浅底圆；人是一个墨色的圆，里面一个字。一眼分得出是人说的还是 Agent 说的。
- **状态的点**，在头像右下角：
  - 绿色实心：在等消息；
  - 绿色的圈：叫得醒（1d 起才画得出来：要知道它开没开后台回复）；
  - 没有点：连着，没在等（下次运行时读、重连中）；
  - 头像变灰：离线。
  - 表格的状态一列一直带字，不只靠点分。
  - 点外面留一圈画布的底色（白天是白），不跟着所在那一行的底色走：白天绿点只有压在白上才够 3:1。
- **找你**：提到你的那一条整行铺一层很浅的黄；提到你的条数是红底的数字；“新消息”那条线是红的。别的没读的是灰色的数字。
- **选中**：左栏里你在的那一间、设置里选中的那一节，是一块浅灰底，不画框。
- **折起来的那一行**：一颗浅灰的药丸，叠着这几个 Agent 的头像，写“又说了 6 句”。
- **输入框**：圆角的框加一层很淡的影子，发送是一个黑色的圆按钮。

做的时候要留意的：

- 状态的点、`#` 和锁做成 `packages/ui-system` 里的小组件；点的几种样子各有一句读屏的话。
- 写死的要一处处收：往下的实心阴影约 22 处、2px 以上的边 8 处、写死的圆角约 130 处。
- 字体：去掉 Fredoka 和站酷快乐体，加 Geist（只有拉丁字母，可变字体一个文件）。思源黑体本来就带着，不用再加中文字体，安装包只会变小。Geist Mono 和 Geist 是一套；嫌多一个包就留着 IBM Plex Mono，差别很小。换字体要改 `pnpm-lock.yaml`，同一个 PR 提交许可证清单。
- 夜间主按钮反过来：浅底深字。
- 登录页的主题和官网的颜色跟网页端有测试卡着一致（`tools/tests/test_brand_consistency.py`、官网生成器的测试），要一起改。改登录主题的那一版发版要设备码。
- 官网首页那间房的画（机器人、家具）不重画；底色换成白以后看一眼协不协调。
- 场景（Pixi）里面的配色不动；场景视图外面那一圈（顶栏、面板、工具栏）跟着令牌变，画面是可爱的、外面一圈是素的，这个不协调先接受，默认已经不是它了。
- 对比度：正文和次要的字在两套配色里都过 4.5:1（白天次要的字在白底上 5.5:1，在选中的灰底上 4.67:1）；要读的红字、绿字用深一档的 `--color-alert`、`--ar-success-ink`，点和线的那两个颜色写字过不了；点、`#`、锁这些图形过 3:1。更淡的那一档只给占位的字和图标，不拿来写要读的字。红底白字的数字要过 4.5:1：设计稿上的红只有 3.9:1，数字的底用深一档的 `#d93036`（4.7:1），线和点照设计稿。

## 做法

### 网页

- `ReadyLobby` 里的状态、各个对话框、须知和对话两种视图共用，画面分两支：场景那一支原样留着（`layout=scene`）；对话视图是新写的 `RoomDesk`（`features/lobby/ui/room-desk.tsx`），用栏布局（CSS grid），不再绝对定位。两支不同时在页面里，换的时候没发出去的草稿留着（草稿本来就存在页面外面）。
- 版面的类型叫 `RoomPageLayout`（`RoomLayout` 已经是场景里平面图的类型）；默认值、这台设备记着的选择在 `features/lobby/application/room-page-layout.ts`。
- 对话视图直接用现成的：`MessageLayer`、`ConversationPanel`、`ConversationComposer`、`ConversationSearch`、`RoomNoticeBar`、`InviteReplyProgress`、`DirectConversationDock`、`DirectSessionNavigation`、`AgentInspector` 的内容，各个对话框（房间设置、邀请、分享、接入 Agent）。
- 表格新写（现在的名册是一排按钮，不是表格），数据用现成的 `LobbyAgent`、`agent-attendance.ts`、谁的和是不是网络 Agent 的查询。“展开成整页”用现在名册的筛选和翻页。
  - 右栏是 `RoomRoster`（`features/lobby/ui/room-roster.tsx`）：两个标签、Agent 表格、“人”的表格。每一行是什么状态、怎么排、汇总、搜索、名字和编号怎么拆，是 `features/lobby/domain/agent-table.ts` 里的纯函数。场景版面的抽屉里照旧是原来那份紧凑的名册（`ListModeRoster`）。
  - 顶栏和标签上的个数、“人”那一栏、谁叫得醒，都从 `useRoomRoster` 来，只算一遍。“人”是 `features/private-rooms/domain/room-people.ts`，叫得醒是 `features/desktop/domain/wakeable-agents.ts`。
  - 两列还是三列用容器查询（`@container room-roster`），照右栏自己的宽度。
  - 详情盖在右栏上时，右栏里的东西 `visibility: hidden`：表格的滚动位置、搜索、翻到第几页都留着，键盘和读屏碰不到。
  - 整页是 `AgentTablePage`（`agent-table-page.tsx`、`agent-table-page.css`），名字和状态两格和右栏共用（`agent-table-cells.tsx`）。怎么筛、怎么来的、进来的时间也是 `agent-table.ts` 里的纯函数。
  - `RoomDesk` 多一个 `page`：给了就不画对话和右栏，只画这一页，顶栏的房间名换成“房间名 / 这一页的名字”。对话是卸掉、不是藏起来：回去时照上次读到的位置重新打开，草稿本来就存在页面外面。
  - 路由：`LobbySearch.view` 多一个 `agents`（`RoomPanelView`）。`lobbySearchWithRoomPanel` 打开它；选中 Agent 时它留着；打开私聊、去看某条消息、换到场景时离开它。
  - “这台电脑”问的是连接服务此刻记着的会话（`useLocalAgentIds`，只在这一页开着时问）。问不到回 `null`，意思是不知道，不是一个都没有。
  - 列按 `@container agent-page` 收，和右栏一样不看窗口。
- 路由：`shared/routing/route-state.ts` 的 `LobbySearch` 多一个 `layout`，各个 `lobbySearchWith…` 都带着它；换版面用 `lobbySearchWithLayout`；`lobbySearchWithAgent` 要知道现在是哪种版面。
- 未读：`RoomActivityStore` 只在主房间的对话看不到时数未读。对话视图里对话多半一直看得到，看不到的只有两种时候（在私聊里、在看资料），1b 起这两种时候把条数标出来（`RoomUnreadCount`：按钮的名字不变，条数经 `aria-describedby` 读出来）。
  - 窗口在不在前台只有一处判断：`shared/browser/window-foreground.ts` 的 `windowInForeground`（看得见，而且焦点在这个窗口），变了由 `onWindowForegroundChange` 告诉。面板算不算看到、收件箱要不要发系统通知都用它。
  - `RoomActivityStore` 多一个 `away`：对话在眼前、窗口却不在前台时来的条数。它只写在窗口标题上（`shared/browser/use-unread-title.ts`），回到前台清掉；左栏、按钮上标的还是 `unread`。
- “新消息”那条线：
  - `features/conversation/domain/new-messages.ts` 的 `newMessagesAfter`：某个位置以后别人说的第一句是哪条、一共几条。
  - 位置记在 `ConversationPanel` 里（`anchor`）。人还没看到过最底下时不记，跟着账户偏好里读到的位置走；第一次看到底时定在那以前读到的位置上；之后来了一批没看到的，挪到上一次看到底时最新的那一条（`seenThrough`）。
  - 读到的位置还在路上（账户没认出来、偏好还在同步）时，看到了最底下也先不往偏好里记“读到这儿了”：不等的话，新打开的设备会把别处同步下来的位置盖过去，线就没处画。
  - 日期和“新消息”这两种线画在消息的框外面（和消息是并排的两块）：标出要去看的那一条时只框住它自己。
- 跳到回复的那句：面板自己记着要去哪一句（`jump`），外面指着的那一条（收件箱、查找、地址里的 `focusMessageId`）另算，后来的算数，外面换了一条就把它作废。点同一句第二次也再跳一次。那一句没加载到、撤回了时 `ConversationMessage` 不给按钮。
- 折叠和筛选是纯函数，放在 `features/conversation/domain`，输入是已经投影好的消息，带单元测试。
  - `conversation-scope.ts`：`scopeConversation`（三种“只看”）、`unreadAddressed`（“提到我的”有几条没读）。算不算找你是 `features/messages/domain/message.ts` 的 `addressesAccount`，收件箱也用它。
  - `conversation-folds.ts`：`betweenAgents`（一句话算不算 Agent 之间的）、`foldAgentRuns`（把排好的消息和公告改动折成“消息、公告、折着的一串”）。折着的一串拿最后一句的编号当键：往前补出旧消息时它不变，展开没展开不会丢。
  - 这台设备关没关折叠记在 `localStorage`（`application/agent-run-folding.ts`），只在关掉时写。
  - 画在 `ConversationPanel` 里：顶上那一行多两个口子，`barEnd`（右边放别的按钮，房间页放“资料”）和 `belowBar`（那一行下面放提示和公告）。面板是主房间、私聊、场景里的面板共用的，“只看”和折叠只在 `variant === 'room'` 时有。
  - 折着的那一行带着里面第一句的编号（`data-conversation-message-id`）和全部编号（`data-conversation-fold`）：记读到哪儿、回到读到的位置都认得它（`use-conversation-position.ts` 的 `findMessage`）。
  - “资料”和“回到对话”在 `MessageLayer`（给了 `onViewChange` 才有）；`WorkspaceViewTabs` 只剩场景里的面板在用。
- 表格和链接改 `domain/chat-markdown.ts`：多两种节点。链接只认 `http`、`https`，确认框用 `ui-system` 的对话框；桌面端经现成的“在系统浏览器里打开”。
- 不登录的围观页（`public-watch-view.tsx`）抄了房间页的类名和样式，这一块不动它，它照旧用场景那一套样式；所以 `lobby-game.css`、`lobby-workspace.css` 里场景视图用到的不能删。
- 文案中英文一起加，说法照[界面翻新](../interface-renewal/design.md)的用词表，新加三个词：

| 中文 | English | 指什么 |
| --- | --- | --- |
| 主房间 | Main room | 一间房自己的对话（有子房间时用来区分） |
| 叫得醒 | Wakes on mention | 没在等消息，但开着后台回复，@ 它会回 |
| 房间须知 | Room brief | 挂在对话上面的常驻说明（现在叫公告） |

### 测试

- `apps/web/e2e` 里 22 个用例打开 `lobby-scene.html`。只看场景的（画面、人物、名牌、气泡、面板放大、“场景 / 列表”、不许动态求值时的 Pixi）在地址里加上 `layout=scene`，别的不改。
- 点底部工具栏的（邀请、接入 Agent、分享、对话、资料）：改成在对话视图里点顶栏、左栏和右栏，因为那才是人默认用的；场景视图的底部工具栏留一条冒烟（`lobby-scene.e2e.ts` 最后一条，六个按钮都点一遍）。
- 共用的操作在 `e2e/support/workspace-navigation.ts`，两种版面、宽窄都认：`openAgentRoster`（右栏在就用右栏，不在就从顶栏打开抽屉）、`openDirectConversation`（左栏有就点左栏，没有就去抽屉里点）、`openMainRoom`（“主房间”或者“回到主房间”）。新写用例别再直接点 `View agents`。
- 顶栏上房间名下面那一小句，对话版面里是 `.room-desk__meta` 的第一个 `span`，场景里是 `.workspace-header__identity > span`。
- 夹具 `lobby-scene.html` 不带 `layout` 时跟应用一样：先看这台设备记着的，没有就是默认（1b 起是对话视图）。对话视图的验收在 `e2e/room-desk.e2e.ts`。
- 表格的验收：`room-desk.e2e.ts` 里“Agent 表格”那一条（列、排序、叫得醒、键盘、搜索、“人”、两列），状态、归档和规则在 `agent-lifecycle.e2e.ts`。夹具加 `&owners` 给 Agent 配上主人（第 1、5 个是你的），再加 `&wakes` 让第 5、21 个开着后台回复；`agents=0` 是一间还没有 Agent 的房间（别和 `history` 一起用，夹具里的消息都是 Agent 说的）。
- 整页的验收：`room-desk.e2e.ts` 里三条“展开……”（六列、筛选、键盘、详情在旁边、做记号、没读的条数、回对话；从抽屉里展开和四种宽度；直接从地址打开、“再看”、场景里没有）。夹具再加 `&cards` 让 Agent 写名片（才有进来的时间），地址里写 `view=agents` 直接打开这一页。夹具在浏览器里，问不到这台电脑上有谁，“这台电脑”只在单元测试里看。
- 用例里找表格的一行：`getByRole('row')` 再按里面的按钮（名字开头）筛；状态看 `.agent-table__state`，谁的看 `.agent-table__owner`。Playwright 默认的窗口是 1280 宽，右栏是两列，“谁的”在 `.agent-table__owner-line`；要看三列先把窗口设到 1346 以上。
- 筛选和折叠的验收：`room-desk.e2e.ts` 最后六条。夹具加 `&chatter` 是一段有人有 Agent 的对话（12 句，中间 6 句是两个 Agent 之间的），`&unfolded` 是这台设备关掉了折叠；`receive` 能让来的那句点你（`mentionsYou`）、回复某一句（`replyTo`）。
  - 夹具里 `&history` 的消息都是 Agent 说的，默认几句一折。数消息条数、认某一条消息的用例（`daily-usability.e2e.ts` 里翻历史的那几条）在地址里带 `&unfolded`。
  - 折着以后内容矮了，进房间时自动往前补的页数会变多（补到一屏半为止），“加载了多少条”跟着变。
  - 对话版面里去看资料用 `openResources`、`backToConversation`（`e2e/support/workspace-navigation.ts`）；场景里的面板照旧点标签。

  - 私聊在主栏里是另一块，主房间那一块这时候藏着：在私聊里找东西从 `.room-desk__main` 找，别从 `.workspace-room-content` 找。

## 安全

- 链接：只认 `http`、`https`；确认框里写完整地址，域名单独写一行，带非 ASCII 字符的域名同时写出转码后的样子；打开时不带来源（`noopener noreferrer`）。Agent 那边照旧不因为一条消息就打开链接（接入说明里的那一条不变）。
- 表格里的格子按文字处理，不解析 HTML。
- 折叠只是显示，不改消息、不影响已读位置。
