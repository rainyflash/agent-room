# 提醒：把人叫回房间（第 4 块的前一半）

[总纲](./design.md)第 4 块里“提醒”这一半。“须知与置顶”是另一半，轮到它时另写一份。

## 为什么先做它

- 2026-11-16 第一份漏斗周报（`agent-room-ops` 的容量周报）按注册那一周数：
  - 10-26 那周注册 54 人：89% 进过应用，43% 的 Agent 进了房间，6% 一周后还来；
  - 11-02 那周注册 72 人：82% 进过应用，42% 的 Agent 进了房间，7% 一周后还来。
- 人进得来，Agent 也接上了四成，可过了一周几乎没人回来。第 3 块（项目房间）是带新人来的，留不住的话来多少走多少。所以第 4 块排到第 3 块前面，第 4 块里先做提醒。
- 现在人怎么知道房间里有人找他：
  - 网页没有通知，只有页面里的提示；
  - 桌面端只在应用开着、窗口不在前台时弹系统通知；
  - 关了应用就什么都收不到，也没有邮件。

## 想要的样子

三样，从小到大：

1. 网页开着、标签页不在前面时，和桌面端一样弹系统通知。
2. 关了应用、房间里有人说了话他还没看时，每天最多一封邮件，写哪几间房有新消息，点一下回到房间。
3. 接入 Agent 时默认把后台回复开上：人走了，Agent 照样回话，房间不死。

## 网页通知

- 什么时候弹，照桌面端现在的规则（`inbox/ui/inbox-notice.tsx`、`inbox/domain/inbox.ts` 的 `notificationAllowed`）：
  - 提到你、回复你、私聊里的话、交接；
  - 没读、房间没开免打扰、没在“暂停提醒”；
  - 两分钟以内的；
  - 标签页在后台或者窗口没有焦点。
- 写什么也照桌面端（`systemNotificationSummary`）：在这台设备上解开、在这台设备上弹，不经过服务器。
- 点通知回到那间房、那一条。
- 浏览器要人点一下才肯给权限：
  - 设置“通用”里加“网页通知”开关，第一次打开时问浏览器；
  - 第一次有人提到你、回复你、私聊你，你又还没开过网页通知时，提示栈里问一句要不要在后台也提醒你，只问一次（答过就不再问，记在本机）；
  - 浏览器拒了就照实说，告诉人去浏览器的网站设置里改；浏览器没有网页通知（iPhone 上没加到主屏幕的网页）也照实说。
- 开关和权限都是每个浏览器自己的，不同步。桌面端不变，它已经有了。

## 关掉网页以后的推送（这一轮不做）

- 要做的话：
  - Web Push 要改 service worker（现在是 Workbox 生成的，得换成 `injectManifest`）；
  - 要一对 VAPID 钥匙；
  - 通知要经浏览器厂商的推送服务（Google、Mozilla、Apple）转，隐私说明页要加；
  - iPhone 上还得先把网页加到主屏幕。
- 加密的房间里服务器不知道谁被提到了，推送也只能说“有新消息”，和邮件差不多。
- 先看邮件管不管用，再定要不要做。

## 邮件提醒

### 什么时候发

每小时一轮。轮到一个人时，这几条都满足才发：

- 他开着邮件提醒，邮箱验证过；
- 离他上一封提醒满 24 小时（从没收过的不限）；
- 有该提醒的消息（下一节），而且最早的一条已经过了 1 小时：给他时间自己看到；
- 不在“暂停提醒”里。暂停结束以后，只说结束以后来的。

每封只说上一封之后来的，已经提醒过的不再说。

### 哪些消息该提醒

- 他此刻在里面的房间：私人房间、子房间、私聊、公开房间。不算公共大厅。
- 别人发的，在他读到的位置之后。人和 Agent 发的都算，他自己的 Agent 发的也算：它替他回了谁，他该知道。
- 开了免打扰的房间不算。
- 加密的房间（私人房间、子房间、私聊）：每一条都算。
  - 这些房间人少，每一条都是说给屋里的人听的；
  - 服务器也读不到内容，分不出提到了谁。
- 不加密的房间（公开房间）：只算点了他名字的，也就是消息里 `conversation.mentions` 有他的 Matrix ID。公开房间人多话多，每条都算的话他天天都会收到。
- 读到的位置、免打扰、暂停提醒都已经存在聊天服务器上他自己的账户数据里（`io.github.rainyflash.agentroom.personal-workspace.v1`）。
  - 控制面以应用服务替他读：应用服务的命名空间覆盖所有本地用户，是 ADR 0011 加的。
  - 不另存一份。
- 网页还没给某间房写过读到的位置时，从他进这间房的时候算起。

### 怎么算

每小时一轮，按账户分批（每批 50 个）：

- 候选：还在用、不是网络 Agent 的账户，邮件开关开着（没有那一行算开着）。邮箱验没验证，到发信那一步从身份服务读邮箱时再看。
- 对每个账户：
  1. 以应用服务替他读个人工作区（`personal-workspace.v1`）。用到的有三样：
     - 每间房读到的位置：按 Matrix 房间 ID 记，是那条事件的时间和 ID；
     - 免打扰的房间；
     - 暂停提醒：`0` 是没暂停，数字是暂停到那一刻，`null` 是一直暂停。
     - 没写过（404）就当什么都没有。
  2. 从库里列他在的房间：已加入、还在用的私人房间和子房间，没屏蔽、还在用的私聊；不算公共大厅和归档了的。每间带 Matrix 房间 ID、加没加密、他什么时候进来的。
  3. 每间房从哪一刻算起：读到的位置、上一封说到的那一刻（`covered_until`）、他进来的时候、暂停结束的时候、7 天前，取最晚的那个。
     - 7 天是这一步加的：从没打开过网页的人，第一封不说一个月前的事。
  4. 替他读那以后的消息（`/messages`，从新往旧翻，每页 100 条，最多两页，再多的照“200 条以上”算）：
     - 加密的房间看 `m.room.encrypted`；
     - 不加密的看消息预览事件，只留 `conversation.mentions` 里有他的；
     - 不算他自己发的；
     - 某一间读不了（比如 Matrix 上他还只是受邀）就跳过这一间，不算这个账户失败。
- 发不发照上面“什么时候发”。
- 每封说到哪一刻（`covered_until`）记成算的那一刻。

### 写什么

- 标题：“备份改造”里有 12 条新消息，几间房时写“3 个房间有新消息”。
- 正文：
  - 最多 5 间房，按新消息多少排，每间一行：房间名、几条新消息（公开房间写“有人提到了你”）。子房间写“父房间 / 子房间”，私聊写“和 Lin 的私聊”：对方的名字就是这间房的名字。点房间名直接打开那间房，多的写“还有 N 间”。
  - 一个“打开 Agent Room”按钮。
- 不写消息内容，不写谁说的：加密的房间服务器本来就读不到，邮件还要经发信服务商的手。
- 最底下三样：
  - 为什么收到：“你开着邮件提醒，每天最多一封，只在有人说话你还没看时发”；
  - 去设置里改的链接；
  - 一键退订。
- 语言照他在应用里选的（`preferences.v1` 的语言）；没选过的照注册时的（身份服务里用户的 `locale`）；都没有的用英文。
- 纯文本和 HTML 各一份，HTML 照网页“白底黑字”的样子，不放图。

### 默认开着

- 新注册的人和已有的人都默认开着。要叫回来的，正是不再打开应用、也不会去设置里找开关的人。每天最多一封，只在真有人说了话时发，每封都能一键退订。
- 第一封开头多一句：这是新加的提醒，不想收的点这里。
- 这一条要维护者看过再打开：发信那一步（4R-5）上线时，部署配置里的开关默认关着，维护者给了控制面发信的凭据、点了头才打开。

### 退订

- 每封都带 `List-Unsubscribe` 和 `List-Unsubscribe-Post: List-Unsubscribe=One-Click`（RFC 8058）：邮箱客户端自己的“退订”按钮直接发 POST，点了就退。
- 正文里的退订链接打开是控制面出的一页，上面一个按钮“不再发提醒邮件”，点了才退。不在 GET 上退：邮箱的链接扫描会先点一遍（见 CLAUDE.md 验证邮件那一条）。
- 链接里是签过名的令牌（账户 ID 加用途），不用登录。
  - 签名用一把新的钥匙（HMAC-SHA256，至少 32 字节），部署时生成，放在 `secrets/` 下，和网络 Agent 的封存钥匙一样；
  - 令牌不过期，可以反复用：退了以后再点还是“已经退了”；
  - 没配钥匙时（4R-5 以前的生产、自己搭的服务器）退订链接一律当作用不了。
- 退订页由控制面出（`/reminders/unsubscribe`），样式用分享页那一份（`/r/_/share.css`），自带内容安全策略：只许同源的样式和同源的表单，不许脚本。按来源限流，和分享页一样。
  - 邮件里的链接放在裸域上，和分享页一样经 Caddy 转给控制面。裸域的内容安全策略写着 `form-action 'none'`，这一路要放开成 `'self'`；Caddy 这一条随 4R-5 一起加，4R-3 时只在控制面上。
- 退了以后，设置里显示关着，能再打开。

### 怎么发

- 控制面自己发。现在只有身份服务发信，控制面一封都不发。
  - 走 SMTP，发信服务商和身份服务一样（Resend）。
  - 部署配置加 `reminders.email`：开关、SMTP 地址、用户名、发件人；密码是一个新的 secret 文件。
  - `compose.yaml` 里新的变量先带默认值、默认关（见 CLAUDE.md“发布”一节 Alpha 73 那一条）。
- 邮箱从身份服务读：用控制面已有的 `agent-room-account-admin` 客户端，它的 `manage-users` 包含读用户。只发给 `emailVerified` 的。
- 发信失败时：
  - 这一轮不算发过，下一轮再试；
  - 记 `reminder.email_failed`，加指标 `agent_room_reminder_emails_total{result}`；
  - 连着失败就告警，和身份服务的“发信失败”一样开成 `agent-room-ops` 的 issue。
- 量：现在两百多个账户，每人每天最多一封。CLAUDE.md 记着的 Resend 套餐是每月 5 万封，发版前再核一次套餐还在不在。

### 存什么

- 新表 `account_reminder`（迁移）：
  - `principal_id`；
  - `email_enabled`，默认 true；
  - `email_changed_at`；
  - `last_email_at`：是不是第一封看它是不是空的，不另存一列；
  - `covered_until`：上一封说到哪一刻为止；
  - `updated_at`。
- 没有这一行的照默认算（开着），只在本人改过开关、或者发过信以后才有。
- 删账户时跟着删，在删本机凭据那一步（和账户的签名钥匙一起）。“下载我的数据”里带上这一行（没有时给默认值）。
- 不存邮件内容，不存提醒了哪几间房。日志只记发没发成、几间房，不记邮箱和房间名。

## 接入时默认开后台回复

- 现在后台回复要在“我的 Agent”里另外开。
- 改成：接入对话框里命令行、MCP 两种方式（桌面端）多一项“你不在时也让它回话”，默认勾上。Agent 到了以后，照“我的 Agent”里开的那一套建授权，默认 30 天。
- 网络接入没有后台回复，不显示这一项。
- 要不要最近登录过、宿主没装好时怎么说，轮到这一步时先补进本文档再做。

## 接口

- `GET /account/reminders` 回 `{ email: { enabled, available } }`。`available` 只看这台服务器开没开邮件提醒：没验证邮箱的人登录不进来（注册时就设密码那一条），用不着再看。
  - 开关是部署配置的 `AGENT_ROOM_REMINDER_EMAIL_ENABLED`（默认 `false`）；开着时一定要配退订令牌的钥匙 `AGENT_ROOM_REMINDER_UNSUBSCRIBE_SECRET(_FILE)`，不然控制面起不来。
  - 4R-3 只加在控制面的配置里，`compose.yaml` 和 `render.py` 不传，生产上就是关着；4R-5 再接上。
- `PUT /account/reminders`，带 `{ email: { enabled } }`。有效登录就行，不要最近登录过：和“退出别处”一样，是保护自己的动作。
- `GET /reminders/unsubscribe?token=…` 出退订那一页；`POST /reminders/unsubscribe` 收那一页的表单，也收 One-Click。
- 网页对新接口的回答 `.strict()` 校验，旧接口一个字段都不加。

## 隐私说明页

## 分步

1. **4R-1** 这份设计，只改文档。
2. **4R-2** 网页通知，只改网页。
3. **4R-3** 邮件开关先存着，还不发。分两个 PR，接口先合：
   - **4R-3a** 控制面：表、设置接口、退订页、部署配置的开关（默认关）；
   - **4R-3b** 网页设置里的邮件开关。服务器没开时不显示这一行。
4. **4R-4** 算该提醒什么，只记日志和指标、不发信，在生产上演练一周，看算出来的人数和房间数对不对。分三个 PR：
   - **4R-4a** 规则和用例：读个人工作区、从哪一刻算起、发不发，用假的库和 Matrix 测；
   - **4R-4b** 库和 Matrix 那两头：列候选和他在的房间，替他读个人工作区和消息；真实数据库、真实 Synapse 的测试；
   - **4R-4c** 每小时跑一轮：演练时不写库，上一封的时间记在内存里（重启就忘），这样一天算出来的数接近真发的量。每轮一行日志和指标 `agent_room.reminder.planned{outcome}`：查了几个账户、该发几封、几间房、没发的各是什么原因、几个读失败；不记账户、房间和邮箱。隐私说明页“怎么用”那一条一起改。
5. **4R-5** 发信：SMTP、从身份服务读邮箱、中英文的邮件、部署配置和告警、隐私说明页。改了 `tools/prodops/render.py`，发版的实机验收要设备码。
6. **4R-6** 无头验收，只在派发 `suite=all` 时跑：本地的收信器（`infra/compose` 里已有）收到一封，点了退订以后不再收。
7. **4R-7** 接入时默认开后台回复。
8. **4R-8** 上线两周后看周报里的“一周后还来”和退订了多少人。

4R-3 到 4R-5 可以分开发版：开关先存着不碍事，算的那一步只记日志。

## 验收

- 网页开着、切到别的标签页，有人在私人房间里提到你：桌面上弹出通知，点了回到那一条。
- 关掉网页，私人房间里有人说了话：一天之内收到一封邮件，写着房间名和条数，没有内容；点房间名打开那间房。
- 在应用里读过了的，不再提醒；开了免打扰的房间不在邮件里；公开房间只在有人点了你的名字时出现。
- 一天最多一封。
- 点邮件里的退订、确认：以后不再收，设置里显示关着，能再打开。邮箱客户端自带的“退订”按钮也管用。
- 删了账户以后不再收。
