# 游戏大厅界面重做

## 决定

2026-09-17，维护者在三个视觉方向里选定「游戏大厅」。另外两个方向是「工作室」（暖纸色、建筑平面图、衬线标题）和「控制室」（深色仪表、信号环、列表优先的手机布局）。三份对比稿画的是同一个房间、同一组人物和消息，比较的只是视觉语言。

本文取代 [界面与交互设计规范](../agent-room-foundation/ui-design.md) 的 §1.2 美学方向、§1.3 色彩、§1.4 字体和 §10 视觉令牌。那份规范的信息架构、交互状态机、消息预览与交付规则、私人房间流程和安全要求继续有效：换的是外观，不是行为边界。

## 视觉语言

像一局温暖的多人小游戏：明亮的底色、粗描边、能「按下去」的按钮、有性格的机器人和对话气泡。房间里发生的事应该一眼可见，而不是藏在文字里。

它仍然是一个协作工具，不是游戏 HUD：

- 状态和风险依旧如实表达，不为了热闹夸大「正在回复」「已读」等结论；
- 长文、表单、设置页使用同一套颜色和描边，但字体换成正文字体、装饰收敛，保证可读；
- 动效只强调变化，静止状态保持静止。

## 颜色

所有文字都用墨色放在浅色或彩色底上，不在彩色底上放白字——这一条是为了对比度，而不是审美偏好。

## 形状与质感

- 描边：大面板与主按钮 2.5 px，小控件 2 px，统一墨色。
- 按压阴影：`0 4px 0 ink`（大）/ `0 3px 0 ink`（小），不用模糊阴影。按下时元素下移、阴影同步缩短，`prefers-reduced-motion` 下取消位移。
- 圆角：胶囊按钮与贴纸 999 px，场景与面板 28 px，输入框 22 px，工具按钮 14 px。
- 焦点环：`3px solid brand`，外扩 3 px，确保在奶油色、白色和黄色按钮上都清晰。
- 手机端触控目标不小于 44 × 44 px；底部只保留一层操作栏，标签不折行。

## 字体

字体作为本地 WOFF2 随客户端发布，不使用第三方字体服务（沿用原规范理由：避免泄露访问元数据）。中日韩字体按 unicode-range 分片，只下载实际用到的字形。

- 界面与数字：`Fredoka Variable`（圆润、有性格，数字清楚）；
- 中文正文：`Noto Sans SC Variable`，接在 Fredoka 之后作为中文回退；
- 标题展示：`ZCOOL KuaiLe`，只用于房间名等大号标题，不用于正文、按钮和表单；
- 技术标识：`IBM Plex Mono`，只用于 Agent ID、事件 ID 等机器数据。

## 状态文案

人物名牌下只放一行大白话状态，不出现内部术语。例如用「空闲 · 提及即回复」代替「在线 · 读取方式未确认」。接待能力未知时不写进名牌，放进人物详情，并如实说明未知。

## 推进方式

每批改动单独合并，保留全部浏览器验收做回归，并附同一夹具的改前改后截图：

1. 设计令牌、字体与基础组件（按钮、贴纸、面板），房间工作区外框：顶栏、底部操作栏、视角与缩放控件、对话面板、对话气泡、手机布局。
2. 场景内部：地砖、墙面与家具、人物描边与状态贴纸、名牌、小地图。Pixi 与无 WebGL 回退共用同一套几何与颜色。
3. 次级页面：私人房间、自动发言授权、接入 Agent、账户、安全与连接。

第 1、2 批合并后一起发布。Pixi 名牌的字体写死在画布里，且网页字体加载完成后不会重绘；只换外框不换场景，名牌会退回系统字体，用户会看到一半新一半旧的房间。第 3 批可以单独发布：令牌是全局的，次级页面在第 1 批后已经换上新的颜色和字体，只是还没有粗描边与按压质感。
