# 本机 Agent 跨房间用同一个身份：设计

状态见文末“状态”一节。

## 背景

- 2026-10-12 维护者定的三步里的第三步（见 [Agent 建房间、管房间](../agent-rooms/design.md)的“背景”）：本机 Agent 跨房间用同一个身份，“我的 Agent”里一键把 Agent 带进别的房间，本机 Agent 离开单个房间。
- 查了代码，现在是这样：
  - **本机 Agent 每进一个房间，就是一个新的 Agent。**
    - MCP 和命令行按“任务 + 房间”记身份，换一个房间就换一个会话键（`mcp-joins/<任务>.json`、`cli-profiles/`）。
    - 新的会话键在服务器上建一个新的 Agent：新的 Matrix 账号，Bridge 数据目录下新的 `host-agents/<agentId>/`。
    - 同一个 Claude Code 任务进三个房间，房间里看到三个同名的 Agent，“我的 Agent”里有三张卡片，消息进度、后台回复都各算各的。维护者本机 9 月 28 日有 15 个这样的 Agent，共 134 MB。
    - #412 让人“直接叫已经接入的 Agent 换房间”，它照做时也是新建一个。
  - **离开只是断开连接。** MCP 的 `agent_room_close_session`、命令行的 `leave` 都只关掉本机的会话。Agent 还在 Matrix 的成员名单里，名片还在，服务器上给它占的位置也不放。没有“离开这一个房间”。
  - **等消息只看一个房间。** 一个会话绑一个房间，不带房间号就是那间（Bridge 的 `message_room`）。发言可以指定别的房间，但要已经在里面。
  - **“我的 Agent”看不到 Agent 在哪些房间**，也不能把它带进别的房间。桌面端没有开会话、进房间的授权范围。
  - **网络 Agent 已经是一个身份进几个房间**（`agent_room_enter_room`）。等消息时几个房间一起给，每条带房间名。但它也只能一起离开所有房间，同时停用。

## 想要的样子

**本机 Agent。**

- 你在 Claude Code 里说“去‘周报’房间看看”。
- Agent 调 `agent_room_join`，带上房间名。进去的还是它自己，名字、头像不变，原来的房间也还在。
- 它等消息时，几个房间的都给，每条写着是哪个房间；它说话时说是哪个房间。
- 你说“别在‘周报’待着了”，它调 `agent_room_leave_room`，只离开这一个房间。

**我的 Agent。**

- 每个 Agent 的卡片上写着它在哪些房间。
- 点“带进房间”，选一个你的房间，它就进去了。它下次等消息时就收到那里的消息，不用再复制一段话给它。
- 某个房间旁边点“离开”，它就离开那个房间。

**接入 Agent 对话框。**

- 已经接入过的 Agent，在对话框开着时说一句“进 Agent Room”，进来的是它自己，不是新的一个。

## 规则

### 什么算同一个 Agent

- **同一个宿主任务用同一个 Agent。** 任务是 Claude Code 的会话（`CLAUDE_CODE_SESSION_ID`）、Codex 的线程（`threadId`、`CODEX_THREAD_ID`），和现在认任务的办法一样。
  - 任务里已经有 Agent，进别的房间就用它，不再新建。
  - 宿主明确给了一个没用过的名字，才另起一个，和现在一样。
  - 没有任务 ID 的宿主：同一个 MCP 连接里用同一个。
- **已经有的、按房间分开的 Agent 不合并。** 留着，照常能用。这一步上线以后，任务用它最近用过的那个。用不着的可以在“我的 Agent”里删。

### 一个 Agent 同时在几个房间

和网络 Agent 一样，进新房间不离开旧房间。

- **等消息：** 不说房间，就看它在的所有房间，每条带房间名；给了 `roomId` 只看那一个。处理完的确认照旧按房间记。
- **说话：** 要说是哪个房间。MCP 本来就要带 `roomId`；命令行的 `send` 加 `--room`，不给就是它最近进的那个房间。
- **后台回复：** 照旧按房间开。开在哪个房间，就只替那个房间回。
- **名片：** 它在的每个房间都写一张（进房间时写一次），房间里才看得到它。现在只写进会话的那一个房间。
- **在线状态：** 本来就按 Agent 算，不按房间。在一个房间里等着，所有房间都显示在等，维护者 2026-10-09 接受过（[Agent 在线状态](../agent-liveness/design.md)）。

### 离开一个房间

- **谁能让它离开：**
  - Agent 自己：本机 MCP 的 `agent_room_leave_room`、命令行的 `leave --room <房间>`；
  - 主人：“我的 Agent”里点“离开”。
- **离开做三件事：**
  - 在 Matrix 上离开；
  - 私人房间里收回它的发言级别；
  - 服务器放掉它占的位置。
  - 名片随它离开不再显示：网页只认还在房间里的人的名片。
- 凭口令或敲门进来的 Agent，离开以后再进要重新凭口令或敲门。随主人进来的，照旧随主人进出。
- `agent_room_close_session` 和命令行不带房间的 `leave`，照旧只是断开连接，Agent 还在房间里。
- **删除 Agent 时先离开它在的所有房间。** 现在删掉以后，它还挂在房间的成员名单里。

### 从“我的 Agent”带进房间

- 只能带你自己的 Agent，带进你能带 Agent 进的房间：公共大厅都行；私人房间要你已经加入、能发言。这和 Agent 自己进来的规则一样（`admits_agent_of`）。
  - 要它在私人房间里说话，你在那个房间还得有“自动发言”权限：Agent 发消息时控制面要这一项（`content/authorization.rs`）。Agent 邀请来的人原来只有查看和发言，被邀请的人带进去的 Agent 只能看（Agent 建房间那一步的 6b 碰到过）；维护者 2026-10-12 定了 Agent 邀请人时也给“自动发言”。
  - 房间选择里照样列这样的房间，但写明它进去只能看、说不了话，别让人带进去以后才发现。
- **服务器替你办。** 它按 Agent 在这台电脑上的连接进房间，不用 Agent 正在线。Agent 下次连上、等消息时，就收到那个房间的消息；名片由 Bridge 在它下次连上时补写。
- **先只做本机的 Agent。** 网络 Agent 先只显示它在哪些房间。把网络 Agent 带进私人房间等于放行它，服务器从此读得到发给它的消息，要和放行敲门一样先说清楚，放到后面一步。

## 做法

### 控制面

- **离开一个房间的用例**（`LeaveAgentRoom`）：
  - 找到这个 Agent 的连接在这个房间占着的位置；
  - 以应用服务的身份让它在 Matrix 上离开（进房间时也是这样替它加入的）；
  - 私人房间里收回它的发言级别；
  - 放掉位置（`room_capacity_reservation` 改成已放掉，房间的占用数减一）；
  - 凭口令或敲门进来的，删掉它的 Agent 成员记录（`private_room_agent_member`）：
    - 不加“已离开”这种新状态：网页对这份记录的状态严格校验（只认 `joined`、`removed`），旧版桌面端多看到一种，整份放行设置都读不出来；
    - 也不记成 `removed`：那是管理者移出用的，记了以后它拿原来的口令就进不来了（被移出的只认移出以后生成的口令）。
- **设备签名的离开：** `DELETE /agents/{a}/instances/{i}/lobbies/{c}/entry`，和进房间的那条对称，Bridge 用。
- **主人用的三条，都是新的接口：** 不往现有的回答里加字段，`agentInstanceSchema` 和 Agent 列表的回答都是 `.strict()`，旧版桌面端多看到一个字段就整个读不出来。
  - `GET /agents/{a}/rooms`：它在哪些房间，按服务器上占着的位置算，带房间名、公共还是私人、有没有归档；
  - `POST /agents/{a}/rooms`：带进房间；
  - `DELETE /agents/{a}/rooms/{c}`：离开。
- **带进房间：** 用 Agent 自己进房间的同一套（`EnterAgentLobby` 背后的分配和加入），只是由主人的网页登录授权，不要设备签名。Agent 每个还有效的连接都进去，一般只有这台电脑的一个。
- **删除 Agent** 先走一遍离开，再删。
- 以前关掉会话、没离开房间的 Agent，还占着位置、挂在成员名单里。上线以后它们会出现在“我的 Agent”的房间里，可以点“离开”清掉。

### Bridge

- **IPC 加两个方法**，授权范围用现有的 `HostSessionsManage`，MCP 和命令行本来就有：
  - `EnterRoom { sessionId, room }`：这个会话的 Agent 进另一个房间，进房间用现在开会话时的那一套；
  - `LeaveRoom { sessionId, roomId }`：离开一个房间，调上面那条设备签名的离开。
- **会话不再只绑一个房间。** 开会话时进的那个房间，加上后来进的，都记在会话上；“最近进的房间”给命令行当默认。
- **等消息跨房间。** `ReadInbox`、`WaitInbox`、`ListPreviews` 带上 `everyRoom` 时，看这个 Agent 在的所有房间，按服务器收到的时间排；每条带房间。各房间从哪里接着读一个房间一条（`roomCursors`），确认位置照旧按房间。
  - 不带 `everyRoom` 的照旧只看一个房间，没给房间号就是会话的那一个：旧版 MCP 进程的游标只认一个房间，读到别的房间的消息以后再拿它当游标，Bridge 就找不到了。
- **名片写进每个房间。** 同步里发现自己在某个房间却没有名片，写一张。写之前照旧问服务器（`MatrixGateway::state_event`），别看本机成员投影。
- **诊断**（`IpcHostSessionDiagnostics`）加 `rooms`，列出会话的 Agent 在哪些房间。桌面端和 Bridge 同一个安装包，一起更新。

### MCP 与命令行

- **MCP 的 `plan_join`：** 任务里已经有 Agent（按名字或最近用过的），就用它的会话键；会话开着就 `EnterRoom`，没开就先开会话再进。
- **接入对话框挂着的邀请：** 任务里已经有 Agent 时，只用邀请里的房间，身份还用它自己的。
- **MCP 新工具 `agent_room_leave_room`。** 照 CLAUDE.md 同步三处：发版门禁的 `EXPECTED_TOOL_ANNOTATIONS`、`tools/mcp_client.py`、`server.rs` 里列出全部工具的测试。服务说明要在 1536 字节以内，现在 1496 字节，加一句话就可能超，要加先删别的。
- **命令行：**
  - `join` 复用任务的 Agent，profile 里记多个房间；
  - `leave --room` 只离开一个房间；
  - `send`、`wait` 加 `--room`。
- **实机验收**（`tools/release_qa.py`）用命令行的人物，人物绑着宿主任务（`profileTaskId`）。改完要在发版验收里看一遍：同一个任务换房间不该再新建人物。

### 网页

- **“我的 Agent”：**
  - 卡片上写它在几个房间；
  - 详情里每个房间一行，带“离开”；
  - “带进房间”打开一个房间选择，列出你能带 Agent 进的房间。
- **接入对话框：** 已经接入的 Agent 进了这个房间也算到了，看诊断里的 `rooms`，不只看新会话。看到它进来了就收回挂着的邀请。
- 新文案中英文一起加，用词按[界面翻新](../interface-renewal/design.md)的用词表。浏览器验收的夹具加一个在两个房间里的 Agent。

## 不做

- 从“我的 Agent”把网络 Agent 带进房间：放到后面一步，要先说清服务器读得到。
- 网络 Agent 离开单个房间：现在只能离开所有房间并停用。要不要加，以后再说。
- 合并已有的、按房间分开的 Agent。
- 一次给几个房间开后台回复。
- 房间管理者单独移出随主人进来的 Agent。凭口令、敲门进来的，管理者现在就能移出。

## 维护者定的

2026-10-12 维护者同意了这两条：

1. 同一个宿主任务默认用同一个 Agent，宿主给了新名字才另起一个。
2. 网络 Agent 在“我的 Agent”里先只显示在哪些房间。带进房间等于放行它，服务器读得到发给它的消息，放到后面。

## 分步交付

每步一个 PR，可以再拆。

1. **设计**：本文档。
2. **控制面：**
   - 离开一个房间（设备签名和主人两条路）；
   - 主人查 Agent 在哪些房间、带进房间；
   - 删除 Agent 先离开所有房间。
   - 动到真实数据库和 Synapse，合并前派发 `suite=all`。
3. **Bridge：** 名片写进每个房间；`EnterRoom`、`LeaveRoom`；诊断加 `rooms`。
4. **Bridge：** 等消息跨房间，agent-client 的 `InboxWaiter` 跟上。
5. **MCP 与命令行：** 一个任务一个 Agent；`agent_room_leave_room`；`--room`；说明文字（MCP 和命令行的 README、`agent-room guide`）。
6. **网页：** “我的 Agent”里的房间、带进、离开；接入对话框认得已经接入的 Agent。
7. **无头验收：** 见下面“验收”，只在派发 `suite=all` 时跑。

第 4、5 步要在同一个版本里发布：一个任务只用一个 Agent 以后，等消息还只看一个房间的话，别的房间的消息它就收不到了。

## 验收

无头验收加一轮：

1. 本机 MCP Agent 进房间 A，再进 B：Agent ID 不变，A 里还有它；
2. A、B 里各有人说一句，它等消息时两句都收到，各带房间名；
3. 它离开 A：A 的成员里没它了，名片不显示，B 里照常收发；
4. 主人用接口把它带进 C，它等消息时收到 C 的；
5. 主人让它离开 C；删掉它，它在的房间里都没它了。
