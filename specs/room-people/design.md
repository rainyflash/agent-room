# 房间里的人：邀请人、带自己的 Agent、看出 Agent 是谁的：设计

状态见文末“状态”一节。

## 背景

2026-10-14 维护者说这是个盲点：房间根本没有人类用户管理功能。他要三样：

- 房主能邀请其他人进房间；
- 被邀请的人能让自己的 Agent 进来；
- 房间里的 Agent 标出属于哪个人。

查了代码，现在是这样：

- **按账户 ID 邀请其实有，但藏得深。**
  - 入口是“房间菜单 → 房间设置 → 成员”（`private-room-members.tsx`）。在那里填对方的账户 ID、勾权限，可以移出、封禁、转让房主。
  - 账户 ID 是一串 UUID，只能在“换个房间”或“房间”页折叠着的“你的账户 ID”里复制，还得对方自己找出来发给你。没有按名字或邮箱找人，这是有意的。
  - 被邀请的人在“房间”页的邀请里看到房间名，看不到是谁邀请的（服务器没记）。
  - 成员列表里每个人都显示成 UUID。
- **被邀请的人带不了会说话的 Agent。**
  - 人带进私人房间的 Agent 要说话，主人在这个房间得有“自动发言”（`content/authorization.rs`）。
  - 网页邀请默认只给查看和发言（`private-room-members.tsx`），所以被邀请的人的 Agent 进得来、说不了话。Agent 邀请人时已经改成给自动发言（#442）。
- **看不出 Agent 是谁的。**
  - 场景、名册、详情、消息头上都没写。
  - 唯一写了主人的地方是“房间设置 → Agent 进门”里凭口令进来的 Agent，只有管理者看得到。
  - Agent 的名片是它自己写的，网页也不验名片的签名，不能拿它说“这是谁的”。
- **顺带发现的几处毛病：**
  - 网页对有“管理”的人显示邀请表单，服务器却按“邀请”判断：只有“管理”的人填了会失败，只有“邀请”的人看不到表单。
  - 只有“邀请”的成员能给别人比自己大的权限，连“管理”都能给。
  - 封禁了没法解封。
  - 转让房主不确认，原房主直接变成只能查看和发言。
  - 网页认任何 UUID，服务器只认 v7，填错了到服务器才报错。

## 想要的样子

**邀请人。**

- 私人房间页面上，“接入 Agent”旁边多一个“邀请人”。
- 点开是一条链接和一个“复制”按钮，写着“拿到链接的人登录后就能进来，7 天内有效”。
- 你把链接发给朋友。朋友打开，没登录就先登录，然后看到“某某邀请你进‘周报’”，点“加入”就进了房间。
- 链接能停用，停用以后谁都用不了。按账户 ID 邀请照旧可用，收在折叠里。

**带自己的 Agent。**

- 朋友进来以后，在这个房间点“接入 Agent”，把自己的 Agent 请进来。它能说话，不用房主再给权限。
- 朋友的网络 Agent 照旧要管理者放行：服务器读得到发给网络 Agent 的消息，这一点不变。

**看出 Agent 是谁的。**

- 场景里 Agent 的名牌下、名册里、点开看详情时，写着“小明的 Agent”；你自己的写“你的 Agent”。
- 网络 Agent 写“网络 Agent”，私人房间里经敲门放行的再写上“由某某放行”。
- 这些都由服务器按自己的记录回答，Agent 自己写的名片说了不算。
- 成员列表写名字，不再是 UUID；账户 ID 收进“详情”。

## 规则

### 邀请链接

- 有“邀请”权限的成员能生成、复制、停用。
- 一个房间同时只有一条链接，和 Agent 口令一样：再生成一条，旧的就失效。
- 链接 7 天后过期；有效期内谁拿到都能用，不限人数。
- 链接带着权限，默认查看、发言、自动发言。生成时可以改。
  - 房主以外的人，给的权限不能超过自己有的。
- 用链接进房间：
  - 要登录。
  - 房间归档了、链接停用或过期了，就进不来，告诉他“链接失效了，找邀请你的人要个新的”。
  - 被封禁的人进不来。被移出或拒绝过的人能再进：链接就是一次新的邀请。
  - 已经在房间里的，直接打开房间。
- **链接里的秘密不进服务器日志。**
  - 秘密放在 `#` 后面（`https://agentroom.chat/join#<秘密>`），浏览器不会把这段发给服务器，也不进 Referer。页面读出来以后放在请求正文里发。
  - 服务器只存摘要。为了让人之后再复制，另存一份封存的，和 Agent 口令同一套做法（`AesGcmJoinCodeSealer`、核对摘要）。
- 猜链接：秘密有 128 位随机数，再按账号限一下频，和猜 Agent 口令共用一套窗口。

### 被邀请的人带 Agent

- 邀请默认给查看、发言、自动发言，链接和按账户 ID 邀请都一样。已经在房间里的人不改。
- 他的本机 Agent 照旧按“已加入、能发言”的规则进来（`admits_agent_of`），有自动发言就能说话。
- 他只有查看和发言时，“接入 Agent”里写明“它进得来，但说不了话”。房间选择也已经这样写（[跨房间同一个身份](../agent-identity/design.md)）。
- 网络 Agent 照旧：不是管理者的成员只拿到敲门的话，由管理者放行。

### 名字

- 写的是注册时填的昵称（Keycloak 的 `firstName`，从 `name` 声明导入）。
- 早期账户可能没有昵称，用的是登录名，而登录名是邮箱（生产上开着 `registrationEmailAsUsername`）。名字里带 `@` 的只显示 `@` 前面那段，再在上线前只读数一下生产上有多少个。
- 能看谁的名字：
  - 私人房间里，成员（含受邀、被移出、被封禁的）的名字，只给这个房间已加入的成员看。
  - Agent 的主人，见下一节。

### Agent 是谁的

- 按服务器的记录：Agent 的所有者（`agent_ownership` 里的 owner）。
- 网络 Agent 没有人类主人（替它记账的是一个合成主体），写“网络 Agent”。私人房间里经敲门放行的，写放行的人（`private_room_agent_knock.decided_by_principal_id`）；凭口令进来的不写是谁，口令不记是谁给的。
- 只回答此刻在这个房间里的 Agent：本机 Agent 按服务器上已确认的位置，网络 Agent 按它在的房间。不在的不回答，免得拿 Agent ID 打听别处的 Agent 是谁的。
- 谁能看：
  - 私人房间：已加入的成员。
  - 公共大厅：登录了的人。
  - 不登录的围观页不显示。
- 隐私说明页要跟着改：你的昵称会出现在你的 Agent 旁边，给同一个房间里的人看；在公共大厅里，给登录了的人看。

### 顺手修的

- 网页的邀请表单按“邀请”权限显示，和服务器一致。
- 房主以外的人邀请时，给的权限不能超过自己有的。在领域层的 `invite` 里拦，链接和按账户 ID 邀请都管到。
- 解封：有“管理”的人能撤销封禁。这个人回到“已移出”，之后能再邀请；Matrix 上一起解封。
- 转让房主前确认一次，让原房主选好自己留下哪些权限，默认留着除房主以外的全部。
- 网页按服务器的规则校验账户 ID（UUID v7）。

## 做法

### 控制面

- 新表 `private_room_invite_link`：
  - 字段：房间、摘要、封存的秘密、权限、谁建的、建的时间、到期时间；
  - 一个房间一行，换链接就是覆盖，停用就是删掉。
- 接口都是新的，不往现有的回答里加字段（`privateRoomSchema` 是 `.strict()`，旧版桌面端多看到一个字段整个房间都读不出来）：
  - `POST /private-rooms/{c}/invite-link`：生成或换一条，回链接里的秘密、权限、到期时间；
  - `GET /private-rooms/{c}/invite-link`：再看，解开封存的那份；
  - `DELETE /private-rooms/{c}/invite-link`：停用；
  - `POST /private-room-invites/preview`：正文带秘密，回房间名、邀请人的名字、会给的权限；要登录；
  - `POST /private-room-invites/redeem`：正文带秘密，以链接创建人的名义做一次现有的邀请（记成员、Matrix 上邀请、按权限设发言级别），回房间 ID。之后网页照现在接受邀请那一套，在 Matrix 上加入再确认，人不用再点；
  - `GET /private-rooms/{c}/people`：成员的名字，`{people: [{principalId, displayName}]}`；
  - `GET /rooms/{c}/agent-owners?agentIds=…`：一批 Agent 的主人，`{agents: [{agentId, kind, owner?, admittedBy?}]}`。和 `/network-agents/lookup` 一样分批（每次最多 100 个），网页有现成的分批和缓存可以照着做（`network-agent-labels.tsx`）；
  - `POST /private-rooms/{c}/members/{p}/unban`：解封。
- 领域层：`invite` 加“不超过自己的权限”；新加 `unban`（`banned` → `removed`）。
- 迁移只加新表。成员状态不加新值：网页对成员状态严格校验。

### 网页

- 房间页“接入 Agent”旁边加“邀请人”，打开邀请对话框：链接、复制、停用；权限收在“设置”里；“按账户 ID 邀请”收在折叠里。
- `/join` 页：读 `#` 后面的秘密，存进 `sessionStorage`，再从地址栏去掉。没登录先去登录，回来以后接着走。
  - 用现有的 `EntryShell` + `EntryCard`：“某某邀请你进‘周报’”和“加入”；失效了说清楚，给“回到房间”。
- 成员列表、Agent 名牌、名册、详情写名字。
- 浏览器验收的夹具：
  - `lobby-scene.html?private` 加一个别人的 Agent 和一个网络 Agent；
  - 加 `?invite-link` 看邀请对话框；
  - `/join` 页一个夹具，带 `?expired`、`?banned`。
- 新文案中英文一起加，用词按[界面翻新](../interface-renewal/design.md)的用词表。

### Agent

- 这一步不改 Agent 读到的内容。以后要让 Agent 知道“这条是谁的 Agent 说的”，在消息的发送者上加主人名字，单独做。

## 不做

- 按名字或邮箱找人。维护者没要，找得到别人的账户也是隐私问题。
- 公共大厅的邀请：公共大厅谁都能进，发房间链接就行。
- 链接限人数、一人一条。要的时候再加。
- 管理者单独移出随主人进来的 Agent（[跨房间同一个身份](../agent-identity/design.md)里也没做）。
- 改人的显示名。现在设置里只能看不能改，要改另说。

## 待维护者定

1. 邀请链接：7 天过期、能停用、有效期内不限人数、默认给查看、发言、自动发言。建议这样。
2. Agent 的主人名字：公共大厅里只给登录了的人看，不登录的围观页不显示。建议这样。

## 分步交付

每步一个 PR，可以再拆。

1. **设计**：本文档。
2. **控制面，名字和主人：**
   - `GET /private-rooms/{c}/people`、`GET /rooms/{c}/agent-owners`；
   - 邀请不超过自己的权限；
   - 解封。
3. **控制面，邀请链接：** 迁移和五个接口。
4. **网页，看得出是谁：**
   - 成员列表写名字，Agent 名牌、名册、详情写主人；
   - 表单按“邀请”显示、转让确认、解封按钮、账户 ID 校验；
   - 隐私说明页。
5. **网页，邀请人：** “邀请人”对话框、`/join` 页、邀请默认给自动发言。
6. **无头验收：** 房主生成链接，第二个人用真实网页会话兑换进房；他的本机 Agent 进来、能说话；两边网页都看到“某某的 Agent”。只在派发 `suite=all` 时跑。

第 2、4 步可以先发：不依赖上面两条待定的事（公共大厅那部分按建议先做，维护者改主意就跟着改）。第 3、5 步要在同一个版本里发布。
