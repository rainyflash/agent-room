# 2D 房间美术

用户确认采用清晰的 2D 平面房间，并要求支持大量 Agent。场景保留可点击、可活动的虚构机器人；姓名、状态、人数和对话均由真实数据生成。

- `flat-robots.png`：本任务通过 OpenAI image generation 生成，1536 × 1024，4 列 × 2 行，每格 384 × 512。四种外形依次为青色方形、珊瑚色圆形、黄色胶囊、青色菱形；上排站立，下排行走。
- 原始生成文件：`exec-6c2b2cb6-ea20-427e-8a1b-d80201313def.png`。用户认可的房间参考：`exec-3301488d-8118-422d-9d77-8919240a0c7b.png`。原图保留在本地任务的 generated_images 目录，未将参考图作为应用截图发布。
- 生成要求摘要：与认可参考一致的简洁平面机器人；纯品红背景供色键处理；完整身体、清楚轮廓、相同列保持身份与尺寸；没有文字、网格或写实材质。此处为摘要，不是生成请求逐字记录。
- `studio-assets.ts` 按实际输出校准站立和行走脚点。生成结果没有严格遵循统一基线，不能直接假设每格脚点相同。
- 解码器只处理一次品红背景。Pixi 共享图集与有限的状态纹理；SVG 和名单头像共享一个页面生命周期的 Blob URL，避免千人名单重复内嵌大段图片数据。浏览器在文档卸载时释放该 URL。
- 图集外形由稳定 ID 分配，不是身份凭证；身份以真实姓名、账户与信任信息为准。人类用户使用独立的深蓝六边形标记与“你”标签。

## 可伸缩的场景几何

有意采用原生矢量绘制平面地板、细墙线、边缘家具和人类标记，而人物保留生成素材。原因是房间必须随人数扩大，不能拉伸一张固定背景图，同时碰撞和显示需要使用同一套几何。

`room-plan-art.ts` 提供 Pixi 与 SVG 共用的形状；`room-floor.ts` 提供家具位置和可行走范围。家具不承载任务状态或交互按钮。原先的写实和低多边形素材不进入构建。

在总览中按实际人物位置汇总人数与任务状态；放大后显示视口内人物，选择后显示姓名及详情。减少动态设置会停止持续角色动画。运行时图片失败有明确提示并保留可交互替代标记。
