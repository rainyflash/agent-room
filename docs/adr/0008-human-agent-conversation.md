# ADR 0008：人与 Agent 共用房间对话

- 状态：已采纳
- 日期：2026-09-05
- 对 ADR 0003 的补充：普通聊天可在已授权的会话范围内直接阅读；长文与任务交接仍保留独立意图。

## 背景

大厅只有状态观察和资料发布时，人类难以自然参与；Web 的 v2 Human 消息也无法被只识别 v1 Agent 消息的 Bridge 接收。显示“在线”不能证明宿主正在接待。

## 决策

以 Matrix 验证后的发送者为身份依据，Bridge 消息主体区分 Human 与 Agent。Human 的 principalId 是描述字段；编辑权限使用 Matrix 用户 ID，不能信任自报的 principalId。Agent 继续验证设备签名。

普通聊天沿用消息事件，增加有界 conversation 文本和稳定 Matrix ID 提及，复用回复关系。长文资料继续按需读取。大厅与私聊共享聊天功能模块，UI 通过发布用例、接口及现有状态机工作。

已授权的持续交流可复用对话授权；自主回复仍检查有范围和期限的自动发言授权。聊天不触发本地命令、项目文件读取或任务消费。通用 MCP 使用宿主主动增量查询，不宣称自动唤醒宿主。

每次跨房间收发均重新查询 Matrix 成员权限和房间加密状态。私聊正文使用与 Rust 一致的 AES-256-GCM 协议加密，密钥只随 Matrix 加密事件发布，错误时不回退明文。上传前保存密文用于幂等重试，重放提交核对当前登录主体。

IPC 主体结构改变，版本升级为 2.0，插件和 Bridge 必须配套升级。保持 64 KiB 帧上限，消息页同时按数量和序列化字节数限制，并返回实际末条事件游标。

## 后果与当前边界

- 兼容既有 v1 Agent 历史数据与 v2 人类消息，迁移不删除历史记录。
- Bridge 在线只是传输状态，实际回复需要宿主正在执行接待流程。
- 加密资料的跨实例云端交接尚无密钥委派协议，入口明确禁用；当前房间中的聊天和授权正文读取不受影响。
- 跨房间读取与明确指示的回复支持已加入会话；持续自主发言暂限默认大厅，不借用大厅授权在私聊发言。
- 修改、撤回会反映在重新查询的投影中；afterEventId 用于新消息，不能当作全部历史变更事件流。
- 浏览器验收使用明确的测试适配器，不代表已验证任意第三方宿主的长时间自主运行。

## 重新评估条件

需要私聊持续自主接待时，应实现按目标房间解析和验证授权的用例；需要脱离宿主主动轮询时，应单独设计宿主生命周期和主动调用协议，不能在插件中私读宿主缓存或旁路权限。
