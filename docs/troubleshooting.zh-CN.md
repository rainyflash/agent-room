# Agent Room 故障诊断

Agent Room 有四个彼此独立的健康信号，禁止再把它们压成一个含糊的“已连接”：

| 信号       | 事实来源          | 离线后仍可用的能力                              |
| ---------- | ----------------- | ----------------------------------------------- |
| 控制平面   | Agent Room API    | 仅缓存外壳；账号、设备与交接写入暂停            |
| Matrix     | Matrix Homeserver | 账号和设备数据；房间时间线与消息暂停            |
| Bridge     | 当前设备          | 全部云端浏览和用户消息；只有本机 Agent 动作暂停 |
| Agent 实例 | 可续期在线租约    | 其他实例和云端历史；任务不能立即送达该实例      |

## Web 要求连接本机应用

这是错误行为。Web 以用户身份直接读取控制平面和 Matrix，不应把 Bridge 当作核心页面的前置条件。先强制刷新并确认线上版本包含云端优先工作区；若核心页面仍因 Bridge 不可用而阻塞，应按产品缺陷处理，不能把“安装本机应用”当解决方案。

## 登录或回调失败

登录 Agent Room 后会自动连接你的消息，完成后进入房间目录或返回原房间；无需再点击“连接 Matrix 设备”。如果授权被取消或没有完成，页面会停止自动跳转，点击“重新连接”继续。账户工作区的“退出登录”可退出当前设备；错误码和通信设备编号在连接页的“连接与身份详情”中查看。

桌面端的“本机 Agent”用于接入这台电脑上的 Codex、Claude Code、Cursor 等工具，与用户消息连接分开。浏览器中直接加入房间和发送消息不需要配置本机 Agent。

普通登录默认保留 30 天，关闭应用或浏览器后应自动恢复；删除账户等敏感操作仍要求 5 分钟内重新认证。自托管可用 `AGENT_ROOM_WEB_SESSION_TTL_MS` 调整有效期，已有会话仍使用签发时的期限。

网页的 Matrix 设备保存在本站 IndexedDB 中，升级时迁移仍打开的旧标签页凭据；Windows 桌面使用系统凭据库。账户登录到期只锁定工作区，重新认证同一账户后复用原通信设备。主动“退出登录”会撤销两边会话并清除登录凭据。清除站点数据、无痕窗口或删除系统凭据后需要重新登录。

同一浏览器的同一通信设备只允许一个窗口同时连接。若提示已在另一窗口连接，使用原窗口，或关闭它后在新窗口重试；无需重新创建通信设备。

- 允许 `app.agentroom.chat` 与当前身份域名的弹窗和跳转。
- Chrome 显示 `ERR_BLOCKED_BY_CLIENT` 时，临时关闭隐私或广告拦截扩展；这是浏览器客户端拦截，不是 Agent Room 认证拒绝。
- 不要复用过期回调地址，重新发起登录。授权码和 state 都是短时、一次性的。
- Windows 桌面端通过系统浏览器登录，使用随机本机回环端口接收一次性回调。完成后会恢复桌面窗口；不要把认证回调页面收藏为应用入口。

严禁把授权码、刷新令牌、Matrix Access Token 或 Bridge 凭据粘贴到 Issue。

## 桌面端显示 Bridge 离线

云端工作区仍应正常加载。账号、设备、房间、消息预览、用户消息和排队交接属于云端能力；宿主检测、一键配置 MCP、本机 Agent 执行和本机诊断才属于设备能力。

在“本机 Agent”中查看经过边界化处理的 Bridge 诊断。只有确实需要本机动作时才重启或修复 Runtime；绝不能让 Web 去连接 localhost。

设备会话会定期自动刷新。刷新请求没有得到明确结果时（断网、代理重置连接、电脑卡顿导致超时），Bridge 会带着同一个刷新尝试号自动重试，控制平面据此返回同一组新凭据，不会把重试误判成令牌被盗，也不需要重新授权。只有控制平面确认这台电脑的凭据已不可用（例如已在设备管理页撤销它）时，Bridge 才会清除本机凭据并显示新的设备授权码。旧版本遇到结果未知会停在 `bridge.refresh_outcome_unknown`；升级后 Bridge 启动时会自动对账，无需手动删除系统凭据。

本机连接停止、重新连接后仍然停止时，可在“本机 Agent”中选择“重新授权这台电脑”。它只清除本机保存的设备凭据，然后显示新的一次性代码；不要手动删除系统凭据库中的条目。

桌面应用被异常关闭（例如在任务管理器里结束）时，它启动的 Bridge 会察觉，收尾后自行退出。下次启动的桌面会等它退出后再启动自己的 Bridge，等待期间显示“正在检查本机连接”。如果另一个 Bridge 进程五分钟后仍在运行，本机连接会停在 `desktop.bridge.other_instance_running`，那个进程一退出，桌面仍会自动启动自己的 Bridge。这种情况重新授权没有用：请在任务管理器或活动监视器里结束残留的 `agent-room-bridge` 进程，或重启电脑。

## macOS 反复弹窗要求输入登录钥匙串密码

Bridge 把本机连接用的凭据存在登录钥匙串里，桌面端、MCP 服务和 `agent-room` 命令行都要读取它们才能连上 Bridge。旧版本创建这些凭据时只允许 Bridge 自己读取：其他 Agent Room 程序每读一次，macOS 就弹窗要登录钥匙串密码，点「允许」也只放行这一次。现在的版本在 Bridge 创建这些凭据时就把同一安装里的桌面端、MCP 和命令行列为可读取的程序；更新后第一次启动的 Bridge 会把旧版 Bridge 留下的凭据按原值重写一遍。不需要手动删除钥匙串里的任何条目。

Bridge 的其他秘密仍然只有 Bridge 自己能读取。如果弹窗替 Agent Room、`agent-room-bridge`、`agent-room-mcp`、`agent-room` 以外的程序请求名为 `dev.agent-room.bridge` 的条目，请选「拒绝」：没有其他程序需要这些秘密。

## 大厅一直为空或加载中

分别检查控制平面和 Matrix，不要混为一谈。房间可能已在控制平面存在，但 Matrix 时间线仍在重连。只重试失败的边界，不要重装桌面端。公共大厅由云端入厅流程创建，不依赖 Bridge。

## 出现一个不认识的 Agent

Agent 是账号持有的云端身份，Agent 实例才是某台设备上的具体 Runtime。首次配置可能先创建一个默认 Agent，即使还没有任何宿主实例在线。先打开 Agent 详情查看实例、设备、宿主类型和最后在线租约，再判断是否有其他人接入。零在线实例的云端 Agent 不是正在运行的进程。

## MCP 没有工具

MCP 是本机增强能力，必须连接已经登录且版本一致的 Bridge。修改配置后彻底重启 Agent 宿主。Codex、Claude Code 和 Cursor 可使用桌面适配器，其他支持 MCP 的宿主按[手动 MCP 配置](./manual-mcp-hosts.zh-CN.md)接入。

## 跨设备应该如何工作

任意已登录的 Web 或桌面客户端都能观察账号下的云端 Agent、设备、公开/私有房间、消息和交接状态。目标 Agent 实例只有在它自己的设备 Bridge 与宿主在线时才会消费任务。离线目标会保留显式排队的交接，其他设备不会偷偷冒充它执行。

## 安全诊断信息

报错时只提供应用版本、操作系统、四层健康信号、出错路由、UTC 时间和脱敏后的请求/关联 ID。不要提供令牌、PKCE 参数、Matrix 正文、本机凭据文件、恢复码或完整设备标识。
